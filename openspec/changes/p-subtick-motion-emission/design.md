# Design: 亚拍运动采样（p-subtick-motion-emission）

## D0. 目标与承诺

**目标**：把"决策之后、下一拍之前"的运动呈现从"线性插值折线"升级为"连续运动采样"，让画面通过
盲测视觉验收，同时**保证决策/判据零变化**。

**硬承诺（守卫）**：本 change 不改 `TICK_SECONDS`、不改任何 RNG/概率/阈值、不改 `st.pos` 的
拍边界语义；`move` 事件只是"拍边界之间位置的确定性采样"。验收时 L1/P38/P18/ratchet 必须逐值不变。

## D1. 证据（为什么必须在这一层解决）

1. 1 Hz beat 只给拍边界位置 ⇒ 轨迹是折线；A 层/B4 连续化/时间平滑/运动学层全部试过，
   两轮三裁判盲测均判定"比基线更不像真实"（报告 §12–§14）；
2. 直接把 `TICK_SECONDS` 改成 0.1 会压缩所有 per-tick 常量语义，行为被扭曲（报告 §15）；
3. 因此唯一不动决策语义的改进点 = 在引擎**发射层**为拍内运动提供确定性采样。

## D2. 机制

```
拍 k 边界：位置 P_k（现有 st.pos，不变）
拍 k+1 边界：位置 P_{k+1}（现有 mover 目标/限速逻辑给出，不变）
运动采样：用运动模型把 P_k → P_{k+1} 插值成 N 段（默认 N=5）：
    - 速度状态 v（每球员）→ 朝段方向按加速度上限逼近；
    - 转角限制（避免直角折返）；近目标线性降速；
    - 在 t_k + i/N·TICK（i=1..N-1）取位置，发射 move 事件；
    拍边界本身仍由既有事件表达（不重复发）。
```

- **确定性**：无 RNG；只依赖 `P_k`、`P_{k+1}`、上一拍速度状态；同 seed 同流。
- **不回流**：采样结果不写回 `st.pos`、不参与碰撞/分离/事件判定。
- **失败回退**：viewer 没收到 `move` 时按旧方式线性插值（协议向后兼容）。

## D3. 协议（event-stream-protocol delta）

新增 `move` 事件类型：

```
{ "type": "move", "t": <秒>, "positions": [[id, x, y], ...] }
```

- `positions` 覆盖全部 22 人（含门将），坐标归一化 0..1（与现有字段口径一致）；
- 顺序按 id 升序；`t` 介于两个 beat 之间；
- 每个 tick 发 N-1 条 `move`（N=5 ⇒ 4 条/秒），或按配置 `MOTION_SAMPLES_PER_TICK`；
- 相机/viewer 只把 `move` 用于插值渲染，不改变选择/统计（match-metrics 的引擎帧采样是否用
  `move`：默认**不用**，保持判据口径不变；另设可选开关供视觉工具用）。

## D4. 为什么不改 tick

改 tick 会改决策频率/RNG 消费/所有 per-tick 常量语义（报告 §15 已实测），等价于重做引擎节拍；
而视觉问题只需要"拍内运动呈现"。两者解耦是成本最低、风险最小的路径。

## D5. 验收

1. **零变化守卫**：L1 9/9、P38 八条逐值、P18 A1/A2/B4、ratchet 22 项逐值——与改动前完全一致；
2. **盲测**：三张匿名图（A 层基线 / 真实 / 本 change），三裁判中 SHALL 至少不把本 change 判为最假，
   目标 ≥ 基线（报告里预注册判定标准）；
3. 连续性数值：轨迹方向变化率/曲率半径接近真实 tracking（先报告、后定带）；
4. 协议/确定性：`move` 事件字段合法、可被 viewer 消费；同 seed 同流；无 `move` 时回退正常；
5. 体积/性能：事件量增幅、wasm 大小、单场模拟时间在预算内（另给读数）。

## D6. 风险

- viewer 渲染若消费 `move`，`like-football`/判据工具若也从 game 帧采样，读数会变——**默认不让判据消费**，
  只在视觉工具启用；若未来判据要消费，必须按新口径重生成基线。
- `move` 采样只改善"拍间运动"，不改变方向改变的拍边界（决策仍 1 Hz）——但真实盲测核心是"折线感"，
  预期收益主要来自此。
- 事件流体积 ×(N-1)；N 可配置，默认 5。
