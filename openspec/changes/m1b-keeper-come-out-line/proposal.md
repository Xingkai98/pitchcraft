# 改进提案：门将目标从「恒回门线」改为「随球距本方门线出/退」（M1b）

## Why

`p-looks-like-football` 的判别测试里，零上下文裁判 **3/3 全判对**，而它们给出的**头号判据**是
「引擎两名门将 12 s 内一毫米不动」。根因在 `compute_mover_candidates` 的门将支：

```rust
let tx = if id == 0 { 0.02 } else { 0.98 };
((tx, 0.5), "keeper_return".to_string(), GK_SPEED_MS)
```

门将目标被钉成**常数** `(0.02 | 0.98, 0.5)` ⇒ 门将距门线恒 **2.10 m**、12 s 位移恒 **0.0 m**。
这不是参数没调好，是**目标表达式里根本没有球**——门将是唯一一个完全不受球位置影响的球员。

**真实侧**（22 场真实语料：`viewer/data/real-game-{1,2}.json` 的 Metrica 两场 +
`skillcorner-*.json` 的 20 场；门将槽位 = id 0/21、逐场球场尺寸、原始球帧）：把「球距本方门线」
按 `[0,10) [10,20) [20,30) [30,40) [40,55) [55,70) [70,85) [85,106)` 分箱、取「门将距本方门线」的
**中位数**（两数据集各一份再平均），8 个分箱中位为
`2.18 / 2.93 / 4.38 / 7.12 / 10.95 / 15.48 / 19.84 / 21.86` m —— **球越远、门将站得越出**，
两数据集在整条曲线上相差 ≤2.5 m（结构，不是噪声）。

⇒ 引擎缺的是一条**真实存在的关系**，不是一次参数微调。

## What Changes

**唯一的功能改动**：`engine/src/lib.rs` 的门将目标表达式（`compute_mover_candidates` 的门将支）。

- 新增 4 个**私有**常量（无 `pub const` 增删改）：
  - `GK_COME_OUT_SLOPE = 0.2440`、`GK_COME_OUT_INTERCEPT_M = -0.4632`
    （对上述 8 个 `(分箱中点, 中位)` 点做**最小二乘**得来，复算一致）；
  - `GK_COME_OUT_FLOOR_M = 2.0`（真实 q10 = 2.22 Metrica / 2.92 SkillCorner，取略低者保守）；
  - `GK_TRACK_Y = 0.10`（横向跟随；Metrica 逐帧 OLS **0.09**，SkillCorner 20 场 0.14 但 86% 的点是外推值 ⇒ 靠可信侧）。
- 新增纯函数 `keeper_line_dist_m(球距本方门线) -> 门将距本方门线` = `max(截距 + 斜率·d, 地板)`。
- 门将支改为：纵向走该直线、横向 `y = 0.5 + (球 y − 0.5)·GK_TRACK_Y`。
- `formation_target` 的一句陈旧注释（「门将恒回门线」）改为「门将不走本函数」，**函数体一字未动**。

**不动的**（逐条）：`GK_SPEED_MS`（3.0）、`DEAD_ZONE_METERS`（2.0）、action 名 `keeper_return`、
同队间距分离、任何其它常量、任何 `pub const`、任何门的判据（`DUR` / `TICK_SECONDS` / seed 集 / detector）。
`git diff --stat`：**1 file changed, 57 insertions(+), 3 deletions(-)**。

**为什么不落 M1（8 节点查表）**：独立判据镜已证**节点表对 P4 非必要**——同一条最小二乘直线在
P4 头条项上**比节点表更贴真实**（主 12.008 vs 12.363，真实 11.476；客 12.381 vs 12.004，真实 12.352），
四项判据里三项无差别。⇒ 少 6 个常量、少一段查表代码。**M1 的候选唯一一条「直线更差」的反证据
量的是旧板条尺子**（`slab −0.0176 / t=−2.33`），换正确矩形口径后是 **−0.0115（t=−1.75, n.s.）**、
叠 M5 后 **+0.0000（t=+0.01）** ⇒ **归零**。
