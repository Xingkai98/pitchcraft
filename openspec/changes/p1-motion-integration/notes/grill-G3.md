## 一、已拍板、不需要再问的事实

1. **D11 六项已由用户拍板（2026-11-21，全按推荐）**：决策 2Hz、beat 5Hz 名义、协议只发端点、
   角球带重锚 ~10.27、守卫不变量化作为本 change 的 Phase 0、C1 只做运动执行。
   出处：`design.md:1072`–`:1083`，拍板记录 `:1087`。
2. **批准范围 = 运动执行 + Phase 0 + D1.2 两处可见行为差异**（save 几何否决、高亮参与者进 `movers`）。
   出处：`design.md:66`–`:74`、`:1097`–`:1098`。
3. **beat 节拍与 `movers` 发射集合属于 C1 允许的接缝变更**，不受「不改事件层」限制；
   被禁止的是高亮事件的**类型与概率常量**（不是涌现计数逐位相同）。
   出处：issue #175「边界（2026-10-17 复审后补）」；`design.md:34`–`:37`、`:641`–`:643`。
4. **验收主判据已预注册**：条件 `turn120`（`turnsPerPlayer`，24s/121 帧）/`staticFrac`/速度谱/

   出处：`design.md:814`–`:817`、`:973`–`:996`。
5. **最终验收是盲测，不是指标**：72 clip、7 个真实簇、≥5 零上下文裁判、δ=0.15、CI 完全落入
   `[0.35,0.65]`；"未拒绝差异"不算通过。出处：`design.md:1013`–`:1033`；#175「双盲判别是最终验收」。
6. **viewer 不是主因、引擎运动层是**：同流消融 viewer 只改旧 `turn120` −1.6%、`staticFrac` −3.2%；
   条件 `turn120` 引擎 0.829 vs 真实 0.0104、`staticFrac` 23.9% vs 3.69%。
   出处：Change 0 裁决 §2/§3/§4（该分支，本仓 main 不可自证）。

## 二、逼问

### Q1 — D1.2 的「两处可见行为差异」是否漏了第三类：可达性修复与候选拒绝？

**问题**：`D5.4` 允许改落点（传球缩短）、改接触点（tackle）、延长时限/准备期，不可行时置
`highlight_infeasible` **不发射结果**（`design.md:691`–`:704`）；`D5.3` 承认这会改变实际事件计数
（`:641`–`:643`）。但 D1.2 只列了 save 否决 + 参与者进 movers，D12 只把 D1.2 写进批准范围
（`:1097`–`:1098`）。这是**改事件几何、甚至丢事件**，不是「运动数值」。
- A：把 D1.2 扩为三类——保存否决 / 参与者进 movers / **可达性修复+候选拒绝**，并给出频次预算
  （修复率、拒绝率 ≤5%，D7.5 已有）。
- B：维持两类，把修复/拒绝当实现细节。
- C：禁止修复，不可达一律拒绝（事件丢失更多，不推荐）。

**推荐 A**。理由：用户签字的是 D1.2；审阅 R2-H5 已把「先固定结果再瞬移」定为失败，修复是唯一替代，
它必然改几何。C 会把不可达直接变成事件消失，比修复更偏离真实。
**需要用户决策：是**（批准范围的内容）。

### Q2 — 验收门槛是否太弱，重演「指标变好、用户看不出」？

**问题**：D9.1 的**通过门槛**是相对 v11：`turn120` 降 ≥50%（0.829→0.414，仍约真实 0.0104 的 **40×**）、
`staticFrac` 降 ≥30%（0.239→0.167，约真实 0.040 的 **4×**）；≤3×/≤2× 只是「目标」，
**不达目标不判失败**（`design.md:973`–`:989`）。若盲测落到「无结论」（见 Q3），
唯一能判通过的只剩这两个弱门槛——这正是用户抱怨的形态。
- A：收紧门槛到可见变化量级（例：`turn120` ≤10× 真实 ≈0.104、`staticFrac` ≤3× 真实 ≈0.12）。
- B：维持现门槛，但把「盲测无结论」定义为**不验收**（指标过门不能替代盲测）。
- C：维持现状（弱门槛 + 盲测无结论也可过）。

**推荐 A+B 组合**：门槛收紧一档，且无结论不得用指标替代。理由：Change 0 已证明引擎缺口是 40–80×，
50% 改善仍在同一量级；「最小有意义」应按用户能否在 5min 回放里看出变化来定，不由现有基线定。
**需要用户决策：是**。

### Q3 — 盲测协议可执行吗：7 簇能否给出 ±0.15 的 CI？「无结论」怎么处置？

**问题**：通过要求 95% CI **完全落入** `[0.35,0.65]`（半宽 ≤0.15），但独立真实源只有 7 簇
（`:1019`–`:1022`）；证据等级 A 要 ≥140 clip，72 clip 只能是 B（`:1030`–`:1033`）。
7 簇的多向聚类 bootstrap 半宽很可能 >0.15，**最可能的结局是「无结论」**；而设计没说无结论时
是继续迭代、拒绝 C1，还是仍可落地。另外 5 裁判 × 140 clip ≈700 次判定，**裁判媒介**
（视觉 agent/人）与零上下文隔离方式未定义；盲测所用 engine seed 是否只取留出 321–440 也未写。
- A：Phase 0 预注册三件事——① 72→140 的扩样规则；② **「无结论 = 不验收，继续迭代或拒绝」**的
  处置；③ 裁判媒介（固定 vision agent/批次/提示/随机顺序/负控）+ 盲测 engine seed 仅取 321–440。
- B：把 δ 放宽到 0.20（更易出结论，但等价性更弱）。
- C：先跑 7 簇 × 少量 clip 的哑测估 CI 宽度，再冻结 δ（可能推迟批准）。

**推荐 A**。理由：等价性判据的价值在于「不通过就是不通过」；先冻结处置规则，避免验收时临场改标准。
**需要用户决策：是**（δ 与无结论处置是验收标准）。

### Q4 — 是否加一个「先看画面」的最小 vertical slice 门？

**问题**：D7.5 的首个 1-seed smoke 只测**成本**（`design.md:894`–`:911`），不要求出 5min 回放/轨迹图
给用户看。而本仓反复出现的失败形态是「三版指标变好、用户看不出」（`visual-review` 的教训）；
D9.2 的图只在**全量验收**阶段出现。若运动核心做出来画面仍不对，最贵的协议/viewer/golden 已付完。
- A：在运动核心（不含 CommittedPlan 缓存与协议/viewer 改造）后加一道门：1 seed × 5min 回放
  + 轨迹/contact-sheet → **用户先看** → 通过再铺全量（推荐）。
- B：按现设计，全量做完再给用户看。
- C：出数字不出图。

**推荐 A**。理由：这是对「指标变好画面不变」和「viewer 尺度≠探针尺度」最直接的防线；
成本极低（1 seed + 渲图），但能提前否掉方向性错误。D9.2 的 5min-first 规则应提前到这道门。
**需要用户决策：是**（交付顺序/里程碑）。

### Q5 — CommittedPlan 是否必须与「可见改善」同批交付？

**问题**：`D2.2` 的唯一权威执行规则（计划缓存、RNG checkpoint、四阶段、三路守卫、follow-on 链）
是审阅 R4–R6 的主要工程面（`design.md:89`–`:222`）。它保证**事件锚点精确可达**，但
`turn120`/`staticFrac` 的可见改善只依赖运动积分本身；先做完它，用户看到改善的时间被推到最后。
- A：拆成 C1a（运动核心 + live scheduler + 参与者确定性前视终点，**无全状态 plan 缓存**）与
  C1b（CommittedPlan/原子提交/严格 finalize）；C1a 先过 Q4 的视觉门（推荐）。
- B：维持一个 change 一次做完。
- C：把 CommittedPlan 简化成「参与者前视 + 容差校验」，放弃全状态缓存（风险：跌破已收敛的合同）。

**推荐 A**。理由：C1a 已足以让画面从锯齿变连续弧线；把最重的合同放在视觉门之后，避免
「机制正确但方向不对」。C 会重开 R4-H1，不建议。**需要用户决策：是**（范围/交付顺序）。

### Q6 — Phase 0 是独立 PR 还是塞进 C1 大 PR？

**问题**：Phase 0 含改门（角球重锚）、改夹具（p53/p31/p6/p32）、测权威 L1、预注册指标与盲测、
测成本等非运动工作（`tasks.md:19`–`:30`）。D11 #5 已定「作为本 change 的 Phase 0」，但没说落地粒度。
若与运动改动同一 PR，审阅者无法区分「门变严/重锚」与「运动导致破带」，也无法独立对照 v11 验收。
- A：同 change 内拆独立 PR：2.1 角球重锚 / 2.2 夹具改造 / 2.3–2.5 基线与预注册 / 2.6 `ok_step`
  各自可独立验证，**行为零变化**（推荐）。
- B：全部塞进 C1 一个大 PR。
- C：拆成独立 OpenSpec change（会与 D11 #5 的措辞冲突）。

**推荐 A**。理由：保住 D11 #5 的「本 change 的 Phase 0」，同时给每块独立可验收的边界。
**需要用户决策：否**——实现规则：**每个 Phase 0 PR 不改引擎行为，对照 main v11 验证；改门的 PR 单独列出证据。**

### Q7 — 旧流（v11，beat 无 `dt`）兼容是否必要？

**问题**：D6.1/D6.2 保留旧流路径（流级 `legacyBeatSeconds=0.5`、混用报错、旧五段式合成，
`design.md:739`–`:795`、viewer spec `:43`–`:51`、`:55`–`:57`），增加双路径与测试面。
仓内未发现消费者：`viewer/*.test.js` 与 `tools/*.test.mjs` 不加载无 `dt` 的事件流。
- A：删除旧流路径，缺 `dt` 直接报错；除非存在仓外旧流消费者（推荐）。
- B：保留第一阶段兼容（现设计）。
- C：只保留「读旧流」，不保留旧五段式合成。

**推荐 A**。理由：旧流不是产品形态（viewer 用现构 wasm 生成新流）；双路径是隐藏 bug 面。
**需要用户决策：是**（是否存在仓外旧流/存档消费者）。

### Q8 — 加速度尾部指标会不会空转？

**问题**：D9.1 的加速度尾部定义为 p99 `|Δv_total|/SIM_DT`，软目标 ≤8.8 m/s²，
同时有每子步硬门 `|Δv_total| ≤ A_MAX·SIM_DT`（A_MAX=8.0，`design.md:979`）。若从**内部子步**算，
p99 恒 ≤8.0，软目标 8.8 **必然通过**——该指标不承载信息（本仓 P36 的「空转断言」教训）。
- A：改为从**已发射的 beat 端点**（`to−from`/`dt` 与相邻段速度差）算并双口径报告（推荐）。
- B：明确定性为「构造不变量」，删软目标，不进验收表。
- C：维持现状（风险：假绿）。

**推荐 A**。理由：验收指标必须对外部可观测变异有区分度；构造不变量可以作为守卫，但不能冒充现实指标。
**需要用户决策：否**——规则：**指标须能对目标变异产生区分度，否则降为不变量/报告项。**

### Q9 — L1「新增破带=失败」会不会被护栏带误杀？

**问题**：D7.2 规定新增破带=失败，**唯一例外是角球带重锚**（`design.md:830`–`:832`）。但仓内多条 L1
是**护栏带不是真实拟合带**：角球 [1,7] 与界外球 [15,60] 的注释都明写「不塌缩/不爆炸」而非真实值
（`engine/tests/realism.rs:1002`–`:1042`）；破护栏 ≠ 变差（同文件注释记录角球 4.83→14.48 反而更近
真实 10.27）。C1 改变球程/几何后若把某护栏带推出上界，会被当失败。
- A：Phase 0 增加**带分类审计**（真实拟合 / 护栏 / 过时），护栏带按**方向**判：
  向真实锚移动 = 通过，远离 = 失败；真实拟合带维持现规则（推荐）。
- B：仅按现规则（新增破带=失败）。
- C：所有护栏带降为报告项（会丢塌缩守卫，不推荐）。

**推荐 A**。理由：D7.2 的初衷是防「用旧红解释新破带」，不是把护栏中心当真实值；分类+方向判定
同时保住守卫和真实锚。**需要用户决策：是**（改变 L1 判据语义）。

### Q10 — 回退/停止条件是否可判定、谁在何时判？

**问题**：D9.1/D10 有零散触发（留出不改善、只训练 seed、微抖降 `staticFrac`、拒绝率 >5%、
save 否决 >2%、`highlight_infeasible`），但没有统一的**决策点 + 决策人 + 回退含义**
（revert / 留分支 / feature flag）。特别是 save 否决 >2% 时「停止并另立标定 change」
会让 C1 无限期挂起，没有「先试哪个更小杠杆」的次序。
- A：在 Q4 的视觉门后设显式 **Go/No-Go**（用户看 5min 回放 + 24 窗指标 + L1 非恶化）；
  No-Go = 停止、分支留档；各触发条件在此点汇总由用户判（推荐）。
- B：只在全量验收后判。
- C：逐指标自动停，无人判。

**推荐 A**。理由：回退成本随阶段指数上升；在最便宜的阶段做一次显式决策，比全量后 revert 便宜得多。
**需要用户决策：是**（停止点与回退方式）。

## 三、G3 认为仍会阻塞 design 批准的点

1. **Q1（批准范围不完整）**：D1.2/D12 只写两处，但可达性修复与候选拒绝同样改事件几何/计数；
   用户签字前必须补齐，否则批准范围与实际行为不符。
2. **Q2 + Q3（验收可能放行「指标变好画面不变」）**：弱门槛 + 最可能的「盲测无结论」，
   会让唯一通过判据退化为 50%/30% 的相对改善；必须先定「无结论=不验收」并收紧门槛。
3. **Q4 + Q5（交付顺序）**：没有「先看图再铺全量」的门，且把最重的 CommittedPlan 与可见改善绑死；
   这是本仓「三版空转」的同一形状，建议列为批准前必须回答的范围问题。
4. **Q9（护栏带误杀）**：不先做带分类，C1 可能被一条与真实无关的护栏带拦下，
   重演「换一档就有一组守卫翻红」。
