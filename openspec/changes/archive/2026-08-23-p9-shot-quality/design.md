# Design: 射门质量模型（按起脚位置分桶 + 射门起脚位置修正）

## Context

L3 实测（200 场）：
- 射门 7.14/场（普通 5.93 + 头球 1.22），转化 14.9%，射正率 50%，禁区内进球占比 12%。
- 起脚位置分布：禁区内(≤16.5m) 14.5%、16.5-25m 10.8%、25-35m 50.0%、35-45m 11.8%、45m+ 12.9%。

真实参考带（report.md §五，带来源）：射正率 ~33%、整体转化 ~10%、禁区内进球占比 ~85%、禁区内射门占比 ~55-58%、禁区外转化 4.2%、禁区内转化 14.7%。

## Goals / Non-Goals

**Goals:**
- 射门结果概率按起脚位置分桶（禁区内/外），加权后对齐真实射正率/转化率/禁区内进球占比。
- 射门起脚位置对齐真实分布（禁区内 ~55-58%），消除中场/自家半场射门。
- 头球射门对齐禁区口径。
- L1 分桶断言 + L2 起脚位置断言 + L3 gate 草案；golden re-baseline。

**Non-Goals:**
- 全场事件密度扩展（B 档，另立）。
- 失败传球 / 主场优势（A 档后续项，另立 change）。
- xG 完整建模（用分桶近似，不做逐事件 xG）。

## Decisions

### D1: 分桶模型（三桶，按起脚点到球门距离）——用户确认三桶

| 桶 | 定义 | goal | saved | off | 射正率 | 转化率 |
|---|---|---|---|---|---|---|
| 禁区内 | ≤ 16.5m（home x≥0.843 / away x≤0.157） | **15%** | **30%** | 55% | 45% | 15% |
| 禁区弧 | 16.5-25m | **7%** | **22%** | 71% | 29% | 7% |
| 远射 | > 25m | **4%** | **11%** | 85% | 15% | 4% |

加权验证（起脚分布实测：禁区内 ~58-61%、禁区弧 ~28-29%、远射 ~11-12%）：
- 射正率 = 0.61×45% + 0.28×29% + 0.11×15% = 36.7%（实测 38.3%；真实 ~33%，略偏高但带内）
- 转化率 = 0.61×15% + 0.28×7% + 0.11×4% = 11.6%（实测 13.1%；真实 ~10%）
- 禁区内进球占比 = 0.61×15% / 11.6% = 78.9%（实测 86.9%；真实 ~85%）

概率来源：禁区内转化对齐真实 14.7%（取 15%）；禁区弧对齐真实 xG 5-10%（取 7%）；远射对齐真实禁区外转化 ~4.2%（取 4%）；射正率对齐真实 ~33%。实测（200 场，H1 修正后，l3_shot_ratios 口径）：射正率 38.3%、转化 13.1%、禁区内进球 86.9%，>45m 射门 0，射门 8.14/场（普通 7.08 + 头球 1.06）。

### D2: 射门起脚位置修正（混合推进）——用户确认混合（近带球 / 远传球）

**问题**：射门槽固定间隔触发，carrier 持球位置任意（多为中场）→ 50% 中场射门。分桶概率不解决位置分布。

**方案**：射门槽 = 推进 + 射门两段（对齐「推进到进攻三区再起脚」的真实行为），起脚分布由**采样目标距离**决定：
1. 射门槽触发，先**采样目标射门距离** `d_target`（对齐真实起脚分布：禁区内 58% / 禁区弧 27% / 远射 15%，采样范围 6-16.5 / 16.6-25 / 26-34m）。
2. 若 carrier 当前 `dist_to_goal ≤ d_target`：直接射门（保持自然起脚位置）。
3. 若 dist > 40m：**向前传球推进**（传给进攻方向最靠前队友），传球完成后再进入带球推进。
4. 否则：**带球推进**（carrier 向球门移动，产 goal-directed main beat），**最后一步精确落到 `d_target`**（步长 = min(5m, 剩余距离)），起脚位置严格 = 采样值。
5. 推进段 slot 时钟暂停（同 transition 语义），保证「推进→射门」连贯呈现；步数上限 5 tick，超限强射。

**目标结果**：起脚分布 = 采样分布（禁区内 ~58%、禁区弧 ~27%、远射 ~15%），实测 61/28/11（远射略低——carrier 已近时远射目标被自然位置替代）。

**实现落点**：新增 `MatchState.shot_setup`（类似 restart_prep/transition 状态机）；`tick()` 增加分支；`roll_highlight` 的 Shot 槽触发 setup。

### D3: 头球射门对齐禁区口径

- 头球全部来自角球争顶（禁区内）→ 概率 = 禁区内桶：goal 15% / saved 30% / off 55%（替换当前 12/38/50）。
- speed 保持 [15, 20)，h=0 保持。

### D4: shot_target 微调

- goal/saved 落点保持球门矩形内（y∈[0.455,0.545]），off_target 保持贴柱偏出——L2 落点断言不变。
- 若起脚位置更靠禁区，飞行距离变短、flight 时间变短——viewer 演绎自动适配（纯函数）。

### D5: 进球数取舍——用户确认 B（射门槽微调）

- 转化率对齐真实 ~10.6% 后，7 射门/场 → 进球 ~0.7/场（当前 1.06）。
- **用户选 B**：射门槽占比 30% → **35%**，射门 ~8.4/场（普通）+ 头球 ~1.2 → 进球 ~0.9/场。保集锦进球，仍低于真实 2.75（那是 B 档的事）。
- 连锁：槽位相对 mix（shot:tackle）从 30/22≈1.36 变 35/22≈1.59——L1 断言带 [1.0,1.8] 仍适用；普通射门总数下限 800 → 200 场实测 ~1680，自动满足。

### D6: 测试更新

- **L1**：射门结果断言改**按三桶**——禁区内 goal/saved/off ≈ 15/30/55、禁区弧 ≈ 7/22/71、远射 ≈ 4/11/85（各桶样本量 ≥ 150，校准带：box goal [10,20]/saved [24,36]/off [48,60]，arc [3,12]/[14,30]/[61,75]，far [0,8]/[4,18]/[78,92]）；头球 chi-square 期望改 15/30/55；禁区内射门占比 ∈ [45%, 65%]；无 >45m 射门断言。
- **L2**：起脚位置从 known-gap 变正式断言（无距门 >45m 射门），落位 L1（`n_shot_far45 == 0`）。
- **L3 gate**（本 change 启用，因射门相关比率已对齐）：射正率 ∈ [28%, 39%]、转化率 ∈ [8%, 14%]、禁区内进球占比 ∈ [72%, 92%]（实测 38.3%/13.1%/86.9%）。
- **L1 槽位 mix**：shot 槽 35% → shot:tackle ≈ 1.59，带 [1.0, 1.8] 保持。
- **Golden**：10 canary seed re-baseline（人工审查），摘要含 n_box/n_arc/n_far 新字段。

### D7: 连锁影响

- 进球数变化 → golden 全流 re-baseline；e2e 无 snap 不受影响（无进球断言）。
- 头球概率变化 → L1 头球 chi-square 期望更新。
- 起脚位置变化 → 射门 flight 更短，viewer 动画时长变化（interpretation 纯函数，自动适配）。

## Risks / Trade-offs

- **[推进机制复杂度]**：shot setup 状态机新增，可能引入新 bug。缓解：复用现有 transition/restart_prep 状态机模式；L2 不变量（beat 间隙、t 范围、球权一致）兜底。
- **[进球数下降]**：集锦观感可能「少进球」。缓解：grill Q5 定取舍（保底选项）。
- **[起脚分布校准]**：推进步数/射程阈值决定分布，需实测校准。缓解：先宽松断言（禁区内占比 [45%,65%]），再收紧。
- **[golden 误伤]**：任何概率/位置改动都触发全流哈希。缓解：ACCEPT_GOLDEN=1 + 人工审查。

## Migration Plan

1. 引擎：D1 分桶概率 → D2 shot setup 推进 → D3 头球 → D4 shot_target。
2. 测试：realism.rs L1/L2 更新；golden re-baseline（审查后提交）。
3. verify.sh 跑通；L3 gate 启用（射门相关比率）。
4. 审阅闭环。
