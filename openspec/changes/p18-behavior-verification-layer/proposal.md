## Why

`#17A` 给出了 **6 条行为异常**（动作间隔 12.64 s、52.7% 同 tick 收束、拦截/抢断夺回率 0.0% …），
`#17B` 把它们降到了**逐 episode**。但仓库里**没有任何一条门槛**管
「球权转移的过程像不像足球」——P17A/P17B 都明说「不产生 pass/fail」，
而 `realism.rs` 的 L1/L2 全是统计分布与跨事件不变量。

⇒ `#19`（最小生成改造）改完之后，**没有机制能说"这次是真改善"**。

**主 session 给的前提需要先更正**（本 change 侦察**实跑**，
见 `.scratch/notes/18-recon-2026-09-30.md`）：

> 「真实数据只有位置、没有事件」「四类里可能只有空间关系有真实参照」

**对 P37 建的那条通路成立，对「本仓实际能拿到的数据」不成立。**
SkillCorner opendata 每场都带 `_dynamic_events.csv`（球权事件 / 无球跑 / 压迫）
与 `_phases_of_play.csv`（双侧战术阶段 + 队形宽长），**都不是 LFS，都在我们已经下载过的
那个 tarball 里**。实测四类**全部有真实参照**，其中三类是 **2.4–2.8 倍**的量级差。

⚠️ **本文与 design 的所有数字都来自 `notes/probes/` 里两份可复现探针**。
初稿的引擎侧数字（含一个 1.24 s 的头条）在**第一轮独立 grill 中被证为不可复现**
（原探针未归档且被后续覆盖）——已全部重测，修订记录见 design §10。
这条本身就是本仓「产物可比性要源码指纹」族缺陷的又一次实例，**故本 change 把
"引擎侧产物必须带 provenance" 写进了 spec**。

## What changes

- 新增 **capability `behavior-verification`**：把 `#17A` 的异常候选变成
  **可执行、成组否决、带真实参照的判据组**（`#18` 的产物原文：
  「转换反应、动作链、空间关系、球权过程四类断言及容忍带」）。
- **真实侧参照提炼器**：从 SkillCorner `dynamic_events.csv` /
  `phases_of_play.csv` 提炼**每场一个值**的参照分布，入库存成小 JSON
  （**仿 `real-shots.mjs`**：原始 CSV 在 `.scratch/tracking-data/`（gitignored），
  判据器只读入库的小 JSON，带数据 sha256 + 解析器版本做 provenance）。
- **判据组**（成组否决），三条纪律：
  1. 每条判据必须带真实参照与 provenance——「未标定」不得进判据组；
  2. **每条候选必须先回答「这个量两侧测的是同一件事吗」**，答案进 `gates-spec.json`；
  3. **不可得类必须显式声明**，不得留空、不得用代理冒充。
- **报告期落地**（不阻塞 verify.sh），形态与 P38 的 `check-criteria.mjs` 一致；
  **升门路径写死**（`#19` 交付合格机制后改 exit 码）。

### 为什么「形态条」是核心（实测证据）

三条独立实测指向同一结论——**均值会骗人，形态不会**：

1. **链内动作数**：引擎 **3.90**，真实 **3.60 ± 0.52**（全部链）／4.11（仅正时长链）
   —— **落在两栏之间**；而同一条链的时长差 **2.84 倍**、
   间隔差 **2.44 倍**。**任何只看"动作数"的门都会把这个模型判成健康**。
2. **转换反应**：引擎 **19.1% 的丢球在丢球前一拍就有人在跑、37.1% 在同一拍指派追球者、
   42.9% 在 10 s 内没有任何人去追**，唯一 0.8% 的"之后才去"**全部挤在 9–10 s 的窗口边缘**。
   **分布是双峰 + 空集**，真实侧是连续分布（p50 = 1.50 s）。
3. **传球失败率**：引擎 0.173 vs 真实 0.166 —— **几乎相同，且两侧都在 L1 带内**。

⇒ 这正是 P38 的教训（纯拟合让 3/5 条均值改善，但断层只是搬家）在**行为层**的同构。

## Non-goals

- **不改引擎**：`engine/src/` 零改动；跑位/决策、RNG、正式事件流、golden 全不动。
- **不实现 `#15B` 的 phase 标注器**，**不得**用区域冒充；但**如实上报**一条情报（见下）。
- **不重做空间关系**（P38 已覆盖）。
- **不调参、不做生成改造**（那是 `#19`）。本 change 只立**标尺**。
- **不阻塞 verify.sh**（报告期）。
- **不引入新数据源、不改下载逻辑**（`dynamic_events.csv` 与 `phases_of_play.csv`
  **已经在** `tools/fetch-tracking-data.mjs` 的下载产物里；改 `convert-*.mjs` 会撞源码指纹哨兵）。

## 如实声明（本 change 的诚实边界）

1. **restart 恢复：三段切分不可比**。引擎的 `RestartSequence` 切「死球 → 发出 → 恢复开放」，
   而真实数据里**没有"发出"这个时刻**。可得的是**整个死球期时长**
   （throw_in 19.3 s / free_kick 36.1 s / goal_kick 35.4 s / corner 41.7 s），
   它混了准备 + 飞行 + 走位。⇒ **本 change 不立 restart 判据**，
   并在 spec 里写死为**已声明的不可得**。
   ⚠️ **这是对 `map.md` #18 五类授权（含「restart 后的开放比赛恢复」）的偏离**，
   须同时在 roadmap 的 frontier 更新里记。
2. **动作链的映射表是前置**：引擎 `pass.result` 有 **5** 个取值
   （`success`/`contested`/`intercepted`/`out`/`lost`，其中 `contested` 占传球 **5.4%**，
   不是稀有值），真实侧只有 `successful`/`unsuccessful`/**`offside`** 三个。
   **先合并/映射，再比**——「拿分解去比整体」是本仓口径分叉的经典形态。
3. **真实侧 20 场是单一联赛单一赛季**（实测 `AUS - A-League - 2024/2025`）。
   故真实侧的跨场 sd 里含"同一联赛"的系统偏差；**跨数据集检查是待决策项**。
4. **本 change 不产生可阻塞的行为门**（报告期）。`#19` 的 tasks 要求「行为门结果」时，
   它拿到的是**报告 + 倍数**，真正的门要等 `#19` 交付机制后由本判据升格。
5. **本仓尚无足够历史变体**做 P38 式的「16 变体全挡」变异自证。判别力证明改用
   **反证条 + 合成变体 + 唯一的真实历史变体**（`#17A` 实测 `BASE_ACTION_DEADLINE_TICKS`
   7→3 ⇒ 间隔 12.64 → 8.54 s）。⚠️ **这三件事证明的是"判据没被改坏"，
   不是"判据组能分辨真改善"**——后者只能等 `#19`。

## 顺带上报的一条情报（**不属于本 change 范围**）

`_phases_of_play.csv` 是 **#15B 从未盘点过的观测来源**：它给出真实比赛里
`build_up / create / finish / chaotic / direct / transition / quick_break / set_play`
八档战术阶段的**占比与切换**（build_up 13.5% / create 32.6% / finish 18.4% …），
且**双侧互斥配对**、带队形宽长。

#15B 的重开前提原话是「**先找到新的观测来源**」——这条**可能已经满足**。
⚠️ 但它的词表与标注主体都与我们的 `Phase` 闭集**不同**，直接拿来当判据是**类型错误**。
**先做词表映射研究**（`#16` 量级的工作）。**本 change 只上报，不做。**
