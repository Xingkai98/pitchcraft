# Design: 抢断四段式演绎（tackle-drama）

## Context

P0 已打通"引擎 → 事件流 → 画面"链路，但 tackle 的演绎是占位水平：`interpretTackle` 只生成"防守者从 (x,y) 跑到 (x2,y2)"两个锚点，球在事件内完全不参与。用户期望抢断是一个完整戏剧：**持球 → 防守者逼近 → 碰撞捅开 → 球向旁弹开 → 有人拿到球**。且拿球者**不一定是防守者**——原持球人也可能重新拿回（抢断未成）。

本 change 只改 viewer（Phase A）。引擎/协议不动；抢断结果由事件已有字段 `result` 表达。

## Goals / Non-Goals

**Goals:**
- tackle/interception 演绎为四段式：球参与全程（先到持球者脚下、被捅开、弹开、被捡起）。
- 球权归属由 `result` 驱动：`success` → 防守者拿球；`fail` → 原持球人拿回。
- 弹开方向确定性（纯函数可测）、弹开点在场内。
- 演绎节奏参数进 config，可调。

**Non-Goals:**
- 不改引擎（Phase B 再做 nearest_opponent / loose 字段 / fail 概率）。
- 不改协议（不新增字段）。
- 不做"附近队友抢先捡球"的多方争抢变体。
- 不做滑铲/伸脚的姿态动画（第一版仍是圆点，靠节奏表达）。

## Decisions

### D1: 球权归属由 `result` 驱动（不新增字段）
- `result=success`（缺省同）→ 防守者追弹开点拿球；`result=fail` → 原持球人追弹开点拿回。
- **为什么**：`result` 是事件已有的语义字段，viewer 不该自行发明归属；这样 Phase B 引擎按概率出 fail 时，viewer 无需再改。缺省视为 success，兼容 P0 引擎始终发 success 的现状。
- **限制**：P0 引擎（含 demo）只发 success，所以 fail 变体目前只能通过 mock 观看；引擎出 fail 是 Phase B。

### D2: 弹开方向确定性、取逼近方向垂线
- 弹开向量 = 逼近方向（被铲者 − 防守者）的垂线 × 弹开距离。两个垂线候选按 `(subject*7 + to*3) % 2` 确定性选一；优先选弹开点仍在场内的候选；都越界则钳制到 [0,1]。
- **为什么**：纯函数可单测（垂直性、确定性、边界）；向侧面弹开符合"球往旁边去了"的观感，不朝进攻方向顺走。

### D3: 接触点 = 被铲者位置（保持现状简化）
- 防守者跑向 `(x2,y2)`（被铲者位置）即接触/碰撞点；被铲者在碰撞前原地持球。
- **退化守卫**：事件缺 `to` 或 `x2/y2` 时无法定位持球人，viewer 退化为最小演绎（只给防守者一个锚点），不伪造球/人位置——避免"球出现在防守者脚下"的荒谬。
- **为什么**：P0 引擎把被铲者位置发给 viewer，接触点就是它；不做更精细的"提前拦截点"（Phase B 引擎出 loose 字段后再对齐）。

### D4: 捡球节奏 = 球先到位 + 反应停顿 + 以跑速追球
- 球在 `t_loose` 到达弹开点；捡球人在接触点反应一拍（`collectDelay`），随后**以跑速（runSpeed）追到弹开点**（`t_pickup = t_loose + collectDelay + 距离/跑速`）。人球汇合 = 拾取。
- **为什么**：追球时长必须由距离/速度推导，否则捡球人会以 25-35 m/s 瞬移到弹开点；反应停顿制造节奏（interpretation-scripts 的"动作之间有节奏停顿"）。

### D5: 纯 viewer，无协议/引擎变更
- 协议校验不新增 tackle 必填（`to/x2/y2` 列必填是 Phase B 的事，P0 已有笔记）。
- mock 补全字段并加 fail 样例，保证两种归属在开发模式都可见。

## Risks / Trade-offs

- **[失败变体在 WASM demo 看不到]** → 引擎只发 success；本轮在 mock 展示 fail，Phase B 引擎加 fail 概率。
- **[demo 数据位置不连续]** → demo 各段独立，tackle 事件里防守者起点是站位而非上一段留下的真实位置，切换事件时可能有小瞬移（既有现象，非本 change 引入；Phase B 引擎给出真实位置后消失）。
- **[弹开点越界被钳制]** → 垂直性在边界处不成立，但弹开点仍在场内；测试只对场内典型用例断言垂直。

## Migration Plan

- 无（viewer 内部改动；index.html 版本号 +1）。

## Open Questions

- 拦截（interception）语义与抢断不同（截空中球），本轮共用四段式剧本；是否需要独立剧本？——建议 Phase B 再定。
