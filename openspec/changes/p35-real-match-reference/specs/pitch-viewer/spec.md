# Spec: pitch-viewer

## ADDED Requirements

### Requirement: 真实比赛对照数据源

画面层 SHALL 支持第二个数据源：预生成的真实比赛**帧序列**（公开 tracking 数据转换而来）。
该通路 SHALL **绕过引擎与演绎层**——帧序列直接插值成每帧 `{ players, ball }` 后交给同一
`renderFrame` 渲染，不产生事件流、不经过 `Game`。目的是保留未加工的真实行为作参照物，
使真实比赛与引擎比赛可背靠背切换对比。

#### Scenario: 播放真实比赛帧序列
- **GIVEN** 一份帧序列 JSON（`{ meta, frames }`）
- **WHEN** 画面层以该数据源播放
- **THEN** 按 `t` 推进播放时刻，每帧渲染 22 个球员圆点（主客队分色）与球，复用同一球场绘制

#### Scenario: 真实比赛数据缺失时给出可操作提示
- **GIVEN** `viewer/data/` 下无预生成数据
- **WHEN** 用户选择真实比赛数据源
- **THEN** 报错并提示生成方法（拉取数据集 + 转换命令），不静默失败、不停留在不一致状态

### Requirement: 帧序列与事件协议同构（id 方案与坐标约定）

帧序列 SHALL 使用与事件协议**相同的球员 id 方案**（0-10 主队 / 11-21 客队，门将占 0 与 21）
与坐标约定（归一化 0-1，`x=0` 是主队侧门线），使两边能被同一渲染层消费、直接对照。

转换 SHALL 归一化源数据的朝向：把逐帧坐标折算成「主队始终从 x=0 攻向 x=1」。

#### Scenario: 门将映射到 id 0 / 21
- **GIVEN** 源数据每队含门将（球衣号不一定为 1）
- **WHEN** 转换帧序列
- **THEN** 主队门将输出为 id 0、客队门将为 id 21，其余球员占据 1-10 / 11-20

#### Scenario: 换边后门将仍在各自半场（朝向已归一）
- **GIVEN** 源数据上下半场攻防方向相反
- **WHEN** 渲染上下半场任意时刻
- **THEN** 主队门将恒在左半场、客队门将恒在右半场（像素断言）

#### Scenario: 起始朝向相反的两场比赛都被正确归一
- **GIVEN** 两场比赛的源数据起始攻防方向相反
- **WHEN** 分别转换并渲染
- **THEN** 两场的主队门将都在左半场——朝向由数据检测得出，不依赖任何硬编码约定

### Requirement: 转换对数据缺陷不静默处理

转换器 SHALL 对无法判断的情形**报错**而非猜测，对数据固有的缺陷**如实统计并标注**而非修饰。
具体：方向无从判断时抛错；疑似球员列无法解析时抛错（不静默丢弃球员）；
球缺失、坐标重叠、场上人数不足 SHALL 统计进 `meta.coverage`。

#### Scenario: 表头列名变体不被静默丢弃
- **GIVEN** 源数据表头含 `Player 26`（带空格）这类列名变体
- **WHEN** 解析该文件
- **THEN** 该球员被正常解析（不丢失、不少一人）；无法解析的疑似球员列则报错

#### Scenario: 缺球补全带标记
- **GIVEN** 源数据存在长时段球缺失
- **WHEN** 转换帧序列
- **THEN** 缺球帧的球位为推断值并带 `ballFill` 标记，`meta.coverage.ballMissingPct` 如实记录

#### Scenario: 坐标重叠如实统计而不去重
- **GIVEN** 源数据存在同帧两人坐标完全相同的追踪伪影
- **WHEN** 转换帧序列
- **THEN** 位置原样保留（不静默挪动），`meta.coverage.duplicateCoordPct` 如实记录

### Requirement: 画面只由「此刻及之前」决定

给定时刻的渲染状态 SHALL 是**帧号的纯函数**——不依赖播放路径。同一时刻，「拖动进度条直达」
与「顺着播到」SHALL 给出相同画面；从后往前 seek 不得残留未来帧的位置或可见性。

#### Scenario: 跳着拖与顺着播一致
- **GIVEN** 含缺帧的帧序列
- **WHEN** 分别以「顺序播放」与「直接 seek」到达同一时刻
- **THEN** 球员位置、球位置、球可见性三者都相同

#### Scenario: 缺帧用过去而非未来
- **GIVEN** 某球员/球在当前帧无观测、在下一帧有
- **WHEN** 渲染当前帧
- **THEN** 用最后一次已知位置停住，不采用下一帧的位置

### Requirement: 数据源切换在异步加载下保持状态一致

数据源切换 SHALL 保持 UI 状态与当前实际数据源一致。三个 UI 状态（数据源选择、场次选择可见性、
事件导航可用性）SHALL 由当前数据源**单一推导**。加载是异步的，用户可在加载途中改变意图；
过期请求 SHALL 被作废且不得改动任何状态。

#### Scenario: 加载失败后状态回退
- **GIVEN** 真实比赛数据加载失败
- **WHEN** 失败发生
- **THEN** UI 与画面回到失败前的数据源，事件导航保持可用（不留下"引擎比赛 + 导航禁用"的死状态）

#### Scenario: 加载途中切换目标
- **GIVEN** 一次真实比赛加载正在进行（未完成）
- **WHEN** 用户在完成前切回引擎、或改选别的场次、或选回当前场次
- **THEN** 慢请求落地后不得覆盖用户的选择；数据源、信息条、计分板、事件导航四态一致

#### Scenario: 已经加载过的场次不重复加载
- **GIVEN** 某场次已加载并在播放
- **WHEN** 用户切走再切回该场
- **THEN** 不重复请求数据、直接复用

### Requirement: 对照通路的验收不依赖视觉

真实比赛对照通路的验收 SHALL 由自动化断言覆盖（转换逻辑单测、插值/播放纯函数单测、
真实数据 → `renderFrame` 的像素断言、数据源切换的 DOM 测试），不依赖截图读图。
真实数据文件缺失时，依赖它的测试 SHALL 跳过并提示生成方法，而非让整个套件失败。

#### Scenario: 渲染结果由像素断言验收
- **GIVEN** 一份真实比赛的帧序列
- **WHEN** 渲染任意时刻
- **THEN** 断言球员圆点数与分色、门将所在半场、球在场内——全部经 `renderFrame` 的绘制调用断言，
  不依赖人眼看图

#### Scenario: 缺数据时测试跳过而非失败
- **GIVEN** `viewer/data/` 下无预生成的真实比赛数据
- **WHEN** 运行依赖该数据的测试
- **THEN** 该组测试跳过并提示生成方法，套件整体不因此失败
