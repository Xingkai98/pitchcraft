### ① D2 外推点口径 = **(β) 换 n 不变估计量**

用户选择：改用 n 不变估计量（线性插值的 q10–q90）。
- 须把**插值规则一句话写死并由测试守护**——P36 D3 曾以「约定歧义」否决过 p10–p90，
  这次要正面解决：明确写清分位定义（如 `q(p) = x[floor(p*(n-1))]` 的线性插值形式）、
  边界行为、n 很小时的表现，并给守护测试。
- **必须同步重生成基线**（P36 的 `hashMetricsModule` 陈旧性校验会因此失效——这是设计意图）。
- 实测依据：把口径差从 8.5m 压到 ~4.8m（只留检测效应）。
- ⚠️ 不要用审阅建议的「比例修剪」（你已复核是空操作，保持这个结论）。

### ② D5 窗口步长 = **900s**

用户选择：沿用 900s 步长（139 窗，与 P36 窗口定义可比）。
- 声明里写清：可比仅在**窗口定义**上成立，帧密度差 3–6 倍。

### ③ D6 样本组合 = **两套分别报告**

用户选择：SkillCorner 为主、Metrica 作对照**分别报告**，并把

## P1. 抓取与转换器

- [x] P1.1 `tools/fetch-tracking-data.mjs` 增加 SkillCorner 数据集条目：
      仓库用 codeload 打包（~25.7MB，含 `match.json` 等小文件）；**tracking 实体是 LFS 指针**，
      须逐场从 `media.githubusercontent.com/media/SkillCorner/opendata/**master**/data/matches/<id>/<id>_tracking_extrapolated.jsonl`
      拉取（分支是 **master**，用 main 会 404）。
      - 单场失败**可跳过/可续**；**并发下载**（实测单连接 90KB/s–2MB/s 抖动，串行 20 场要数小时）。
        ⚠️ 实现期的两个坑：① 完整性判据用 **LFS 指针的精确字节数**——用「最小字节数」下限会把
        **截断下载**当成完整（实测 17/20 被误判，直到解析才炸且错因看着像"格式不对"）；
        ② 并发须让 curl **不阻塞事件循环**（用 `execFileSync` 会把 worker 池串行化，并发形同虚设）。
      - 记录许可（MIT）与来源；落 `.scratch/tracking-data/`（gitignored）。
- [x] P1.2 `tools/convert-skillcorner-to-frames.mjs`：SkillCorner → 帧序列（与 Metrica 转换器同构）
      - 坐标系：米 + 球场中心原点 → 归一化 + 平移到左门线；y 轴翻转与 Metrica 转换器一致
      - **球场尺寸按每场取值**（104/105/106，不得硬编码），记入 `meta.pitchMeters`
      - 朝向：`match.json.home_team_side[period-1]`，`right_to_left` 翻 x；
        **显式跳过 `period ∉ {1,2}` 的帧**（审阅 5.3：`period` 可为 null，
        下标到 null **不报错、静默不翻转**）；**加朝向自检**（归一化后两队门将应各贴一侧，
        判反即报错——审阅 5.6 实测验证了规则成立）
      - 身份：`players[]` 按 `team_id` 分队；门将用 `player_role.name == 'Goalkeeper'`
        （**注意 `position_group` 对门将是 `"Other"`**）；tracking 的 `player_id` 对应
        `players[].id`（**不是 `trackable_object`**，实测交集 0）
      - 槽位：**门将槽由 `player_role` 钉死**（指标层靠剔 id 0/21 剔门将，钉死才保证剔对）；
        替补顶槽位保证每帧 11+11 稳定（审阅 5.4：SkillCorner 给了 role 与出场时间，
        比 Metrica 的几何启发式信息更多，不必沿用 `assignIds` 思路）
      - **时间轴拼接**：P2 平移 `shift = max(P1.t) - min(P2.t)`，产出单调时间轴；
        **优先用 `match.json.match_periods` 的权威半场边界**（审阅 P2-1d：观测极值法
        在首尾缺帧时会静默失真，实测截断场次算出 77.9s 而非 ~190s），
        偏移量与结果接缝间隙记入 `meta.timeAxis`
      - **外推标记透传**：`is_detected=false` 的点写入帧序列（形状见 P1.3）
      - **球的外推标记透传**（审阅 P2-6，初稿遗漏）：球坐标**从不缺失**但 17.7% 是外推，
        须标进 `ballFill`（`'extrapolated'`），否则被当原始观测进主口径
      - 缺球补全：沿用 `ballFill` 语义（`nearest`/`hold`/`none`）与 `ballFill` 标记
      - `meta.coverage`：填充率、球缺失率、**外推点占比**、**球外推占比**、`shortHandedPct`、
        重复坐标率、出界点占比
- [x] P1.3 帧序列 schema 扩展：外推标记的字段名与形状**写定并入库**
      → **选定形状：外推点的坐标数组带第三位 `1`**（`[x, y, 1]`），真检测点只有 `[x, y]`。
