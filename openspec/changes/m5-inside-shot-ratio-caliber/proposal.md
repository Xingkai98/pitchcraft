# 改进提案：`禁区内进球占比` 的真回归修复 + 尺子口径订正（M5）

## Why

`l3_shot_ratios` 的 `禁区内进球占比` 带 `[0.72, 0.92]` 今天**只是勉强绿**（门禁窗 401..600 实测 **0.7211**，
余量 **0.0011**；7 个互不相交块里 **3 块破**）。定性在
`.scratch/notes/p-inside-regression-2026-10-14/REPORT.md`：

1. **是真回归，不是带太紧**：`8e6e292 → main` 配对差 **−0.0280（9/9 块为负，t = −4.7）**；
   元凶 **`2d391c2`（p143r-v4 四层落地）**：`8e6e292 → 2d391c2` 配对差 **−0.0416（8/8 块为负，t = −8.7）**。
   机制是**射门构成位移**（射门 17.8 → 23.7/场，新增射门不成比例来自禁区外），
   **不是任何一条概率常量**（桶概率是写死的，五个单点消融全失败）。
2. **尺子本身是 y-blind 的**：`l3_shot_ratios` 判「禁区内」用的是 `(1−sx)·105 ≤ 16.5`，
   **完全不看 y** —— 一个无限宽**板条**；真实锚的「禁区内」是**罚球区矩形**
   （深 16.5 m × 宽 40.32 m，`|y−0.5|·68 ≤ 20.16`）。板条 **⊋** 矩形 ⇒ 门此前**系统性偏高**。
   v4 把这个口径差放大了 **15 倍**（板条内/矩形外的射门 4–6 → **75–96**/200 场）。
   换矩形口径，main 门禁窗是 **0.6825 —— 已在旧带 [0.72,0.92] 之下**。
3. **引擎侧的真缺陷**：`shot_bucket` 的**禁区外两档**声明值混用了两把尺子（「禁区弧 xG 5-10%」
   与「禁区外聚合 4.2%」），按射门构成加权后聚合到 **7.5%**，是真实锚 4.2% 的 **1.8 倍**；
   而**禁区外射门体量**也偏高（引擎兑现的禁区内射门占比 0.522 vs 真实 55-58%）。

## What Changes

### (a) 尺子 → 真实罚球区矩形（`engine/tests/realism.rs`）

- 新增 `MatchStats::n_goal_in_slab` / `n_goal_in_rect`（**几何**分类，含头球，用 shot 事件自身的 `x/y`）。
- `l3_shot_ratios` 的 `inside_r` 改用**矩形**口径，断言带由 `[0.72,0.92]` 改为 **`[0.80,0.91]`**（两端的取法见下方「带值裁定」）。
- **板条口径与旧口径（含「全部头球算禁区内」规则）都保留在同一行 `println!` 里**，证据不删。
- ⚠️ **这不是为了过关**：换口径后本窗读数**立刻变差**（`0.7211 → 0.6825`）。

### (b) 引擎 → `shot_bucket` 禁区外两档（`engine/src/lib.rs`）

- 禁区弧 `(7,22)` → **`(3,22)`**；远射 `(4,11)` → **`(2,11)`**。**禁区内 `(15,30)` 不动**。
- 依据（真实侧聚合锚）：PL 官方 2024-25 **整个禁区外**转化 **4.2%**（近十年 3.5%）。
  同比例缩两档（含主场优势通道①的 +0.94 pp：`0.759·(7k+0.94) + 0.241·(4k+0.94) = 4.2` ⇒ `k ≈ 0.52`）
  → `arc 3.6 / far 2.1` → 取整 `(3,2)` ⇒ 声明期望聚合 **3.70%**，落在真实区间 `[3.5,4.2]` **内**
  （候选 `(4,2)` 的期望聚合 4.46% 在区间**外**，实测 5.02% 也证实这一边）。
- **两条落地前补齐的理由**（判据镜点名，首版缺；已写进 spec delta）：
  (a) **单调性的实测依据**：M5 实测禁区弧 **4.18%** > 远射 **3.49%**（10 块逐块先算再平均），守序；
      反例「只缩禁区弧」（弧 `7→3`、远射不动）实测弧 **4.11%** < 远射 **5.57%**、**8/10 块违规** ⇒ 反物理。
  (b) **「远射取 2 不取 1」的显式理由**：`(3,1)` 的声明期望**取决于口径**——按上面那条**仿射式**算是
      **3.46%**（**出带**，低于下沿 3.5%），按**实际桶构成的精确式**算是 **3.55%**（带内，但离下沿只剩
      0.05 pp）。**两套口径不可混引**（见 spec delta 与 `lib.rs` 同段的 ⚠️）。⇒ 无论取哪套 `(3,1)` 都**很薄**，
      取 2 靠的是**「按桶权重同比例缩放」这条建模选择**，spec 已写死。
- **只动远射档是死路**（实测）：远射单独缩到 2、禁区弧保持 `7/22` 时矩形口径只到 **0.7432**、破带
  ⇒ **禁区弧那一档承担几乎全部效果**，两档必须同缩。

### (c) 引擎 → `sample_shot_target` 禁区内射门体量（`engine/src/lib.rs`）

- 禁区内占比 **58% → 70%**（禁区弧 27→20、远射 15→10）。
- 依据（真实侧，两个互斥锚取中点）：锚 A「~42-45% 射门来自禁区外」⇒ 禁区内 **0.565**；
  锚 B 由「禁区内转化 14.7% + 禁区外转化 4.2% + 禁区内进球占比 88.3%」联立 ⇒ 禁区内 **0.683**。
  两者不能同时成立 ⇒ 取**中点 0.624**；按**兑现率**（声明 58→兑现 0.522）定标 ⇒ 声明 70%（兑现 0.6226）。

### (d) 带值裁定：`[0.80, 0.91]`（两端同类读数）+ 余量按最坏块报

- 一条带的两端必须由**同一类**真实读数定：只留**直接**读数（0.883、85–88%）⇒ `[0.80, 0.91]`；
  把**派生**读数（联立而得的 ~90.1% / 82.0–82.9%）也算进去则是 `[0.77, 0.93]`。
  **取前者**（直接读数更可信），且它相对候选 `[0.80,0.93]` 是**收紧上沿**、相对旧带 `[0.72,0.92]` 是**整体收紧**。
- **余量按「全部已扫描块的最坏值」报**：M5 单独最坏是块 `801..1000` 的 **0.8075** ⇒ **+0.0075**；
  叠 M1b 后最坏块同为 `801..1000` 的 **0.8152** ⇒ **+0.0152**。
  ⚠️ **不得**引用 `+0.0177`（那只是 7 个起点的稀疏采样，已被两次独立复核证伪）或门禁窗的值。
- **登记已知债**：同族 `射正率 [0.28,0.39]` 在块 `201..400` 上 M5 实测 **0.3921** 破上沿（跨窗才可见）。

### (e) golden 版本 bump（`MODEL_VERSION` 8 → 9）+ 新建 `tests/golden-v9/`

- 行为改动按**仓惯例**（P29→3 / P30→4 / P31→5 / #104→7 / p143r-v4→8）bump 模型版本并**新建** golden 目录，
  **旧目录保留不覆盖**作历史对照（`golden-v8` 是 p143r-v4 四层的基线，被别的记录引用，**不得覆写**）。
- `golden_dir()` 加 `9 => "tests/golden-v9"`；`ACCEPT_GOLDEN=1` 生成 10 个 canary seed，提交前人工审 diff。
- `MODEL_VERSION` **不参与模拟**（只决定 golden 目录选择）⇒ 本步**不改变任何引擎行为**、不影响全量红名单。

### (f) 订正一处陈旧因果注释（`engine/src/lib.rs`，只改注释）

`BASE_DEF_TACKLE` 上方的注释把 `禁区内进球占比` 的下跌归因于该常量轴（「越深越贴 0.72 下界」）。
9 块配对检验证伪：那次改动（`f9edf67 → cd42b0a`）的配对效应是 **+0.0094（t = 1.12，n.s.，符号还为正）**。
**取值（−0.92）不动**，只订正因果叙述并指向 `p-inside-regression-2026-10-14/REPORT.md` §4。

两个未归档 change 携带**相邻 requirement** 的旧 delta：

- `openspec/changes/p104-volume-recalibration/`：MODIFIED `主场优势（主客进球不对称，L1）` 与
  `射门槽频率（L1）`；另有一个 `## Unchanged` 节把 **`l3_shot_ratios` 的 `inside [0.72,0.92]`** 与
  **`l1_shot_result_distributions` 的九条桶带**列为「不动」——**这两条正是本 change 改的**。
  （已核对：p104 对 `主场优势` 的整块复制与当前主 spec **逐字相同**，对 `射门槽频率` 的复制
  在本 change 之后归档会让该 Scenario 的**例证数字**（ratio 0.563）变陈旧——那是 #104 时代的读数。）
- `openspec/changes/home-advantage-conversion-observable/`：MODIFIED 同一条 `主场优势`。

**推荐顺序：先归档本 change，再归档 p104**，并在归档 p104 时**同步修订其 `## Unchanged` 节**
（把 `l3_shot_ratios` 的 `inside` 与 `l1_shot_result_distributions` 的桶带从「不动」列表移除或改写为
「已由 M5 重标」）。否则该节会与主 spec 已生效的新带**自相矛盾**。
本 change 的 delta 已按**当前主 spec 全文**复制两条 MODIFIED requirement。

## 不做

- 不碰 L2 不变量、golden 之外的任何门；不改 `CLINICAL_GOAL_PP_*`、不改防守/传球/移动层常量。
- **不改** `shot_bucket` / `shot_bucket_index` 的**几何**（仍是 y-blind 轴向分桶）——
  「板条内、矩形外」那 ~96 射 / 18 球仍按禁区价（15%）结算。这是**已量化的已知残留**
  （见 M5-REPORT「未知」节），修它要动桶的签名与 `l1_shot_result_distributions` 的分类口径，
  超出本 change 的「只动这两档」范围。
- 不改 `l1_shot_result_distributions` 的九条桶比例带（改 `shot_bucket` 后**实测全过**，余量最小 0.019）。
- 不改 `禁区内射门占比` 的 `[0.45, 0.65]` 带。
