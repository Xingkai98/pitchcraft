## Why

P16（PR #123）用**空间特征**裁决三档 phase，结论是**部分够**：

- `final_third` **可判**（`forward_m/s` AUC 0.855 / 30 seed、0.862 / 300 seed）；
- **`build_up` / `progression` 判不了**（**0.461** / **0.431**）。

P16 的审阅者**自己扫了 21 个空间量**想分开后两档，最强非循环量只 **0.634**
⇒ **「空间量本身不足」**，不是「特征没选好」。继续在空间维度加特征救不了。

P16 报告点名的缺口是**能表达「意图」的观测**：

> 需要能表达**意图**的观测（如**射门窗口开启信号**、**防守方位置/线路**）

## What changes

**关键前提：这不是造新机制，是「把已有的接出来」。** 引擎里本来就有这些状态，只是没出口——
与两个先例完全同模式：

| 信号 | 引擎内有 | 在 sidecar |
|---|---|---|
| 位置 `st.pos` | ✅ | ❌ → **P16 G1 已接出** |
| `transition` 窗口 | ✅ | ❌ → #113 已处置 |
| **`shot_setup` / 起脚窗口** | ✅（`in_window` / `window_ticks` / `drive_ticks_left` / `committed`） | ❌ |
| **防守动作 / 压迫** | ✅（`DefensiveAction` 的 Tackle/Foul/Contain/Jockey + `pressure_state`） | ❌ |

- 与 G1 同法：**只加只读观测**——不改 `ControlFact` 闭集、不改正式事件流、不动决策、不碰 RNG；
- 产出**意图类特征**（逐 episode）：起脚窗口是否开启/何时开启/窗口内让步、防守方压迫强度与
  方式分布、持球者被压迫程度等；
- **重跑 phaseability gate**：三档 AUC 是否改善；
- **重新净化 motif 混淆**（P16 遗留的前置）：`build_up` 与 `progression` 在
  「传球数」与「是否重开」上同时不同，接入新信号后必须再抽一次。
- 产出**明确裁决**：够（给三档可执行谓词）或不够（点名还缺哪类观测 + #15B 的处置）。

## Non-goals

- **不实现 #15B**；**不改跑位/决策逻辑**；
- 不改 RNG、正式事件流协议、viewer 正式播放；
- **不得用区域/坐标冒充战术阶段**：若最终只能用几何代理，须命名为**证据**
  （如 `GoalwardProgressEvidence`），**不得复用 `Phase`**（与 #113 对 `attacking_transition` 的同类处置）；
- 不因 gate 结果调参数（那是 #19）。
