# Change 0 汇合裁决：先修哪里，以及 Change 1 的方向

日期：2026-11-19。Change 0 = GitHub #190 / `p155-measurement-instrument`。
输入：A（冻结刺激集 + 同流渲染消融）+ B（条件指标 + 球静止分解 + L1/守卫审计）的合并树。
**本文件不改任何引擎/viewer 行为；所有历史 L1 当前值仍是转述，本次未跑 200 场 L1。**

## 0. 一句话

**viewer 不是主因；引擎运动层是。** 同一事件流下，现行 viewer 只把旧 `turn120` 改了
−1.6%、`staticFrac` −3.2%；而引擎 raw mover 端点已经是旧 `turn120` 5.983 / `staticFrac` 0.247。
条件化（双方步速 ≥0.5 m/s）后，引擎 0.829 vs 真实 0.0104 = **79.6×**（不是旧的 24×）。
⇒ Change 1 应做**引擎统一运动执行层**，不是继续修 viewer。但动之前必须先把
「护栏带当真实锚」「脆弱场景守卫」这两类锁拆开，否则结构改动仍会被旧门拦下。

- `t1` 与 `current` 逐帧最大坐标差 **0**（2904 帧全等）⇒ 现行 viewer 没有 T1 之外的额外运动加工。
- `direct`（零阶保持）把旧 `turn120` 放大到 **23.798**、`staticFrac` 到 **0.705**、条件 `turn120` 到 **0**

**裁决：viewer 不值得作为第一优先。** 24×/6× 在引擎端点里已经存在；viewer 只加连续自转
（+21%，但引擎锚点本身已是真实 2.3×）。如果 Change 1 后 `rotationTurns` 变成残余主判别量，
再单独修 viewer 的 Catmull/T1 才有依据。

## 3. 条件 turn120：旧 24× 被低估了

B 的冻结 24 窗（A engine + R7i 同锚点 real）：

| 口径 | Engine | Real | E/R |
|---|---:|---:|---:|
| 旧 turn120（零步也计角） | 5.885 | 0.244 | 24.1× |
| 条件 @0.3 | 0.908 | 0.025 | 36.3× |
| **条件 @0.5（主口径）** | **0.829** | **0.0104** | **79.6×** |
| 条件 @1.0 | 0.692 | 0.0083 | 83.0× |
| 每有效步对（@0.5） | 0.0100 | 0.000091 | 109.5× |
| 每有效米（@0.5） | 0.0112 | 0.000172 | 64.7× |

- 零步伪角在**两侧都存在**，但真实被抬高得更多：旧/条件 = real 23.4×、engine 7.1×。
  ⇒ **「24× 是伪角造出来的」不成立**；伪角只是把两侧一起膨胀，并把真实膨胀得更多。
- 宽扫（非冻结）：all 11×、active 31×（口径不同，不可与 79.6× 混表）。真实条件转向在
  SkillCorner 上 0.0025、Metrica 上 0.050 ⇒ **E/R 比值受数据集组成影响，报告必须带数据集**。
- 窗级分布（frozen）：engine 条件@0.5 p10/p50/p90 = 0.43/0.80/1.24；real = 0/0/0.05。
  ⇒ 不是少数离群窗；真实 24 窗里大多数窗的条件转向为 **0**。

**裁决：条件化没有缩小差距，反而放大；引擎的「真的在 ≥0.5 m/s 下反向」是主缺口。**

## 4. 静止与球静止

`staticFrac`（frozen）：engine **23.9%** vs real **4.0%** = **6.0×**。
档位敏感性：<0.2 → 31.5×、<0.5 → 6.0×、<1.0 → 1.8×。⇒ 缺口集中在「逐比特/近零静止」，
不是「所有速度都慢」。

`ballStaticFrac`（B，raw-ball 口径）：

| 口径 | Engine | Real | E/R |
|---|---:|---:|---:|
| frozen 24 窗 | 21.6% | 2.15% | **10.0×** |
| 宽扫 all 1125/476 窗 | 16.5% | 4.3% | **3.8×** |
| 宽扫 active 465/107 窗 | 11.7% | 4.5% | **2.6×** |

- **10× 只在 R7i/A 冻结锚点上成立**；换窗口/数据集落到 2.6–3.8×，方向不变（引擎始终更静止）。
  不要把 10× 当全语料常数。
- 球相关量必须只用**原始球帧**；把 Metrica 的 `ballFill` 补全帧算进来会把 real 抬到 ~15.5%，
  制造「all-window 无差」的假象。
- 来源分解（frozen）：`carrier_hold` 时间 22.3% / 条件静止率 32.7% / **贡献 51.4%**；
  `loose` 15.1% / 64.2% / **30.5%**；`highlight_flight` 26.5% / 8.7% / **15.3%**；
  `restart_dead` 1.3% / 81.3% / 2.8%；`carrier_dribble` 34.7% / 0% / 0%。
  ⇒ **`CARRIER_HOLD_PP=45` 不是时间占比（hold 时间 22–28%），更不是静止率**。
- active 宽扫：hold 59.0% / highlight 23.9% / loose 14.3% —— 高光飞行的「落点停驻」也是重要来源。

## 5. L1 / 守卫审计：哪些带能当真实锚，哪些不能

B 的 `notes/l1-band-audit.md` 逐条审计（42 条断言）。最重要的结论：

1. **`l3_shot_ratios` 射正率 [0.28,0.39]，当前 ~0.47–0.49 → 真红，且是机制问题**，不是带宽问题。
2. **`l1_shot_result_distributions` 禁区内 goal [0.10,0.20]，当前 ~0.06 → 真红**；
   禁区内射门占比 [0.45,0.65] 上沿余量仅 0.027。
3. **角球均值 [1,7] 是护栏带，不是真实拟合**（真实 ~10.27/场）；当前 7.7–8.3 红。
   **上沿 7 会禁止向真实 10.27 收敛**；单场 max ≤15 的余量只有 1。→ 动运动层前必须先决定
   「角球带是否重锚」，否则任何抬体量/抬球程的改动都会先撞它。
4. **主场优势带 [0.85,1.60] 是按引擎旧中心 1.188 的相对容差重标的，不是真实分布推导**；
   方向门 `home_conv > away_conv` 功效低（通道砍半仍绿，z≈0.76）。→ 记录门，不作为物理不变量。
5. **传球成功率 [0.82,0.90] 口径不完全对齐**：引擎分母含发球重开/出界，真实队级统计通常不含
   定位球 ⇒ 同一数字不是同一量。引用时必须带分母。
6. **射门体量 [14,29] / 抢断体量 [24,50] / 犯规 [16,30] 是真实拟合（或宽真实拟合）**，
   但下沿/上沿余量薄；它们是应该保留的硬门，不是护栏。
7. **`realism.rs:1269` 存在跨版本冲突**：注释称 #104 inside 0.753 三条全过，当前带是
   [0.80,0.91]；未删/未放宽，但必须在下一次重标定时修正。
8. 真不变量（确定性、坐标、身份、事件/状态对账、球权）保留硬门；p53/p31/p6/p32 的**契约**
   保留，但应换成「显式构造场景 + 条件断言 + 多 seed 置信范围」的夹具（`notes/guard-audit.md`）。

## 7. Change 1 建议

### 7.1 先做（与 Change 1 同一 change 的前置，不单独开行为改动）

1. **确定角球带的处置**：角球均值 [1,7] 是护栏且上沿禁止向真实 10.27 收敛。二选一：
   - 重锚到真实锚（例：均值 [7,13] 或按真实分布定），并保留单场 max 的护栏；
   - 或明确「角球不是本阶段目标」，把该带降级为报告项，但**不得**用删红门过关。
   必须在 Change 1 design 里拍板，不能默认略过。
2. **给 p53/p31/p6/p32 建不变量式夹具**（`notes/guard-audit.md` 的建议），保留契约、替换固定 seed 触发。
   否则 Change 1 的运动改动会重复 R7c/R7d 的「每换一档就有一组守卫翻红」。
3. **锁定 Change 1 的预注册指标**：条件 turn120、staticFrac、ballStaticFrac、速度分位、加速度尾部；
   训练/留出 seed 与真实窗分开；L1 的既有红先列清单，新增偏离按真实锚联合重标定。
4. **不改** `l3_shot_ratios` / `box_goal` 的真实拟合身份；它们是机制红，不能靠放宽带宽过关。

### 7.2 Change 1 本体：引擎统一运动执行层

- 在 `MatchState` 加每球员 `MotionState { velocity, desired_velocity, mode }`（米制向量）。
- 把 `compute_mover_candidates` 的固定步长追点改为「带制动距离、加速度约束的速度执行」；
  减速到达，不用 `DEAD_ZONE_METERS=2.0` 的整拍开关。
- 明确 `MAX_ACCEL` / `MAX_BRAKE` / 目标响应时间 / 模式速度上限；数值来自同口径真实速度/加速度分布，
  design 阶段不猜常数。
- `carrier_move` 输出运动意图（hold 可为稳定低速控球，不能用独立随机端点替代速度状态）；
  保留真实战术停球与死球。
- `beat_movers` / `beat_movers_main` 统一执行；`commit_beat_positions_ex` 改为可达性与避让约束提交，
  最后同步实际速度、球位与输出；若 solver 仍可任意推端点，加速度硬约束会被绕过。
- 高亮接球者、门将、重开追球者不能绕过统一执行；`highlight_frozen_segs` 用同一运动段与时间语义。
- 决策仍 2Hz；内部可子步，但固定步长、固定顺序、无新增随机抽样，不把射门/抢断机会随积分频率倍增。
- 协议版本化：可先保留端点做最小实验；正式版本输出时间戳 + 起终速度/运动段，viewer 只插值同一轨迹。
- 预期能移动：条件 turn120、加速度尾部、停走比例、速度谱、部分球静止；
  **不保证**个体运动量 CV、传球选择、射门体量自动变真。
- 回退条件：留出窗条件 turn120/速度尾部不改善、出现系统性大回环/碰撞、只靠微抖降低 staticFrac、
  接球可达性失败、改善只在训练 seed。

### 7.3 Change 2（条件触发）

只有在 Change 1 之后、残余证据仍指向「个体运动量差异/支援/覆盖可读性」时，才加
`TaskState { kind, target_id, started_at, expires_at }` 与角色预算；formation 只作软空间先验。
若球静止残余主要来自 carrier/loose，再建连续控球/触球状态。

## 8. 不确定项与最小补实验

1. **真实条件 turn120 的数据集依赖**：frozen 79.6×、all 11×、active 31×。需要 SkillCorner 全量
   真实窗与 Metrica 分层报告；不能把 79.6× 当所有真实足球的普适常数。
2. **ballStatic 10× vs 2.6–3.8×**：需要同一批真实窗的 raw-ball 口径与数据集分层；不要把 10× 当全语料。
3. **L1 当前值全部是转述**：本次没跑 200 场 L1；Change 1 前应跑一次权威 L1，把「当前值」列变成实测。
4. **viewer 消融只覆盖当前事件流**：未覆盖不同 config/快进档；如果 Change 1 改协议，需重跑消融。
5. **历史 R4/R5c/R7 因果**：本 change 只转述，未重跑；Change 1 design 不应把它们的单点结论当契约。
6. **无 48 项盲测**：Change 0 不验观感；Change 1 必须用 48–72 项 + ≥5 裁判做最终验收。

## 9. 结论

- **Viewer 不是第一优先。** 先修引擎运动执行层。
- **条件 turn120 79.6×** 是比旧 24× 更硬的靶；旧值被零步伪角低估。
- **动运动层之前，先拆两把锁**：角球护栏带的重锚决策、p53/p31/p6/p32 的不变量化夹具。
- **L1 的真实拟合带（射门/抢断/犯规体量）保留**；`l3_shot_ratios` / `box_goal` 是机制红，
  不能靠放宽带宽过关。
