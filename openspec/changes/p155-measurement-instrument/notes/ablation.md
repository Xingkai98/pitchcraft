# 同流渲染消融（Change 0 / A）：viewer 到底贡献了多少

日期：2026-11-19。工作流：GitHub #190 / Change 0 的 A（冻结刺激集 + 同流渲染消融）。
行为零改动（`git diff -- engine/ viewer/` 为空）；本文件与其数据只来自新增工具，不改任何判据。

**一句话结论**：`turn120` 与 `staticFrac` 的缺口**不在 viewer**。同一事件流下，
现行 viewer 全链只把旧 `turn120` 改了 **−0.098 / 球员 / 窗（区间 [−0.191, −0.005]）**、
`staticFrac` 改了 **−0.008（[−0.009, −0.006]）**，方向还是**略降**；而引擎自己的
beat mover 端点（`movers`）已经是 **5.983**，对照真实转述值 0.244 仍是 **24.5×**。
viewer 唯一明显加的量是**连续自转**：`rotationTurns` **+0.985（[+0.931, +1.038]）**，
但引擎锚点本身已是真实值的 2.3×。**⇒ viewer 不值得先修**（针对当前判别量）。
`ballStaticFrac` **不列入本结论**：`movers` 的球位与 viewer 同源，本次无法分离（归 B）。

## 1. 五条（+1 诊断）路径

| 模式 | 含义 |
|---|---|
| `movers` | **只用引擎 beat 的 main/movers 端点**（from→to 拍内线性、拍外保持）。不采信 viewer 为 pass/shot/tackle 等合成的锚点 → 「引擎 mover 意图」的代理 |
| `direct` | 全部 viewer 锚点的**零阶保持**（不拍内插值）→ 采样方式伪影的对照 |
| `linear` | 锚点线性插值（事件间真间隙 hold，与 viewer 同规则），无 Catmull、无纹理 |
| `catmull` | 线性 + 球员 Catmull–Rom（仅均匀拍链，与 viewer 同条件） |
| `t1` | Catmull + T1 弓形纹理（= viewer 默认球员路径） |
| `current` | 现行 viewer 全链（直接跑 `viewer/game.js` 的 `Game.seekTo`） |

⚠️ `movers` 的球位仍取 viewer 球锚点（球不在 mover 几何内），故 `ball*` 指标在 `movers` 列
**不是**独立引擎读数，只作对照。`direct` 不是「引擎意图」——它是把分段常值路径按 5Hz
采样的方式，零步伪角因此被放大（见 §3）。

读法（逐条都有区间，不取单点）：

1. **viewer 全链（current−movers）对折返/静止是「略降」**：旧 turn120 −0.098、条件 turn120 −0.079、
   staticFrac −0.008，三者区间都不含 0；方向都是让引擎**更不静止、更少折返**。相对于
   `movers` 的 5.983 / 0.908 / 0.247，相对量级分别是 **1.6% / 8.7% / 3.2%**
   （绝对值 ≤0.1 折返、≤0.08 条件折返、≤0.008 静止占比；条件口径的百分比大是因为基数小）。
2. **viewer 加的是连续曲率**：`rotationTurns` +0.985（4.681 → 5.666，+21%）、自转/米 +0.012、
   加速度 p95 +0.72、路径 +0.85m。逐层看：Catmull +0.272、T1 +0.724。这与 R7「viewer 转弯率
   2×」的转述不矛盾——但**它是连续小转角，不是 >120° 折返**。
3. **viewer 的锚点合成几乎不贡献**（linear−movers）：旧 turn120 −0.023（区间含 0）、
   staticFrac −0.006。也就是说 pass/shot/tackle 的演绎锚点不是判别量来源。
4. **`direct` 是伪影，不是意图**：零阶保持把旧 turn120 放大到 23.798（≈4×）、staticFrac 放到 0.705、
   条件 turn120 压到 0（每步都在「静止」与「跳变」之间切换）。这定量复现了普查
   `atan2(0,0)=0` 的零步夸大机制——**任何用步进/保持采样锚点的分析都必须避开它**；
   本次裁决因此以 `movers`（拍内线性）而不是 `direct` 作为「引擎意图」。
5. `t1` 与 `current` 的 7 个配对差**全部 0**（逐帧坐标差 0.00e+0）：现行 viewer 没有 t1 之外的
   运动加工，`current` 列可视为 `t1` 的等价验证。
6. `ballStaticFrac` 行的多数 0 差值**不是**「viewer 不影响球」：`movers`/`linear`/`catmull`/`t1`
   共用同一份 viewer 球锚点，只有 `current` 因高亮特判在个别窗不同（1/24）。
   球的引擎/演绎贡献本次**不可分离**，归 B。

## 5. viewer 贡献区间（结论）

| 判别量 | viewer 贡献（current−movers，每球员/窗） | 相对量级 | 是否改变「引擎 vs 真实」的结论 |
|---|---:|---:|---|
| 旧 turn120 | −0.098 [−0.191, −0.005] | −1.6% | 否（仍是 ~24×） |
| 条件 turn120 | −0.079 [−0.148, −0.010] | −8.7% | 否（真实锚待 B） |
| staticFrac | −0.008 [−0.009, −0.006] | −3.2% | 否（仍是 ~6×） |
| ballStaticFrac | n/a（球锚点同源） | — | 不可分离，归 B |
| 自转圈数 | +0.985 [+0.931, +1.038] | +21% | 不改变主因（引擎锚点已 2.3×） |
| 速度 p90 | +0.148 [+0.104, +0.191] | +2.6% | 否 |
| 路径长 | +0.853 [+0.733, +0.974] m | +1.1% | 否 |

**不可分解 / 缺什么**（如实写，不四舍五入成百分比）：

1. **真实侧贡献**：本次没有重算真实帧特征（SkillCorner n/a），所以「viewer 让引擎离真实更近还是更远」
   用的真实锚是**转述**。要直接回答，需要下载 SkillCorner 并把 24 个真实窗跑同一 `windowFeatures`。
2. **「引擎事件层 → 锚点」这一段的内部归属**：`movers` 用的是 beat 端点，而 beat 端点本身由
   2Hz 目标决策 + 分离 solver 生成；本消融把「引擎内部（目标/分离/事件时序）」当一个黑盒，
   **不能再分**。进一步分解需要引擎输出每拍的速度/子步状态（Change 1 的运动执行层），
   或者一个只读的引擎侧 mover 审计（当前事件流已够算 mover 端点，但不够算「目标 vs 分离后」）。
3. **`movers` 的球**不是独立读数（见 §1）；球相关结论只能用 `linear`/`current` 的同一球锚点，
   球锚点本身来自 viewer 对 pass/shot 的演绎，所以 **ballStaticFrac 的「引擎贡献」本次无法分离**。
   这是 B（球静止来源分解）的职责。
4. 贡献之间可能有交互（Catmull 改变路径后再叠 T1 的转角不等于两者之和），本表给的是**逐层序贯差**，
   不是可加的百分比。

## 7. 结论（只回答「viewer 是否值得先修」）

**不值得作为第一优先。** 针对当前判别量（`turn120`、`staticFrac`），viewer 全链的相对贡献是
**1.6% / 8.7% / 3.2%**（旧 turn120 / 条件 turn120 / staticFrac，绝对量 ≤0.1 / ≤0.08 / ≤0.008），
方向为「略降」；24×/6× 的缺口在引擎 mover 端点里已经存在。`ballStaticFrac` 本次不可分离（归 B）。
viewer 确实加了 ~1 圈/球员/窗的连续自转（并在加速度上 +0.7 m/s²），如果 Change 1 之后
`rotationTurns` 成为残余主判别量，再单独修 viewer 的 T1/Catmull 才是有依据的次序；现在不是。

本文件不提出 Change 1 方案（按 design D2）。下一步归口：B 的条件指标与球静止分解、
以及主 session 的 `notes/change0-verdict.md`。
