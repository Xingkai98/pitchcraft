# Design: 频率调优 + 90 分钟比赛 + 观看时长控制

## Context

P6 批次1 完成出界重开体系。用户验收反馈频率偏低，并澄清比赛时间机制：**比赛内容是真实比赛时长（90 分钟），播放可压缩到观看时长（5/10 分钟等），时间显示按比赛时钟 0-90，球员移动保持真实速度**。

## Goals / Non-Goals

**Goals:**
- 引擎默认 90 分钟比赛。
- 死球重开频率接近真实比赛（角球/界外球/头球显著提升）。
- 观看时长可调（5/10/20/45/90 分钟看完 90 分钟比赛）。
- 时间显示比赛时钟 `MM:SS / 90:00`。

**Non-Goals:**
- 中场休息/加时/点球大战。
- 真实比赛全部细节（越位、任意球、黄牌）——P6 批次2。
- 引擎物理帧率改造（球员移动仍真实速度，tick 不变）。

## Decisions

### D1: 频率目标（90 分钟基准，用户"看 5 分钟的基线"= 90 分钟事件在 5 分钟内浓缩）

| 指标 | 当前（90min） | 目标（90min） | 真实比赛 | 调整 |
|------|-------------|-------------|---------|------|
| 角球 | 1.4 | 6-9 | 10-13 | 扑出率 30→50%、越线 30→80% |
| 界外球 | 8.2 | 17-21 | 30-40 | 出界率 3-5→8-10%、边线 65% |
| 头球 | ~0.9 | 8-12 | 数十 | 随角球增多自然提升 |
| 进球 | 5.7 | 3-3.5 | ~2.5-3 | goal 率 15→9% |

**为什么**：角球/界外球/头球是 P6 批次1 新机制，用户希望"看得到"。界外球不上探到 30+（画面死球打断过密，观感权衡）。

### D2: 时间机制（用户澄清）

- **比赛内容时长** = `match_duration_seconds`（引擎默认 5400s = 90 分钟）。引擎固定 tick，球员每 tick 移动量按真实速度（m/s × 1s）——**不受观看时长影响**。
- **观看时长** `watchMinutes`（viewer 配置，默认 5）：播放基速 `baseSpeed = matchEnd / (watchMinutes × 60)`。game.step 的 `playTime += dt × baseSpeed × speeds[si]`。
- **时间显示** = 比赛时钟：`MM:SS / 90:00`（`playTime` 秒直接格式化；上半场 45:00、全场 90:00）。
- 倍速档位 `speeds=[1,2,4]` 在观看时长基速上再乘（选 5 分钟 + 2x = 2.5 分钟看完）。

**为什么**：比赛内容与播放解耦——引擎产完整 90 分钟事件流，viewer 决定播放快慢；时间显示始终是比赛时钟，用户感知"在看一场 90 分钟的比赛"。

### D3: 具体概率调整（engine/src/lib.rs）

| 位置 | 当前 | 调整 |
|------|------|------|
| `MatchConfig::default_()` | 2700 | 5400 |
| `emit_pass_highlight` 出界 roll | `out_roll < (3 + %3)` | `out_roll < (8 + %3)`（8-10%） |
| 出界边线/底线 | `%2 == 0` | `%100 < 65`（边线 65%） |
| `emit_shot_highlight` goal | `score_roll < 15` | `< 9` |
| 扑出（未扑住） | `caught < 70` | `< 50` |
| saved-rebound 越线 | `corner_roll < 30` | `< 80` |
| `emit_header_shot` goal | `score_roll < 10` | `< 8` |
| 头球扑出（未扑住） | `caught < 70` | `< 50` |
| 头球 saved-rebound 越线 | `corner_roll < 30` | `< 80` |

**为什么**：角球 = 扑出 × 越线，两项都提 → 角球 ~6-9；界外球 = 出界率 × 边线占比 → ~17-21；goal 率降抵消射门增多。

### D4: viewer 时间显示与观看时长

- `config.playback`：`watchMinutes: 5`、`watchChoices: [5,10,20,45,90]`、`speeds: [1,2,4]`。
- `game.js`：构造时算 `_baseSpeed = matchEnd / (watchMinutes×60)`；`step` 用 `dt × _baseSpeed × speeds[si]`；`cycleWatch()` 循环观看时长。
- `app.js`：MATCH_CONFIG 5400；时间显示 `formatMatchClock(playTime)`（`MM:SS / 90:00`）；加"观看时长"按钮（循环 5/10/20/45/90）；速度按钮显示倍速。
- 进度条拖动仍按比赛秒 seek（不变）。

**为什么**：playTime 即比赛秒，时间显示 = 比赛时钟直接格式化；观看时长只影响步进速率，不影响事件流与坐标。

## Risks / Trade-offs

- **[画面死球密度]**: 界外球 17-21 次/场 + 角球 6-9 次/场会频繁打断流畅感。缓解：界外球不上探 30+；死球段本身有准备期走位动画填充。
- **[测试耗时]**: 5400s 模拟翻倍（cargo test ~40s）。缓解：纯正确性测试改用短 cfg（2700），频率测试用 5400。
- **[e2e 步进]**: 全场步进 5400s = 324k 帧，耗时 ~2.6s（可接受）。

## Migration Plan

- 引擎：default 时长 + 概率参数。
- viewer：config/game/app 时间显示与观看时长。
- 测试：引擎频率断言更新 + 短 cfg 提速；viewer 时间格式测试；e2e 5400。

## Open Questions

- 角球/界外球的具体目标区间（6-9 / 17-21）——实现后按实际频率微调。
