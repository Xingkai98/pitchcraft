# Design: 比赛时长可调 + 精彩事件固定产出 + 跳过机制

## Context

P6 批次1 完成出界重开体系。用户验收反馈：频率偏低 + 比赛时间控制机制需要借鉴 FM 的跳过机制。

**用户澄清（2026-08-09 讨论定稿）**：
1. 比赛时长参数可调（5/10/45/90 分钟），调 5 分钟就是 5 分钟长的比赛（事件流覆盖 300s）。
2. **精彩事件固定产出**：不管比赛多长，每场固定数量的核心精彩事件（射门/进球/角球/界外球/头球/抢断，~40 个）。5 分钟比赛 = 精华集锦密集；90 分钟比赛 = 同样内容分布到更长时间轴，中间大量非精彩段。
3. **跳过机制**（借鉴 FM）：非精彩段（只有 beat 无高亮）在 viewer 播放时跳过——**快速播放（5x/10x，比赛时钟快跳）或直接跳过（切到下一个高亮），屏幕给选项**。非精彩 beat 保留（球员位置连贯），只是播放时跳过。
4. 时间显示统一 00:00 → 90:00 刻度；跳过的时间段时钟也跳。
5. 指标稳定：不同时长下看到相同精彩内容，比赛指标（进球/角球/界外球）不随时长漂移。

## Goals / Non-Goals

**Goals:**
- 比赛时长可调（5/10/45/90 分钟），事件流时间范围随参数变化。
- 核心精彩事件固定产出（每场 ~40：射门 12、角球 6、界外球 8、头球 8、抢断 6，实施可调）。
- 引擎产完整流（精彩 + 稀疏 beat 过渡），非精彩段不产高亮。
- viewer 跳过机制：间隙检测 + 快速播放/直接跳过选项。
- 时间显示 00:00 → 90:00，跳过段时钟跳。

**Non-Goals:**
- 中场休息/加时/点球大战。
- 真实比赛全部细节（越位、任意球、黄牌）——P6 批次2。
- 引擎物理帧率改造。

## Decisions

### D1: 比赛时长参数

- `match_duration_seconds` 可调（app 提供 5/10/45/90 分钟选项），引擎事件流时间范围随参数。
- 引擎默认 90 分钟（5400s）。

### D2: 精彩事件固定产出（槽位机制）

**替换概率门控为槽位驱动**：把比赛时间均匀划分为 `HIGHLIGHTS_PER_MATCH`（~40）个槽位，每个槽位必产一个高亮事件。高亮类型按固定比例分配，保证核心精彩事件数量稳定：

| 高亮类型 | 每场数量 | 分配方式 |
|---------|---------|---------|
| 射门（shot） | 12 | 槽位类型 roll：30% shot（含 goal/saved/off 分支） |
| 角球 | 6 | 射门扑出越线 + 解围出底线派生 |
| 界外球 | 8 | pass 出边线派生（出界率固定 ~8-10%） |
| 头球 | 8 | 角球争抢派生（头球射门/解围/摆渡） |
| 抢断（tackle） | 6 | 槽位类型 roll：15% tackle |
| 普通传球（pass） | 余下槽位 | 过渡用，不算精彩 |

**槽位间距** = `match_duration / HIGHLIGHTS_PER_MATCH`：
- 5 分钟（300s / 40）= 每 7.5s 一个高亮 → 密集集锦
- 90 分钟（5400s / 40）= 每 135s 一个高亮 → 中间大量非精彩段（viewer 跳过）

**实现**：现有 `roll_highlight`（hold_ticks >= hold_max 随机）改为**槽位驱动**——`hold_max` 不再随机 8-15 tick，而是按槽位间距固定（`match_duration / N` 换算 tick 数）。高亮类型 roll 保持，但 pass 出界率/射门 saved 越线率固定（保证派生事件稳定）。

### D3: 引擎产完整流（非精彩段稀疏 beat）

- 高亮事件之间：产稀疏 beat（球员按队形移动，球随 carrier 控球），保证球员位置连贯——viewer 跳过时球员不瞬移。
- 非精彩段不产高亮（槽位之间只有 beat）。
- 事件流天然携带时间戳：viewer 从事件 t 分布识别"高亮间隙"。

### D4: viewer 跳过机制

- **高亮事件识别**：shot / pass detail=corner|out_sideline|out_goal_line|clearance / tackle / 头球 = 精彩段；普通 pass + beat = 过渡。
- **间隙检测**：两个高亮事件之间的时间差 > 阈值（如 5s 比赛时间）→ 进入跳过模式。
- **跳过模式选项（屏幕 UI）**：
  - **快速播放**：非精彩段以 5x/10x 快进，比赛时钟快跳，到下一个高亮恢复正常。
  - **直接跳过**：非精彩段直接不播，playTime 跳到下一个高亮起点（球员位置靠 beat 锚点已连续，无瞬移）。
  - 选项切换按钮。
- 高亮段正常速度播放（按 1x 或用户倍速）。

### D5: 时间显示

- 统一显示比赛时钟 `MM:SS / 90:00`（playTime 即比赛秒，直接格式化）。
- 5 分钟比赛：playTime 从 0 走到 300，显示 00:00 → 05:00（不是 90:00！）。
  - **澄清**：时间显示 = 比赛内容时长刻度（matchEnd），不是固定 90:00。5 分钟比赛显示 0-05:00，90 分钟显示 0-90:00。
  - 用户原话"显示 0-90"指默认 90 分钟比赛；时长可调后刻度跟随 matchEnd。
- 跳过段时钟跳：快速播放时 playTime 快进（时钟快跳）；直接跳过时 playTime 瞬跳（时钟瞬跳）。

### D6: 播放基速

- `baseSpeed = matchEnd / (watchMinutes × 60)`（把整场压缩到观看时长）。
- 跳过机制在基速基础上叠加：非精彩段 × 5/10（快速播放）或直接跳。
- **与跳过机制的关系**：观看时长参数（5 分钟看完）与比赛时长参数（5 分钟比赛）解耦——
  - 比赛时长 = 引擎模拟的内容范围（match_duration_seconds）
  - 观看时长 = viewer 播放压缩目标（可选，跳过机制是另一种压缩手段）

## Risks / Trade-offs

- **[槽位机制改动大]**: roll_highlight 从概率门控改为槽位驱动，影响现有频率测试。缓解：保持高亮类型 roll 结构，只改 hold_max 计算 + 固定派生概率。
- **[5 分钟比赛过密]**: 40 个高亮塞 300s（每 7.5s 一个）可能突兀。缓解：高亮类型含普通 pass 过渡，实际"核心精彩"（射门/角球/头球/抢断）~26 个，节奏可接受。
- **[跳过误判]**: 普通 pass 也算高亮（可能误判为精彩）。缓解：高亮识别只看"核心精彩"（shot/corner/clearance/tackle/header），普通 pass 不算。

## Migration Plan

- 引擎：槽位机制（hold_max 固定 + 派生概率固定）+ 时长参数。
- viewer：时间显示跟随 matchEnd + 跳过机制（间隙检测 + 快速播放/跳过选项）。
- 测试：引擎频率断言（5 分钟 vs 90 分钟产出相同精彩事件数）+ viewer 跳过测试。

## Open Questions

- 核心精彩事件具体数量（~40 初定）——实施后按观感调。
- 跳过阈值（5s 比赛时间）——实施时调。
- 快速播放倍速（5x/10x）——实施时定。
