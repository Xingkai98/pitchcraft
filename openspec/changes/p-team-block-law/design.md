# Design: 球队块定律（p-team-block-law）

## D0. 目标与判据

**改什么**：`formation_target` 从「各自半场固定锚 + 旧/新式混合」换成 **数据拟合块定律**（单函数替换）。
**目标**：P38 形状判据（hd/spread/gap/fault）大面积转绿，同时守住 L1 统计门与 like-football 不退化。

判据（按序）：
1. L1 `cargo test --test realism --release -- --ignored` 9/9（**硬门**）；
2. P38 八条 ≥6/8 且 hd ∈ [23.385, 28.385]；
3. like-football 距离 ≤0.30（改前 0.542）；
4. ratchet 22 项无退化；P18 B4 仍通过；A1/A2 不因本 change 变差；
5. 轨迹图 + 单帧对比人工复核。

## D1. 证据（两条独立链，仓内可复现）

- **存量负结果**：P38 `findings-final.md` §4b（exp4b 指标全绿但画面无变化）、
  `defense-layers.md` §3（形状与事件两层耦合）、#19（单点扫描无可行区间）。
- **真实 tracking 拟合**（`research/2026-10-25-team-shape-law/fit-team-shape.mjs`；Metrica 2 场、
  非门将 10 人、逐帧、米制、控球代理分相位；114,448 队·帧）：
  控球方块心 `21.03+0.607·ball`、失球方 `12.21+0.631·ball`；纵深 q10–q90 25.40–26.02；
  宽度 max−min 37.62–41.93；横向重心斜率 0.317–0.332。与 `real-formation-laws.md` §2/§6 同口径同方向。

⚠ 两个数据集的口径不可混用（P37 教训）：本 change 的靶子用 **Metrica 真实参照**（P38 criteria-spec 的
`realReference`），like-football 的结构锚另为 SkillCorner 主口径——报告里分列。

## D2. 机制（公式即实现规格）

记：`d_own(p)` = p 离本方门线距离（home = x·105；away = (1−x)·105）；球同理；`rank` = 静态纵深排名（0..9）。
`span_q(nodes, d_ball)` / `width_m(nodes, d_ball)` = 7 节点（球位 7.5/22/36.5/52.5/68.5/83/97.5 m）线性插值。

```
phase_att = (己方 possession)
center_own = interpolate(21.03, 0.607) if att else (12.21, 0.631)          // 离本方门线
full_span  = span_q(att?SPAN_ATT:SPAN_DEF, d_ball) / 0.889                 // q10-q90 → 10 人铺满
x_own      = clamp(center_own - full_span/2 + rank·full_span/9, 1, 104)
x          = x_own/105              (home)      = 1 - x_own/105   (away)
cy         = 34 + 0.32·(球y_m − 34)
y          = cy + (base_y − 0.5)·68·(width_m/40.8) + iy      // iy = 继承的 FORM_INDIV 抖动
```

`0.889` 是 n=10 均匀铺满时 q10–q90 / full-span 的解析系数（线性插值，可复算）；
`40.8` = default_lineup 的 y 跨度（0.2..0.8）×68（可复算）。

## D4. L1 标定策略（**落地的硬前提**）

原型实测 L1 3 红：禁区内射门占比 0.738（带 [0.45,0.65]）、抢断 74.22/场（带 [24,50]）、
射正率 0.402（带 [0.28,0.39]）。机制归因：形状压到真实距离后，防守者-持球者距离系统性变近，
而 `select_defensive_action` / `shot_opportunity_features` 的概率常数是旧世界标定。

规则：
1. **只动概率/标定常数**，不动事件结构（与 C1–C4 的禁令一致）；
2. 一次只动 1–2 个，记录 config → L1 3 项 + P38 八条 + like-football；
3. 若出现「无连续可行区间」（#19 型），**如实记录负结果**并停止，不伪造绿；
4. 标定后的常数必须在 design/notes 里逐个带出处（实验记录文件）。

### D4.1 标定结果与残余风险（实验记录 `EXP1-CALIBRATION.md`）

结果：**L1 9/9**；P38 **7/8**（hd 23.691 ✅，latSd 3.886 ❌）；like-football **0.252**。
标定改动（全部概率/形状常数）：`BASE_DEF_TACKLE −0.92→−1.40`、`BASE_DEF_FOUL −0.22→−0.30`、
`BASE_SHOT_TENDENCY −4.0→−4.45`、`SHOT_PRESSURE_NEAR/SECOND 8/16→6/12`、`SHOT_DRIVE_MAX_TICKS 5→8`、
射门目标分布 `70/20/10→35/47/18`、禁区 saved `30→27`、纵深节点整体 +0.4m。

⚠ **两项缺陷（本 change 不合入的判据）**：

1. **主客不对称放大**：600 场冻结窗实测 **主 1.372 / 客 0.578 球/场，H/A = 2.372**（95% CI [2.092, 2.689]）；200 seed 侧效应 1.45/0.58。改前 1.415/1.332（H/A 1.063），真实参照约 1.53/1.22（≈1.25）。
   形状公式对主客镜像对称 ⇒ 根因应在事件层，但**未定位**；本次用"压总射门量"补偿。
   现有 L1 断言（`gh∈[0.85,1.60]`、`ga≥0.30`、`home_conv>away_conv`）对此**不敏感**——记为判据盲区，
   并作为本 change 的前置修复项（新开 ticket）。
2. **进球总量偏低**：600 场总进球 **1.950/场**（改前 2.747，真实约 2.75，−29%）；射门 14.79/场（带 [14,29] 下沿）、角球 3.80。属"少而近"的
   补偿式构成，不是机制解。

⇒ 决策项（用户）：**(a)** 先修主客不对称/进球总量再合入；**(b)** 或把"形状机制"与"事件层标定"
拆成两个 PR（前者只去掉 L1 标定、保留 P38 结构收益；后者单独论证）；**(c)** 或接受为实验分支不合并。

## D5. 与 latSd 的关系（明确边界）

本 change **不承诺**修 `latSd`（原型 3.219→3.992，仍远低于 7.015）。真实横向方差中
「个体游走」占 29–43%（`real-lateral-laws.md` §2.1），其机制来源是「无球目标调整层」
（report §5 的三层架构：分区触发 / 参考点收敛 / 单人追抢 / 角色横向档位），属独立 change。
本 change 的验收里 latSd **只要求不退化**。

## D6. 兼容与风险

- **协议**：`Mover` 结构/action 名不变；`formation_target` 签名不变；不新增事件类型。
- **测试**：`p5_formation_and_transition`（lib.rs:8426）、`p5_ball_side_shift`（8492）、
  `p5_press_up_and_gk_exempt`（8506）直接断言旧公式，需按本 change 重写并保留判据意图。
- **golden**：`MODEL_VERSION 9→10`，新建 `engine/tests/golden-v10/`，`realism.rs:1355` 加 10 分支。
- **spec**：`match-engine` 的「球相关队形目标」整体替换（本 change 的 delta）。
- **风险**：L1 标定可能无解（#19 型）；若如此，本 change 转为**负结果 + 机制分离建议**（保留实验证据）。
- **数据敏感**：Metrica 只有 2 场（样本限制见 `real-formation-laws.md` §9.1）；不声称人口推断。

## D9. 连续化/平滑尝试（追加）与方向结论

把 B4 离散档位改成连续函数（球位连续比例）后：track 0.70 + step 6.5 仍过 P38 8/8（latSd 7.501、
swarm 0.769）、L1 9/9、p53 11/11，但**轨迹图仍有大面积 90° 折返/锯齿**——球在传球/球权转换时瞬移，
任何球位函数都会让目标跳变。再加"球参考低通"（α=0.25/0.12，时间平滑）后纵向位移被压到 10m
（真实 14.35），画面仍为折线。

⇒ 结论：**目标层调参无法达到视觉验收**；根因是 1 Hz + 4m/拍限速 + 无速度/朝向状态（每拍方向可突变）。
下一步应立新 change 做**运动学层**（速度/朝向/加减速，repo SOTA 计划 C1），而不是继续在本 change 内调目标。
## D10. 运动学层原型（追加）与最终结论

在 D9 之后又试了 mover 运动学层（vel 状态 + 转角限制，worktree exp5）：P38 8/8、L1 9/9、p53 11/11、
H/A 1.325，但**第二次三裁判盲测一致把它评为最不像真实**（"长直蛛网/等步长随机游走"），
且新增门将位置硬不变量红与 like-football mix 退化。⇒ **1 Hz + 瞬时事件锚点架构下，
目标层/运动学层都无法通过视觉验收**。本 change 到此定格为"数值机制已验证、视觉不可交付"，
**不申请合入**；下一步需单独立 change 做事件/协议层（beat 频率或锚点/插值语义，C1 级）。
另记：P38 `latSd` 部分奖励抖动（平滑会掉 latSd），运动类改动应与视觉判据一起审，避免指标反向。

## D12. 门前射门优先（评审分支版本 v11）

**问题（探针实锤）**：候选 R12 在"禁区内、球门侧 8m 无人"的状态下，传球占比 **95.1%**（2774 传 / 143 射），
其中 45.2% 的传球最近防守者其实在**持球者身后 ≤4.5m**；传球方向平均**向前 −2.84m**（横向 47%、回传 45.5%）。
代码归因：出球档 `pressured` 只看"任意方向最近防守者 ≤4m"（把背后回追当贴身），加上射门推进 hazard 概率低、
4s 停滞强制出球，禁区内空位仍优先横传。

**改动（本分支，engine/src/lib.rs）**：
1. 新增 `nearest_goal_side_defender_m()`：只统计"持球者 → 球门 ±45° 锥内"的最近外场防守者；
   `pressured` 改用该距离 ⇒ 背后回追不再强制出球。
2. 新增"禁区内球门侧空位优先射门"分支：`!GK && goal_side_m >= 8m && dist_to_goal <= 14m && |y-0.5|*68 <= 12m`
   时按 `OPEN_BOX_SHOT_P` 概率直接进入射门流程（`EnterShotWindow` / `DriveThenShoot`），优先于停滞出球与推进掷定。
3. 射门转化校准（仅本分支）：进球/扑救桶 `(9,45)`（禁区内）/`(2,32)`（禁区弧）/`(1,14)`（远射）。

**v11 参数**：`OPEN_BOX_SHOT_P = 0.60`。
