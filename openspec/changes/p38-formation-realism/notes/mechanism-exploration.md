# P38 线 B：队形的**表示方式**——从"独立算每人"到"互相约束"

> 线 A 的结论：`DECOUPLE_LAG` 是一条死路（幅度/范围/形状全穷尽，天花板 5/7，被**横向**判据挡住）。
> 线 B 接着 #89 的选项 (d)：**先修横向**。
>
> 起点是一个结构性事实：**`formation_target(st, id)` 不读任何其他球员的位置**——
> 每个人的目标是独立算出来的。真实球队的队形是**互相约束**出来的
> （越位线、盯人、协防、对队友的补偿）。本文试的就是：把那个约束接上。

## 0. 结论速览

| # | 结论 | 证据 |
|---|---|---|
| 1 | **真实横向 = 个体行为，不是整队跟球** | 球 y 只解释 **17%** 的 y 方差；队重心也才 26% |
| 2 | 表面看「盯人」解释 85%，**是假象** | 最近**队友**也 0.73、盯人对象只有 30% 稳定、交叉相关峰值在 Δ=0 → 是**局部邻近**不是盯人 |
| 3 | **公共信号 + 个体增益 = 假个体性**（可证） | `duty` 机制 latSd 5.46 时 swarm **0.882**；`gated` latSd 5.68 时 swarm **0.355** |
| 4 | **判据组有个口径缺陷：引擎侧 latSd 被拼接灌水 6.5×** | `probe-latsd-caliber.mjs`：逐场 1.73m vs 拼接 11.26m |
| 5 | 该缺陷**奖励横向大改的 hack** | 动得越多场间偏移越大 → 虚高越多；线 B 一度被它骗过 |
| 6 | **修口径后没有方案过关**——横向能上去，但**铁轨只是转了 90°** | `visual/cmp-gated.png`；`pc2` 定量：真实 0.139 / 基线 0.032 / gated 0.167（靠"面积"才分开） |
| 7 | **缺口比"选哪个驱动"更根本**：引擎的横向自由度**受限于目标公式的形状** | 见 §6：只要 `ty` 是一个**标量目标的静态函数**，轨迹就退化成低维流形 |

**一句话**：横向的瓶颈不是"用哪个信号驱动"，而是**球员目标是"算出来的一个点"**——
真实的横向来自对**动态情境的持续响应**（球、对手、队友、球门），
而引擎每拍只把 `ty` 设成一个**由静态模板 + 一两个标量**决定的数。线 B 把能接的信号都接了一遍，
**没有一个能同时满足 latSd / swarm / 纵深 / 引擎门**；而且**视觉上都没有摆脱"低维轨道"**。

## 1. 前置测量：真实球员的 y 由什么驱动？

### 1.1 球和队重心都解释不了

`probe-lateral-drivers.mjs`（Metrica 2 场，全部非门将，n≈450k 帧·人）：

| 驱动 | R²（合并） |
|---|---|
| D2 **球 y**（引擎唯一用的项） | **0.167** |
| D4 局部球响应（按到球距离加权） | 0.241 |
| D3 **球队重心 y** | **0.262** |
| D5 最近对手 y | 0.849 |
| D2+D3+D5 | 0.849 |

**球位项最多解释 17% 的横向方差**——这直接解释了 exp7 为什么"方向对、力度不够"
（`findings-final.md` §8 把它归因于 `farness` 是二值量，**更根本的原因是它用的那个信号本身只值 17%**）。

**人均 y_sd = 14.0–14.5m**，而球员**个人 y 均值**的极差只有 17.6–18.7m——
说明球员不是"各自守一条带"，而是在**大片重叠的区域**里活动。

### 1.2 ⚠️ "盯人 0.85" 是假象（反证条）

D5 的 0.849 看起来像决定性的答案。但"最近对手"是**用含 y 的 2D 距离选出来的**——
选出来那人天然就在我旁边。`probe-marking-confound.mjs` 三条反证：

| 检验 | 结果 | 判读 |
|---|---|---|
| **T1 换成最近队友** | R² = **0.725–0.744** | 与对手的 0.836 只差 0.1 → 高 R² 主要来自"两人靠近" |
| **T2 盯人对象窗口内定死** | R² = 0.833–0.838 | 没塌——但这是"对手整块也在动"的效果，不能区分因果 |
| **T3 逐帧最近对手的身份稳定占比** | **30.1–32.7%** | **真盯人应长时间同一人**；只有 30% 说明对象在快速漂移 |
| **T4 交叉相关峰值位置** | **Δ=0**，且 Δ<0 与 Δ>0 **对称** | 真"跟随"应峰值在 Δ>0（我滞后于他）；**对称=同步，不是跟随** |

**判定**：真实的横向结构是**局部邻域在 y 上同进退**（两队都一样），
**不是一对一的盯人**。这个区分很重要——它意味着**照抄"盯最近对手"实现不出真实结构**
（引擎里打上 `mark` 机制也只是复现那个假象）。

## 2. 三个机制（+ 两个衍生），一个判据组

实现在 `sweep-mechanisms.mjs`，每个机制只替换 `formation_target` 里的一行 `let ty = ...`：

| 机制 | 表达式 | 信号性质 |
|---|---|---|
| `duty` | `ty = base.1 + (ball.1-0.5)·gain`，gain 按边中角色分化 | **公共**（同相位） |
| `local` | `ty = (1-b)·base.1 + b·(半径 R 内队友的 y 均值)` | **个体**（邻居逐人不同） |
| `mark` | `ty = (1-b)·base.1 + b·(最近对手 y)` | 个体（对手逐人不同） |
| `gated` | `ty = base.1 + (ball.1-0.5)·gain(x 距离)`，球在 x 上越近增益越大 | **个体化相位**（响应时刻不同） |
| `blend` | `(1-b)·公共球侧 + b·局部邻域` | 混合 |

判据仍是 `notes/criteria/` 的成组否决（纵深 / 紧凑 / 重心间距 / latSd / swarm / fault / midBack）。

**前置修复（必须，不是变量）**：`patches/fix-tackle-duplicate-mover.patch`。
横向机制让队友靠得更近 → `emit_tackle_highlight_impl` 的"推开队友"分支频繁触发 →
同 id 两条 mover → `createGame` 抛错。实测 `local s=0.96` **10 个种子崩 5 个**，
不修的话每个强度点都在"少一半种子"上算均值，跨行不可比。
该守卫**单独跑在干净 main 上行为中性**（`duty 0.0` 复现基线射门 7.2/场，一致）。

## 3. 核心结果：公共信号 vs 个体信号

10 种子 × 5400s，**逐场算再平均**（口径见 §4）。同强度点对比：

| 配置 | 纵深 | latSd | **swarm** | 普通射门/场 | 判据组 |
|---|---|---|---|---|---|
| 真实 | 25.9 | **10.5** | **0.671** | 18 | 7/7 |
| 干净基线 | 40.32 | 0.55 | 0.488 | 7.2 | 1/7 |
| **`duty` s=0.6**（公共） | 40.87 | **5.46** | **0.882** ❌ | 5.9 | 1/7 |
| **`gated` s=1.1**（相位个体化） | 40.70 | **5.68** | **0.355** ✅ | 7.7 | 1/7 |
| `gated` s=1.4 | 39.66 | **9.27** | **0.284** ✅ | 4.1 | 1/7 |
| `local` s=1.0 R=12 | 40.98 | 4.09 | 0.386 ✅ | 14.2 | 2/7 |
| `blend` s=0.6 R=12 | 40.39 | 2.49 | 0.697 | 5.6 | 1/7 |

**这是本轮最重要的因果结果**：
`duty` 与 `gated` 在**几乎相同的 latSd**（5.46 vs 5.68）下，swarm 差 **0.53**（0.882 vs 0.355）。
差别只在**每个人的响应是否同相位**。这就把 exp5 的失败从"现象"变成了"机制"：

> **swarm 的根源是公共信号，不是增益大小。**
> 只要 `y_i = base_i + g_i·s(t)`（s 为同一路公共信号），corr(y_i,y_j) 就趋向 1，
> **与 g_i 是否各不相同无关**。exp5 的 0.95 和 `duty` 的 0.88 是同一件事。

**引擎里唯一天然"每人不同"的信号，是他自己邻居的位置**（不同的人邻居不同）——
这是 `local` / `gated` 能压低 swarm 的原因。

### 3.1 为什么判据组还是不过：横向靠"拧"，不是靠"行为"

`gated s=1.4` 的 latSd 9.27（真实 10.5）而 swarm 0.284——**两个横向判据都过了**，
但纵深仍是 39.66（靶子 25.9）。**横向与纵深仍然是两个独立的轴**（线 A 结论的重申），
而**没有任何一个机制同时动两者**。

试过的组合（`sweep-combo.mjs`，exp4b 等间距块 + `local`）：

| 配置 | 纵深 | latSd | swarm | 射门 | 判据组 |
|---|---|---|---|---|---|
| exp4b + local s=0.7 R=12 | **27.01** ✅ | 0.62 | 0.549 | 4.2 | 4/7 |
| exp4b + local s=0.96 R=12 | **27.21** ✅ | 0.76 | 0.595 | 1.6 | 6/7 |
| exp4b + local s=0.96 R=15 | 26.95 ✅ | 1.55 | 0.652 | 0.7 ❌ | 6/7 |

**纵深修好了，横向又没了**——因为 exp4b 把 `ty` 换成了静态模板（`ty = base_y`），
`local` 的偏置被压到很小。而 `local` 强度一上去，射门就塌（0.7/场）。
**两个机制通过"队友密度"耦合**（压缩后邻居更多 → local 的参考值更平滑），不是正交的。

## 4. ⚠️ 方法学：判据组的 `latSd` 口径有缺陷（引擎侧被灌水 6.5×）

**这是线 B 过程中发现的，重要性不低于机制结论本身。**

`render-trajectories.mjs`（单场 seed 42）对某配置报横向 sd **0.37m**，
而 `p38-eval.mjs` 对**同一个 wasm** 报 **11.26m**。差 30 倍。

**根因**：评测器把多个种子的帧 **concat 成一个序列**再算 sd：

```js
const all = [];
for (const seed of seeds) all.push(...r.frames);   // ← 多场拼在一起
const seg = all.filter((f) => f.t >= 1800 && f.t <= 1920);
latSd.push(sd(seg.map(...)));                       // ← 跨场 sd
```

不同场次的球员 y **均值不同**（各自的战术相位、初始条件），拼接后这些**场间偏移
全部计入 sd** → 方差被抬高。`probe-latsd-caliber.mjs` 实测：

```
逐场算再平均（正确口径）  latSd = 1.73 m
拼接多场再算（评测器现状）latSd = 11.26 m
虚高倍数 = 6.50×
```

**两个后果**：

1. **口径分叉**：真实侧（`eval-criteria.mjs --real`）本来就是**逐场算再平均**
   （real-game1 10.81 / real-game2 10.22 → 10.515）。引擎侧拼接 = 口径分叉，
   与 P36「口径分叉 = 数字不可比」是同一个错误，只是发生在**时间轴**上。
2. **方向是反的**：动得越多的配置，场间偏移越大，**虚高越多**——
   这个缺陷**奖励横向大改的 hack**，与判据组"抓 hack"的初衷相反。

线 B 一度被它骗过：`local R=12` 拼接口径报 latSd 18.61（"突破！"），
逐场口径只有 **1.2–4.1**。`swarm` 同样受影响（基线 0.328 → 0.488）。

**已修**：`p38-eval.mjs` 改为 `evaluateByMatch`（逐场算再平均）。
真实侧数字**不变**（10.81 / 10.22），验证修复没有改靶子。

**给 #91 的建议**：`eval-criteria.mjs` 与 `criteria-spec.json` 需要按此重标；
`criteria-spec.json` 的记录值 0.671 本身取自逐场平均（正确），
但**引擎侧必须同样逐场**，否则对照无意义。

## 5. ⚠️ 看图：铁轨转了 90°，数字看不出来

`visual/cmp-gated.png`（左=真实，右=`gated s=1.1`）：

- **左（真实）**：满场交织的**面**。
- **右（gated）**：**竖直的细线**——球员在 x 上几乎不动，只在 y 上来回。

**latSd 从 0.55 涨到 5.68（10 倍）**，但病理**没变**，只是从"水平铁轨"变成"竖直铁轨"。
`findings-final.md` §4b 的教训（"指标全绿≠像足球"）在这里**第二次**应验——
而且这次是 latSd 这个**专门为横向立的判据**被骗过。

### 5.1 把"铁轨"变成可进 CI 的数：`pc2`

`probe-rail-ness.mjs`：对每人 120s 的 (x,y) 点云做 PCA，
取**第二主成分的方差占比** `pc2`（0 = 一条线，无论横竖；0.5 = 各向同性）。

| 来源 | pc2 | 主轴σ | 次轴σ | **面积** |
|---|---|---|---|---|
| 真实（Metrica ×2） | 0.139 | 16.5m | 6.4m | **331 m²** |
| 干净基线 | 0.032 | 3.3m | 0.5m | **6 m²** |
| `gated s=1.1` | 0.167 | 6.6m | 2.5m | **60 m²** |

⚠️ **注意 `pc2` 本身也不够**：`gated` 的 0.167 **高于**真实的 0.139——
因为 `pc2` 是**比值**，竖直细线（x 小 y 大）的比值反而好看。
**真正分开三者的是"次轴 σ"和"面积"**：真实 331 m² / gated 60 m² / 基线 6 m²。

**给 #91 的候选判据**（P38 至此一共给出了三条互补的横向判据）：

| 判据 | 抓什么 | 抓不住什么 |
|---|---|---|
| `latSd` ≥ 7 | 横向幅度 | 竖直铁轨（latSd 高但 x 不动） |
| `swarm` ≤ 0.891 | 整队同步（公共信号） | 纯个体但仍是轨道 |
| **`area`（点云椭圆面积）≥ ~150 m²** | **二维展开程度** | —— |

**三条一起**才关得住：`duty` 被 swarm 挡、`gated` 被 area 挡、基线被 latSd 挡。

## 6. 为什么都不成立：瓶颈在"目标的形状"，不在"信号的来源"

把五个机制放在同一张图（`out/mechanisms.svg`，`plot-mechanisms.mjs`）：
横轴 latSd、纵轴 swarm。**所有点都挤在一条自左下到右上的带里**——
想要横向幅度就得要 swarm。`gated` 把点**从带子上方挪到了下方**（同 latSd 下 swarm 更低），
这是真实的进步；但**带的斜率没有改变**，也就是说：

> **在 `formation_target` 这个形状里，横向幅度与整队同步是同一个自由度的两面。**

`probe-swarm-source.mjs` 给了形式化的解释（P1：第一主成分占总方差的比例——
公共信号 = 秩 1 结构）：

| 配置 | latSd | swarm | **PC1 占比** |
|---|---|---|---|
| 干净基线 | 0.87 | 0.329 | **35.9%** |

基线在"横向几乎不动"时 PC1 已占 36%——**大部分横向方差本来就是公共的**。

**结论（对 #89 的机制含义）**：只要 `ty` 仍然是
「静态模板 + 若干个**标量**（球 y、队友均值、对手 y）的确定性函数」，
球员的 y 就被约束在**低维流形**上——**轨迹必然是轨道**，铁轨只是方向可以选。

真实的横向来自**对动态情境的持续响应**，且这个响应在每个球员身上
**由不同的局部情境定义**（谁在我旁边、球在我哪一侧、我盯谁、我往哪跑）。
要真正修好，需要的不是换一个更聪明的标量，而是：

**把横向目标从一个"算出来的点"改成一个"由局部相互作用定义的关系"**——
例如「保持与最近队友的 y 距离」「保持与最近对手的 y 距离在 [a,b]」，
即**约束**而非**坐标**。这超出本轮（以及 `formation_target` 的签名）的范围，
留给 #89 的设计。
