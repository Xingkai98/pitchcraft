# P38 #91：验收判据（成组否决 + 变异自证）

## 这是什么

**判断一次队形改动是「真修复」还是「拟合数字」的可执行判据组。**

动机：P38 探索中做了 6 个改动，**每一个都能让部分指标变好看**，
其中 exp4b（等间距重排）在**四条指标上全部达标**——却是纯 hack。
单条判据会被"买"（exp1 的纵深被挡但 swarm/midBack 达标），所以判据必须**成组否决**。

## 射门口径（阶段 1 新增，2026-09-20）

### 为什么要加这一条

上一轮 agent 发现的缺口：判据组 7 条里**没有射门相关的**。实测某配置
（`exp4b + local s=0.96 R=12`）判据组给 **6/7**，而它场均只有 **1.6 脚普通射门**
（真实 16.5、引擎 L1 门要求 6–11）。**判据组会为一个几乎不射门的配置开绿灯。**

### 口径（三条，缺一条就错）

1. **只数普通射门**：`type === 'shot' && detail !== 'header'`。
   引擎侧头球走 `emit_header_shot`（角球 battle 派生），节奏与普通射门无关；
   混在一起会让"角球多"伪装成"射门多"。
   真实 Metrica 的 `Subtype` 里头球有**四种写法**（`HEAD-OFF TARGET-OUT` /
   `HEAD-ON TARGET-SAVED` / `HEAD-WOODWORK-OUT` / `OFF TARGET-HEAD-OUT`）——
   判定用**子串 `HEAD`**，别用前缀。`BLOCKED` 计入（封堵仍是一次起脚）。
2. **逐场算再平均**：不是"总射门 ÷ 总时长"。与 `latSd` 同一条口径教训
   （拼接会把场间差异算进方差；射门同理，场长不齐时两者不等价）。
3. **按 90 分钟归一**：引擎一场恒为 `ENGINE_DURATION_SEC=5400s`，
   而 Metrica 两场的**帧跨度是 5800s / 5646s**。射门是速率量——不归一化就是拿
   96.7 分钟的比赛去比 90 分钟的。实测：原始计数 18 + 17 → 不归一化均值 17.5，
   归一化后 16.51（差 5.7% 口径分叉）。真实侧按帧跨度归一，引擎侧按 `game.matchEnd`。

真实侧数字由 `real-shots.mjs` 从 Metrica `RawEventsData.csv` 提炼成
`real-shots.json` 入库（CSV 本身在 `.scratch/tracking-data/`、gitignored，
不让评测器依赖它；JSON 里记了每份 CSV 的 sha256 做溯源）。

### ★ 为什么是「单边下界」而不是「真实值 ± 容差」

**这是本判据唯一一处不能用真实值标定的地方，理由必须留档。**

真实侧普通射门 **16.51/场**，引擎自己 L1 门断言的却是 **6–11/场**。
这不是引擎写错了——**引擎没有二次进攻链**（篮板 / 被扑后的补射 / 被封堵后二次起脚），
为了保住进球数把命中率调高了，射门数因此**设计上**就低于真实。

若判据去追真实值（16.51 ± 容差），它会**拒绝引擎全部的合法配置**——包括干净基线
（7.2）。判据永远为红 = 失去区分力。这与 P37「口径分叉 = 数字不可比」是同类错误，
但方向相反：**这次是拿真实值去要求一个架构上给不出该值的东西**。

上界同样没有锚点（真实 16.5 在引擎里不可达，引擎合法簇上沿也不该被判"太多"），
故只保留下界。语义明确：

> **挡"射门塌到地板"，不承诺射门体量向真实收敛。**

下界取 **5.5**，锚在**引擎 L1 门的预注册下沿 6.0 − 0.5 余量**
（`engine/tests/realism.rs` 的 `assert!((6.0..=11.0)...)`），**不是**从本表反推的
（反推 = 对着样本调参）。实测分离度：

| | 值 |
|---|---|
| 塌缩簇最高 | **4.2**（`exp4b+local s=0.7`） |
| 5.5（下界） | — |
| 合法簇最低 | **5.9**（`exp9-duty s=0.6`） |

⚠️ **这个余量是窄的**（离塌缩簇 1.3、离合法簇 0.4）——射门这条判据的**判别力弱于
几何五条**。它是"地板哨兵"，不是"拟合度判据"。要真收敛须先给引擎补二次进攻链
（#89 之后的量级）。

### ⚠️ 诚实结论：这条判据**大部分与几何判据重叠**

跨 16 个配置算相关（`shotsReg` vs 各量）：

| 量 | r | 读法 |
|---|---|---|
| 纵深 hd | **+0.836** | 压纵深 → 射门崩，这是 §4 那条已知耦合的**再确认** |
| 紧凑度 spread | +0.791 | 同上 |
| 断层 fault | +0.771 | 同上 |
| **横向 latSd** | **+0.385** | **不冗余**——两者测的不是一件事 |
| swarm | +0.055 | 无关 |

**没有一条配置是"只被射门挡住"的**（`latSd` 挡下全部 16 个）。所以：

- 射门判据**不是**新的必要拦截者——把它删掉，16 个变体仍然全被挡。
- 它的价值在**两处**：
  1. **把"几乎不射门"从"靠横向代理推断"变成"有一条明说"**。
     exp4b 族过不了 latSd ≠ 说明了它不射门；现在这一条直接命名了病灶。
  2. **它在 exp4b 上是唯一一条越过几何网的**：exp4b 单独（`exp4b-alone+guard`）
     的纵深 **26.50 ✅ 落在带内**、紧凑 15.52 ✅、重心距 8.03 ✅、断层 3.96 ✅、
     各线 1.03 ✅——**五条几何判据全绿**，只有射门（0.5）和横向/整体性拦下它。
     即：**几何修好了但射门没了**这种状态，是射门判据在说话。
- 它对**未来的 #89 方案**是必需的护栏：若某机制走一条"压纵深同时保住横向"的路
  （正是阶段 2 要试的），几何判据可能全绿而射门塌——那时它是最后一道。

**不要**因为"与 hd 高相关"就删它：相关是在**当前这 16 个配置**上测的，
它们恰恰都是"压纵深就崩射门"的同一族。一个真正的好机制应当**打破**这个相关
（纵深降、射门不降）——判据组存在的意义就是等到那一天。

## 怎么用

```bash
# 0. 首次/换数据源：从 Metrica 事件表提炼真实射门（一次性，产出 real-shots.json）
node real-shots.mjs

# 1. 全量评测（会反复改引擎源码与 wasm，跑完自动还原到干净 main）
node drive-criteria.mjs

# 2. 标定阈值 + 变异自证 + 逐条独有贡献（读 table.json + fixtures/）
node calibrate.mjs

# 3. 对**当前** wasm 核对（报告期，不阻塞；CI 友好，~12s）
node check-criteria.mjs
```

## 口径要求（否则数字不可比）

- **wasm 必须从 main 源码重建**并记 sha256（本轮出过两次事故）。
  干净 main = `901da77b`。
- **种子集 10 个**（`seeds.mjs` 的 `CRITERIA_SEEDS` = `BENCHMARK_SEEDS` 5 个 + 5 个扩容）。
  **为什么必须扩容**：射门是计数统计量，5 种子上基线普通射门 5–9/场、单点 sem≈0.7；
  而判据要区分的差异量级只有 1–2 球/场（exp8 单独 7.9→9.6）。
  **3 种子时 sem≈0.9——判据就是噪声判据。** 10 种子 sem≈0.5。
- **崩溃的种子如实报出**（`crashedSeeds`）：队形压缩会触发已知的
  `beat mover id duplicate`（`fix-tackle-duplicate-mover` 修的就是它）。
  评测器不再让脚本死掉，也不静默丢掉崩溃场——**崩溃率 >0 直接判该配置不可用**
  （`shotsReg → NaN`）。锚在**可用性**，不是拟合度。
- 真实侧用 Metrica 2 场（靶子已按 #88 定为 25–26m 全点口径）
- 客队镜像、y 轴用 `PITCH_WIDTH_M`
