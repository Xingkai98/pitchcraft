## A1. 两份设计是不是同一类东西？——**成立：是，且类边界画错了**

### 主张

任务书怀疑「本质都是换种方式给 10 个人算 x 目标」。逐一核对两份设计的子方案：

| 设计 | 子方案 | 状态变量（自称） | 实际机制 |
|---|---|---|---|
| 甲 1 | 越位线 + 对偶盯人 | 对手位置 | **越位锚定** |
| 甲 2 | 球锚定块 | 球位置 | **次序分档（rank）** |
| 甲 3 | 覆盖链 | 队友间距 | **次序分档（rank）** |
| 乙 A | 深度链约束 | 队友位置 | **次序分档（rank）** |
| 乙 B | 越位线锚定 | 对手位置 | **越位锚定** |
| 乙 C | 块级弹性 | 全队整体 | **仿射平移** |

**6 个子方案收敛到 3 个机制，其中 2 个（越位锚定、次序分档）被两份设计各提一次。**
「独立设计、互不知情、结论一致」在本题上**不是交叉验证**——是用两套词汇描述同两个想法。

### 证据

- 两份设计都从**同一条证据**推出越位机制：甲 `probe11` 的偏回归（增量 R² 0.193）、
  乙 `probeE/probeH` 的偏解释力（0.201）+ 滞后交叉相关（r=0.43）。**同一个测量，同一个推论。**
- 两份设计都把「次序分档」当核心修补：甲的 `rank_schedule(id)`、乙的 `depth_order + chain`。

### 但真正的错误是类边界

两份设计都把世界切成「改目标公式（无效） vs 引入相互作用（有效）」。
甲的 §3 根因表把 E（clamp）列为「三条路线都顺手消掉的副产物」，乙的 §4.3 预判「如果甲也走改
`formation_target` 公式，断层搬家对甲同样适用」。

**这个类边界是错的**：次序分档（rank）**就是一个纯目标公式**——`tx = f(lineup[静态], ball_pos)`，
不读任何其他球员的实时位置，完全落在两份设计认定「无效」的那一类里。
而它**消灭了断层**（§2）。所以「改目标公式不行」不是一条机制律，是一次**归纳过早**。

## A2. 「断层只会搬家」是真相还是共享的思维定势？——**推翻**

### 两份共享的主张

- 甲 §2.4：「19.2m 的断层没有被消除，它从 4→5 搬到了 8→9」
- 乙 §1.3：「**任何**『目标公式』方案都修不掉断层，只会让它搬家」（标题即此断言）

### 反例（实测）

我实现了**等间距次序目标**——两份设计共同内核的最小实现：

```rust
// 0. 每帧按模板纵深给本队 10 名外场排 0..9 档（静态 lineup，不读他人实时位置）
let r = depth_rank_of(st, id) as f64 / 9.0;
// 1. 块中心随球平移（甲的 BALL_ANCHOR / 乙的 g=0.59）
let centre = (0.165 + 0.59 * ball_own).clamp(0.12, 0.82);
// 2. 块内 9 个间距等分
let rear = (centre - 0.32 * 0.5).clamp(0.04, 0.86);
let tx = rear + 0.32 * r;          // ← 这一行就是两份设计说"不行"的东西
```

实测（5 种子 × 6 窗 = 30 窗，wasm `9f00ab51`）：

```
相邻次序间距（米）
真实 Metrica   2.9  3.0  3.3  4.1  3.2  3.4  3.5  5.2  3.9   断层  5.2m
基线 901da77b  4.1  0.1  2.3 14.1  0.3  1.8  2.0 19.2  3.0   断层 19.2m
等间距次序块   3.7  3.8  3.7  3.7  3.7  4.0  4.1  3.6  3.7   断层  4.1m  ← 优于真实
```

四项采用指标同时落位：

| 指标 | 真实 Metrica | 基线 | 等间距次序块 |
|---|---|---|---|
| 纵深（主） | 25.94 | 40.40 | **27.32** |
| 紧凑度 | 15.24 | 18.65 | **15.72** |
| 重心间距 | 8.32 | 23.53 | **7.84** |
| 宽度 | 39.58 | 40.85 | **40.85** |

**断层没有搬家，它消失了。** 而且这是「四项全绿 + 结构绿」——比两份设计举的任何 hack 反例
都更强的「看起来成功」。

### 判定

**「任何目标公式方案都修不掉断层、只会让它搬家」被推翻。**

两份设计里**为真的**是更窄的一条：**模板的仿射变换保留线结构**。
平移/缩放/按球位插值都是仿射映射，仿射映射保持相对间距比——所以断层必然搬家。
**这是同义反复，不是关于「目标公式」的定律。**

两份设计各自的实验都只覆盖仿射：
- 甲 §2.4：模板整体压缩（缩放）
- 乙 `probeJ`：M1「块平移 g=0.59 + 固定块深」、M2「M1 + 越位锚定」（平移 + 固定相对形状）

**没有一份试过非仿射的（rank / 重排）目标公式。** 这就是**同一盲区被踩两次**的实证：
两份设计的「独立收敛」收敛在**同一个未检验的假设**上。

## A3. 实现它们会打破什么？——**两份都低估到致命**

### A3.1 甲 1 / 乙 B（越位锚定）：招牌机制

甲的 §7 把「控制球位后防线↔对方锋线的偏相关」定为**结论性的判别量**，并写明
「若第 1 行的偏相关修不上去……甲 1 应当被否」。

我实现了甲 1 的 `drive` 形态（后 4 人目标高度按越位线牵引，增益 1.0）：

| | 基线引擎 | 甲 1 drive | 真实 Metrica（我复算） |
|---|---|---|---|
| M0 后4 ~ 球位 R² | 0.766–0.824 | 0.421–0.463 | 0.742 |
| M1 增量 R² | **0.021–0.112** | **0.370–0.415** | **0.135** |
| M1 β_球 | 2.2–17.4 | **2.5–3.2** | 14.8 |

**判别量通过了**——增量 R² 从 0.02–0.11 抬到 0.37–0.42，甚至**超过**真实侧（0.135）。
但同一个变体在引擎自己的门上：

```
l1_fouls_and_cards        FAIL  每场犯规 39.12 ∉ [16,30]
l1_shot_result_distributions FAIL  普通射门/场 12.86 ∉ [6,11]
l1_tackle_dilution_and_slot_mix FAIL  shot/tackle 0.451 ∉ [0.5,1.5]
l3_shot_ratios            FAIL  射正率 0.397 ∉ [0.28,0.39]
l1_home_away_goal_asymmetry FAIL 主队进球/场 1.032 ∉ [0.38,0.75]
```

**四条 L1 + 一条 L3 门同时破。**

更深一层：**这个判别量是不可证伪的**。任何让 `tx` 变成对方位置之强函数的实现，都会让偏相关上升——
R² 是构造保证的，不是正确性证据。甲把它当「结论性判别量」，等于把一个**恒真的测试**当验收门。

### A3.2 乙 B（越位锚定）：在引擎上是**空操作**

乙 B 的核心论据是（§B.2）：

> 「真实的越位余量中位数只有 +1.5m……引擎的中位数是 +14.6m……**引擎的锋线活在一个没有越位的世界里**」

我按同口径（攻方最前者 − 对方外场第 2 深者，沿进攻方向带符号）实测：

| | 真实 Metrica | 基线引擎 `901da77b` |
|---|---|---|
| 均值 | −1.62m | **−11.33m** |
| 中位 | −1.48m | **−12.36m** |
| p10 / p90 | −8.14 / +3.77 | −15.67 / −4.80 |
| **越过越位线（余量 > 0）的帧占比** | **31.7%** | **3.6%** |

**量级对得上（真实 |1.5|、引擎 |12.4|），但符号是反的**：
引擎的锋线不是「越位」，是**系统性地落在越位线之后 12m**。

后果是决定性的：**乙 B 的机制是「上界」（`tx.min(offside_line − margin)`），而引擎只有 3.6%
的帧会让上界绑定**。实测该变体：

```
事件流哈希   基线 b76cac97 41f691c6 f0b62023 c1784670 4ea58f73
             乙B  b76cac97 41f691c6 f0b62023 3340e438 23286666   ← 前 3 个种子逐字节相同
四项指标     与基线逐位相同（到 2 位小数）
六条结构判据 与基线逐位相同（断层 19.2 / 中场后防比 0.79 / 后防 y-sd 0.6 / 跨度极差 10.0 …）
```

**在任何验收会使用的分辨率下，乙 B 是一个 no-op。**
它声称「越位锚定把重心间距从 21.4 修到 6.6m」——那个数字必然来自它自己的块模型
（§B.3 的表是「块模型 vs 块模型 + 锚定」），**不是在这个引擎上测的**。

### A3.4 机制定位：不是调参错误，是一条**前沿**

我扫了块跨度（band）：

| band | 纵深 | 断层 | 射门/场 | 抢断/场 | 犯规/场 |
|---|---|---|---|---|---|
| 0.32 | **27.3** | **4.1** | **1.80** | 4.80 | 16.40 |
| 0.36 | 30.6 | 4.7 | 4.00 | 3.00 | 14.40 |
| 0.40 | 33.1 | 5.0 | 4.40 | 2.60 | 9.60 |
| 0.44 | 35.1 | 5.4 | 6.80 | 2.80 | 7.00 |
| 0.48 | 37.9 | 6.0 | 8.80 | 2.00 | 4.20 |
| 0.50 | **40.4** | — | **15.80** | — | — |

**纵深与射门在同一条单调前沿上**：纵深修到真实（27m）时射门只有 1.8/场；
射门回到可接受（≥6）时纵深又退回 35m+。**没有任何 band 同时满足两者。**

机制（可测，已测）：等间距块把**两队**用**同一个球位公式**摆在同一条带上，
于是「carrier 到最近防守者」从**争夺出来的量**变成**球位置的确定函数**：

| 进攻三区最近防守者 | 基线 | 等间距块 |
|---|---|---|
| 中位 | 7.6m | **5.5m** |
| p10 | 3.5m | **0.0m**（贴脸） |
| <8m 占比 | 50.6% | **92.0%** |
| <2m 占比 | 7.1% | **11.1%** |

同时 carrier 反而**更容易**推进到禁区（距门 <25m 的带球拍占比 9.7% → **38.2%**，
<16.5m 0.76% → **14.5%**）。即：**球更容易进危险区，但射门生成被防守几何掐死**——
`space_available = 0.65*space(最近) + 0.35*space(第二)`，最近防守者 ≤2m 时该项为 0，
而 <2m 的帧翻倍。**射门 hazard 被自己的空间因子关掉了。**

> **未完全归因**：我没有逐帧分解 hazard 五因子，上述因果链是**测到的相关**加代码阅读的推断。
> 但「前沿单调」这一条不依赖归因——它本身就是结论：**没有可用的工作点。**

## A4. 横向（y）不碰的代价 —— **成立（对两份）**

### 主张与实测

两份设计都承认没碰 y（甲 §8 未列、乙 §4.2 #8 自陈「最大空缺」）。
现状（基线 `901da77b`，实测）：

| 结构量 | 真实 | 基线 | 差距 |
|---|---|---|---|
| 后防横向移动（y-sd） | **14.7m** | **0.6m** | **24 倍** |
| 后防纵向移动（x-sd） | 19.7m | — | — |

### 我做了两份设计都没做的实验

把 `ty` 从 `base.1 + 0.06*(ball.1-0.5)*0.6`（构造上最大位移 ≈1.2m）改成
`base.1 + K*(ball.1-0.5)`，扫 K：

| K | 后防 y-sd | 四项头条 | 九道引擎门 |
|---|---|---|---|
| 0.35 | **3.7m** | 纵深 40.02 / 紧凑 18.54 / 重心距 23.61 / 宽度 40.74 | **9/9 全绿** |
| 0.40 | 3.9m | 纵深 40.61 / 重心距 22.95 / 宽度 40.80 | — |
| 0.75 | 9.1m | — | **3 门破**（射门 5.12∉[6,11]、shot/tackle 0.191、禁区进球占比 0.694） |

**三个结论，都是两份设计没说的：**

1. **横向也在这条前沿上**——能安全拿到的只有 3.7m（真实的 **25%**），
   再往上就破射门门。**「不碰 y」和「碰 y」之间没有免费午餐**。
2. **引擎自己的门拦不住横向改动**：K=0.35 把后防 y-sd 抬了 **6 倍**（0.6 → 3.7m）
   而 **9/9 门全绿**。P38 已有的结构判据（断层/移动比/块跨度）里，
   只有 `structural-check.mjs` 的 S3 看 y-sd，而它**不在门的集合里**。
3. **纵深修好 ≠ 场面像真实足球**。24 倍是当前**最大的单项差距**（纵深只有 1.56 倍）。
   我的判断：横向权重**不低于**纵深——真实球队被一眼认出靠的是「横向铺开、边中切换」，
   而引擎 0.6m 的横向移动意味着**球员几乎只在一条纵向轨道上移动**。
   纵深从 40m 修到 26m 而 y-sd 仍是 0.6m，画面上是「一条更短的竖线」，不是「一支球队」。

**判定：两份设计如果把纵深做成功，仍是半个修复——而且是较小的那一半。**

## 8. 可以进行动项的结论

按优先级（都是**实测支撑**，不依赖两份设计的机制主张）：

**P0（前置，不改代码）**
1. **拍板真实目标口径**：Metrica 25.9m 还是 SkillCorner 18.3m（差 1.52 倍）。
   两份设计都把它列为「未决」，它是**所有常数与验收的第一因**。
2. **把射门门纳入 P38 验收**：任何队形改动必须同时跑
   `l1_shot_result_distributions` / `l1_tackle_dilution_and_slot_mix` / `l3_shot_ratios` /
   `l1_home_away_goal_asymmetry` / `gm_canary_seeds`。**这是两份设计共同的最大漏洞**——
   它们只讨论形变量，没有一份提到引擎的门或 golden。
3. **把横向（y）立为与纵深同级的目标**，并为它新建结构判据（基线 0.6m，真实 14.7m）。
   现有门的集合拦不住横向改动（§A4 实测 6 倍变化 9/9 全绿）。

**P1（可立即验证的机制事实，不改引擎）**
4. **推翻「断层只会搬家」**：断层可被**非仿射的次序目标**消灭（19.2 → 4.1m）。
   后续设计不应再把「改目标公式」整体划为无效。
5. **越位锚定（上界形态）不可用**：引擎只有 3.6% 的帧越过越位线，
   上界 cap 在任何验收分辨率下都是 no-op。**不要按乙 B 实施。**
6. **两队用同一个球位公式锚定会掐死射门**：这是「靠拢两队」类机制的**硬约束**，
   任何「缩小重心间距」的方案都必须在射门门上验。

**P2（机制方向，需先补测）**
7. **横向的可行工作点很窄**：K=0.35（后防 y-sd 3.7m）过全部门，K=0.75 破 3 门。
   设计横向方案前先跑这条前沿。
8. **纵深与射门是同一条前沿**（band 0.32→0.50：纵深 27→40，射门 1.8→15.8）。
   任何纵深方案必须**先给出它的前沿**，再谈选点。
9. **甲 §2.3 C 的 `corner_setup_target zone_x1=0.98`** 值得单独审视（贡献 4.3m 纵深噪声），
   与三方案正交，可独立做。**我未实测，列为待验。**
