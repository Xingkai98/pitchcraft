## 0. 一句话结论

**假设部分成立，但成立的地方不是 #89 猜的那个。**

- #89 猜：**压力维度**（`nearest_defender_m`）被单标量门坍缩了，改成「压力 × 射门位置」
  二维判断就能同时拿到射门与犯规。
- 实测说：**压力维度在真实数据里根本不承载信息**（详见 §1）——把它"解冻"成二维
  **拿不到射门**（10.8/场，比一维 `flatGate` 的 11.4 还少）。#89 的猜想在这个方向上**是错的**。
- 但它**误打误撞**指对了一件事：出球门确实是在**用错误的维度表达射门意图**。
  真正对的那个维度是**射门倾向本身**（`OPEN_PLAY_SHOT_ENGAGE_SHIFT`），
  不是压力。把它单独抬起来，**射门 7.2 → 26.8/场，同时犯规 23.6（L1 门 [16,30] 内绿）**——
  这是 P38 十轮以来**第一次在一个配置上同时拿到"射门越过真实量级"与"犯规不炸"**。
- 代价在**别处**（§4）：抬射门会把**进球预算**一起抬上去（0.95 → 3.18/场），
  连破 4 条 L1 门。所以它**不是可交付解**，但它把「一维兑换」这条结论**证伪了一次**——
  兑换确实存在，只是**换的是另一对量**（射门 ↔ 进球），不是门那一对。

## 1. ★ 真实数据：贴身时凭什么射门、凭什么传球

### 1.1 口径与自检

Metrica 两场（`RawEventsData.csv` 的事件 × `real-game-*.json` 的帧）。
事件坐标是**原始 Metrica 坐标**（原点左上、y 向下、每半场换边），帧是**归一化后**的
（y 翻转 + 按 period 的 x 翻转）。二者必须走**同一套变换**，否则特征全错。

**自检（门槛，不是报告项）**：事件 `StartX/StartY` 应落在同帧该球员位置上。
实测中位误差 **0.0040 / 0.0043**（归一化单位 = **0.4m**）——对齐。
自检不过就 `exit(1)`，不产出错误特征（本探针里写死）。

事件筛选：`SHOT` 且 `Subtype` 不含 `HEAD`；`PASS` 且 `Subtype` 为空
（排除 CROSS / GOAL KICK / CLEARANCE / DEEP BALL / HEAD —— 那些不是"持球者选射还是传"）。
产出：**1632 行 = 射门 31 + 传球 1601**；dGoal ≤ 30m 的射程内样本 **99 行（射门 29）**。

> ⚠️ **有 4 脚射门丢失**（`Player14 / 27 / 28 / 12` 不在帧的 idMap 里 = 未进 tracking 的替补）。
> 31 脚 vs CSV 的 35 脚非头球射门。如实记录，不作修正（他们被换下后无人顶上）。

### 1.2 单变量分离度（AUC，0.5 = 完全不区分）

**射程内（dGoal ≤ 30m），全部样本**：

| 特征 | 射门中位 | 传球中位 | AUC | 读法 |
|---|---|---|---|---|
| **到球门距离** | 17.2m | 25.4m | **0.192** | ★ 主导（反向，越近越射） |
| **禁区内 0/1** | 1 | 0 | **0.700** | 同一件事的二值版 |
| 射门角度 cos | 0.83 | 0.80 | 0.505 | 无 |
| **第 1 近防守者** | 2.92m | 2.69m | **0.576** | 几乎无 |
| 第 2 近防守者 | 5.91m | 5.47m | 0.549 | 几乎无 |
| 球门侧 15m 内对手数 | 4.0 | 5.0 | 0.426 | 弱（反向） |
| 8m 内对手数 | 2.0 | 2.5 | 0.431 | 弱（反向） |
| 10m 内队友数 | 2.0 | 2.0 | 0.507 | 无 |
| **★ 引擎自己的射门打分** | **−0.31** | **−1.16** | **0.729** | 见 §1.4 |

**贴身子集（d1 ≤ 4m）**：到球门距离 AUC 0.176、禁区内 0.765、
**第 1 近防守者 0.499（字面意义的抛硬币）**。同一格局。

### 1.3 ★ 标定表：引擎的假设直接被数据反驳

引擎的假设是「d1 小 → 不射」。真实数据在同一 `dGoal` 桶内**按 d1 切**：

| dGoal\d1 | 0–2m | 2–4m | 4–8m | >8m |
|---|---|---|---|---|
| 0–11m | **100%** (2/2) | **100%** (2/2) | 100% (2/2) | — |
| 11–16.5m | **60%** (3/5) | **60%** (3/5) | 100% (2/2) | — |
| 16.5–22m | 25% (1/4) | 17% (1/6) | 25% (1/4) | 100% (1/1) |
| 22–30m | 5% (1/19) | 19% (5/27) | 17% (3/18) | 100% (2/2) |

**每一行内部 P(射门) 是平的**——16.5–22m 那一行尤其干净：25% / 17% / 25%，与 d1 无关。
（每格样本量很小，读**格局**不读百分点；全样本仅 99 个射程内事件。）

引擎侧同一张表（10 种子）**结构完全不同**：射门高度集中在中远距离的"无压"格
（22–30m 的 d1>8m 格 9%，中距离 d1 2–4m 格 0–2%），与真实正好相反。

### 1.4 多变量：真正承载信息的是位置，不是压力

L2 逻辑回归（特征标准化，系数 = 每 1 个标准差的优势比）：

| 特征 | 标准化系数 | OR | |
|---|---|---|---|
| 到球门距离 | **−0.93** | 0.39 | ★ 主导 |
| 8m 内对手数 | −0.44 | 0.65 | |
| **第 1 近防守者** | **+0.39** | 1.47 | **符号反了：越贴身越爱射** |
| 射门角度 cos | +0.38 | 1.46 | |
| 禁区内 | +0.28 | 1.33 | |
| 球门侧对手数 | −0.14 | 0.87 | |
| 第 2 近防守者 | −0.12 | 0.88 | |
| 10m 内队友数 | +0.08 | 1.09 | |

**留一交叉验证 AUC**：

| 模型 | AUC |
|---|---|
| 全特征 | **0.844** |
| 仅 dGoal | 0.769 |
| **仅 d1（引擎现状）** | **0.582** |

→ d1 单独就是**噪声**。引擎把「射门意图」表达成了**压力的补集**，而真实数据里
**射门意图基本就是"离球门多近"**。这与 `probe-real-shot-pass.mjs` 的 AUC 表、
标定表的平直度**三方一致**。

### 1.5 这条结论对 #89 意味着什么

#89 的假设「区分贴身射门与贴身传球的是**压力之外的另一个几何维度**」——**方向对了**：
确实存在另一个维度，而且它在数据里很强（CV AUC 0.844）。
但**那个维度不是压力维度**，它是**位置维度**。所以：

> **"把单标量压力门换成多维（压力 × 位置）判断"不会拿到射门**——
> 因为被冻结的那个维度（压力）本来就不承载信息。
> 能拿到射门的是**直接表达"我在射程内"**。

## 2. 引擎侧实现：三个变体 + 两个对照

`probes-main/exp89-variants.mjs`：

- `positionGate`（★ #89 的主假设）：射程内把门收到 0.5m（贴身照射）、射程外保持 8.0，
  再叠 `d1 ≤ 1.5m 时不放行`（"护不住球"单向收紧）。
- `positionGateNoGuard`：同上无保护（隔离保护条的贡献）。
- `flatGate`：全局收门（= 已测过的 exp10 形态，隔离"位置条件"）。
- `engageShift`：★ **不在 #89 假设里**，是探针里长出来的第二个自由度（§3）。

### 2.1 ★ 先修正一条前人的因果结论

`notes/defense-layers.md` §5(a) 写：「出球门一收紧……**犯规 50.4**……传球是解压阀」。
**实测：这个因果链是混淆的。** 那条读数来自 `exp4b + 门 3.0`，而 **exp4b 自己**就把犯规
抬上去了：

| 配置 | 犯规/场（L1 200 场） |
|---|---|
| 干净 main | **23.53** |
| `flatGate3.0`（干净 main + 门 3.0） | **20.37** |
| `positionGate`（干净 main） | **22.48** |
| **exp4b 单独**（快车道 10 种子） | **55.3** |

→ **在干净 main 上收紧出球门，犯规反而略降。** 50.4 那次是 **exp4b 的队形压缩**造成的
（队形压紧 → 球员距离普遍变小 → `TACKLE_DISTANCE_THRESHOLD_METERS` 内的时间变多 → 抢断/犯规暴增），
与门无关。这条修正很重要，因为它推翻的正是 #89 立论的**唯一实测依据**。

## 3. ★ 真正的第二个自由度，与它打破的那次兑换

出球门管的是「**要不要离开持球档**」；`OPEN_PLAY_SHOT_ENGAGE_SHIFT` 管的是
「**离开时走哪条路**」（推进/起脚 vs 继续带球）。源码里是**两个独立的乘子**。
在干净 main 上只动后者：

| `OPEN_PLAY_SHOT_ENGAGE_SHIFT` | 普通射门/场 | 犯规/场（10 种子） |
|---|---|---|
| −4.3（源码值） | **7.2** | 20.2 |
| −3.5 | 17.6 | 22.4 |
| **−3.0** | **26.8** | **25.7** |
| −2.5 | 36.8 | 24.4 |
| −2.0 | 53.8 | 24.7 |
| −1.0 | 95.8 | 21.1 |

**射门从 7.2 一路扫到 95.8，犯规在 20–26 之间几乎不动。** 真实普通射门 16.51/场、
引擎 L1 门要求犯规 ∈ [16,30]。

**L1 门（200 场 release）确认**：

| 配置 | 射击/场（L1） | 犯规/场 | 黄 | 红 | L1 |
|---|---|---|---|---|---|
| 干净 main | 7.75 | 23.53 | — | — | **5 绿 0 红** |
| `engageShift −3.5` | **15.71** | **23.46** | 3.12 | 0.09 | 2 绿 3 红 |
| `engageShift −3.0` | **24.82** | **23.56** | 3.07 | 0.10 | 1 绿 4 红 |

> **这是 P38 十轮以来第一次**在一个配置上同时拿到「射门 ≥ 真实量级」与「犯规落在 L1 带内」。
> §0 里说"假设部分成立"指的就是这个：**兑换确实存在，但换的是另一对量**。
> 门那一对（射门 ↔ 犯规）在干净 main 上**根本不是兑换**——它可以被单独推动；
> 真正互相拉扯的是**射门 ↔ 进球**（§4）。

### 3.1 但代价立刻出现，而且在别处

`engageShift −3.0` 的 L1 全面失败：进球 **0.95 → 3.18/场**（主 1.78 / 客 1.40），
连带 `l1_shot_result_distributions`、`l1_tackle_dilution_and_slot_mix`、
`l1_home_away_goal_asymmetry`、`l1_pass_completion_rate` 全红。

机制直接：`shot_bucket` 的转化概率是**绝对常数**（禁区内 15/30、禁区弧 7/22、远射 4/11）。
射门变成 3.4 倍 → 进球变成 3.4 倍。**引擎的进球预算挂在射门频率上，而真实足球的
进球预算挂在射门**质量**上**（真实 16.5 脚进 ~2.7 球 ≈ 0.16/脚；引擎被校准到 7.2 脚进 ~0.9 球
≈ 0.125/脚，本来就偏高，抬频率就直接爆）。

→ **这才是本题真正的「一维兑换」**：`射门频率 ↔ 进球`，通过**固定的转化率**耦合。
它不是门的问题，是**转化率没有随射门质量自适应**的问题。

## 4. ★ #89 的原假设：实测**不成立**

在干净 main 上，把门从"单标量"换成"压力 × 位置"：

| 配置 | 射门/场 | 犯规/场 | 说明 |
|---|---|---|---|
| 干净 main（单标量门 8.0） | 7.2 | 20.2 | |
| `flatGate 3.0`（单标量，收到 3m） | 11.4 | 21.8 | 单纯阈值变小 |
| `flatGate 6.0`（单标量，收到 6m） | 10.1 | 20.0 | |
| **`positionGate` R25 M0.5 g1.5（★ 二维）** | **10.8** | **23.0** | 射程内贴身照射 |
| `positionGate` R30 M0.5 g1.5 | 10.0 | 19.3 | 放更宽 |
| `positionGate` R22 M0.5 g1.5 | 7.4 | 23.5 | 收更窄 |
| `positionGate` R25 M2.0 g1.5 | 10.9 | 23.0 | 门稍松 |
| `positionGate` R25 M3.2 g1.5（**与 flatGate3 等射门数**） | 11.0 | 22.1 | 配平对照 |
| `positionGateNoGuard` R25 M0.5 | 10.4 | 22.7 | 无保护条 |
| `comboGateShift` R25 M0.5 + −3.5 | 19.9 | 21.6 | 门 + 倾向（§4.0） |
| `comboGateShift` R25 M0.5 + −3.0 | 30.2 | 26.3 | 同上，更激进 |

**读法**：

1. **二维门没有赢过一维门。** 配平射门数（11.0 vs 11.4）时，犯规 22.1 vs 21.8
   ——**逐字相同**。二维门多出来的那一维**不产生任何可测差异**。
   与 §1 的真实数据结论**一致**：压力维度里没有信息，解冻它也拿不到东西。
2. **保护条（d1 ≤ 1.5m 不放行）几乎不生效**：10.8 vs 10.4，在 sem≈0.5 内。
   顺带证明**引擎在射门时刻本来就很少真的贴身**（`probe-defense-layers.mjs`：引擎 d1 中位 7.9m）。
3. 门的天花板停在 **~11/场**（真实 16.5）。**门不是射门量的瓶颈**，
   抬 hazard（§3，同一批种子上 17.6–26.8）才是。

### 4.0 ★ 可加性对照：两个乘子**近似独立**

若"门"与"射门倾向"真是两个独立自由度，同时动它们应当**近似可加**：

| 配置 | 射门/场 | 犯规/场 |
|---|---|---|
| `positionGate` 单独 | 10.8 | 23.0 |
| `engageShift −3.5` 单独 | 17.6 | 22.4 |
| **可加预测**（`10.8 + 17.6 − 7.2`） | **21.2** | — |
| **实测 `comboGateShift`（门 + −3.5）** | **19.9** | 21.6 |
| 实测（门 + −3.0） | 30.2 | 26.3 |

实测 19.9 vs 预测 21.2（差 1.3，约 2 个 sem）——**近似可加**。
这从另一个角度确认：**门与倾向确实是两个乘子，不是同一个自由度的两种说法**；
而"门"多出来的那一维（位置）只是把乘子的**底数**抬高一点，
**真正的驱动量是倾向那个乘子**（§3 的 7.2→95.8 全扫程）。

### 4.1 叠在 exp4b 上更差

| 配置 | 纵深 | 射门 | 犯规 | 判据组 |
|---|---|---|---|---|
| exp4b 单独 | 26.4 | 0.5 | 55.3 | 5/8 |
| exp4b + `positionGateNoGuard` | 27.5 | 4.6 | 48.2 | 5/8 |
| exp4b + `positionGate` | 27.3 | 5.4 | 49.3 | 5/8 |
| exp4b + `flatGate3` | 27.4 | 7.1 | 50.3 | 6/8 |
| exp4b + `engageShift −3.0` | 26.6 | 2.3 | 53.1 | 5/8 |

**二维门在 exp4b 上也不如一维 flatGate**（5.4 vs 7.1）。而 exp4b 的犯规问题
（48–55/场）**任何门都救不了**——那是队形压缩的账。

### 4.2 另一个未验完的分支：`defendLayers`（防守方分层）

`defendLayers`（防守方按纵深分压迫层/保护层）单独跑：**纵深过压到 17.9**
（真实 23.4–28.4）、**射门归零**、**抢断 149/场**（基线 9.6）。
四个参数组合（±flateGate / positionGate）结论一致。这是 P38 已记录过的
"分层防守本就不该有用"的再确认。**未做 L1**——纵深已经出带，判据组必红，不值得花 200 场。

## 5. 判据组：本轮所有产物**全部被挡**

8 条成组否决，全部配置未通过。**阻挡者的分布本身就是结论**：

| 配置 | 被哪几条挡 |
|---|---|
| 干净 main | 纵深 40.3 / 紧凑 18.6 / 重心距 23.5 / 横向 0.55 / swarm 0.49 / 断层 19.2 / 各线 0.83 |
| **`engageShift −3.0`** | **只被几何六条挡**（纵深/紧凑/重心距/横向/断层/各线）；**射门 26.8 ✅、swarm 0.419 差一点点** |
| `positionGate` 全部 | 与干净 main 同（门不改队形） |
| exp4b 家族 | 横向（0.55–0.94）与 swarm（−0.02）——**与前九轮同两条** |

**关键观察**：`engageShift` 是本轮**唯一**把「行为」那一列（射门）变成 ✅ 的改动，
而且它**没有把几何改坏一分**（纵深/紧凑/重心距与干净 main 逐位相同）。
它是**在几何列上原地不动、单独把行为列推过线**。

这正好回答 `notes/criteria/README.md` 留的那个问题：

> 「一个真正的好机制应当**打破**这个相关（纵深降、射门不降）——判据组存在的意义就是等到那一天。」

本轮拿到的**不是**那一天（纵深没降），但拿到了它的**对偶**：
**射门被单独抬起来了，几何一点没动**。判据组的 `shotsReg` 与 `hd` 的 +0.836 相关是
**在那 16 个变体上**测的；本轮的 `engageShift` 落在相关之外——**这条判据确实有独立信息**，
不冗余。建议 #91 把 `engageShift` 系列补进 `fixtures/`（它现在挡不住，因为几何本来就红）。

**射门从 7.2 涨到 26.8、L1 犯规绿，画面却比基线更"铁轨"。**
与 P38 三次前例（"水平铁轨"、"竖直铁轨"、"横贯全场的水平细轨"）**同型**。
判据组的 `latSd` / `swarm` 正确地把它挡住了——**这两条绝不能因为"与射门无关"而放松**，
否则任何"抬射门不碰队形"的改动都会被判绿。

## 7. 结论与给 #89 的判读

1. **#89 的原假设（把压力单标量换成压力 × 位置的多维判断）实测不成立。**
   真实数据里**压力维度不承载射门信息**（AUC 0.50、逻辑回归系数 +0.39 符号还反了、
   交叉验证仅 d1 是 0.582 = 噪声；同一 dGoal 桶内 P(射门) 随 d1 平直）。
   把它解冻成二维，射门与犯规**都不动**（配平对照 22.1 vs 21.8）。
   **这条假设可以关闭了**——不是"没调好"，是**方向错**：被冻结的维度里没信息。

2. **但"出球门用错了维度"这个诊断是对的。** 正确的维度是**射门倾向本身**
   （`OPEN_PLAY_SHOT_ENGAGE_SHIFT`），不是压力。单独抬它：
   **射门 7.2 → 26.8（真实 16.5）、犯规 23.56 ∈ L1 [16,30] 绿** —— P38 十轮首次。

3. **新的、真正的「一维兑换」被定位**：**射门频率 ↔ 进球**，通过 `shot_bucket` 的
   **固定绝对转化率**耦合。踢 3.4 倍射门 = 进 3.4 倍球（0.95 → 3.18/场）。
   要让射门频率向真实收敛，必须先让**转化率随射门质量自适应**（真实 0.16 球/脚，
   引擎被校准到 0.125 球/脚却只有 7.2 脚）。这是**下一个该动的自由度**，
   与队形、与压力都无关。

4. **横向仍是完全没碰的轴**，且本轮再次证明：**任何只动射门/纵深的改动，
   画面都是同一条水平铁轨**。`latSd` 真实 10.5 vs 本轮全部 ≤ 1.0。
   要出真画面，必须换 `formation_target` 的**表示方式**（P38 线 B 的结论未变）。

5. **给 #91 的两条**：
   - `shotsReg` 判据**有独立信息、不冗余**——`engageShift` 落在 `hd` 相关之外（几何全不动、射门翻 3.7 倍）。
   - 建议把 `engageShift −3.5 / −3.0` 补进 `fixtures/`，并在 README 里记下：
     **射门判据能抓住"几何不动但射门暴涨"的配置**（当前 16 变体里没有这种）。
