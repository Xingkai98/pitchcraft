## 0. 一句话结论

**#89 的假设被证伪；但证伪过程里定位到了另一个真实自由度，以及一对新的兑换。**

- #89 猜：**压力维度**（`nearest_defender_m`）被单标量门坍缩了，改成「压力 × 射门位置」
  二维判断就能同时拿到射门与犯规。
- 实测说：**压力维度不承载独有信息**（§1）——最稳的证据是**去一法**：去掉 d1 后
  留一 AUC 0.846 vs 全特征 0.844，**几乎不掉**。把它"解冻"成二维，射门与犯规都不动，
  而且**二维门 = 一维门**（配平射门数时犯规 22.1 vs 21.8）。**这条假设可以关闭。**
- 但出球门**确实在用错误的维度表达射门意图**。真正对的那个维度是**射门倾向本身**
  （`OPEN_PLAY_SHOT_ENGAGE_SHIFT`）。单独抬它：**射门 7.2 → 26.8/场，
  同时犯规 23.56（L1 门 [16,30] 内绿）**。
  ⚠️ 但**这个量级是抬出来的，不是修出来的**：它超出引擎自己 L1 门的射门带 [6,11]，
  因为**二次进攻链仍然缺失**（`criteria/README.md`）。所以它**不是可交付解**。
- 代价在**别处**（§3.1）：抬射门把**进球预算**一起抬上去（0.89 → 3.18/场），L1 **5 绿 4 红**。
  兑换确实存在，只是**换的是另一对量**：**`射门频率 ↔ 进球`，通过固定的绝对转化率耦合**。

> ⚠️ 本文档经**两轮**独立审阅。两轮共修掉**六类**会直接影响结论的缺陷
> （L1 读数两次漏门、wasm 搬运不检错、引擎常数漂移、特征自含、单变量建模的共线脊）。
> 修完**结论方向不变**，但**多个数字变了**。§7.6 列了全部。

## 1. ★ 真实数据：贴身时凭什么射门、凭什么传球

### 1.1 口径与自检

Metrica 两场（`RawEventsData.csv` 的事件 × `real-game-*.json` 的帧）。
事件坐标是**原始 Metrica 坐标**（原点左上、y 向下、每半场换边），帧是**归一化后**的
（y 翻转 + 按 period 的 x 翻转）。二者必须走**同一套变换**，否则特征全错。

**自检（门槛，不是报告项）**：事件 `StartX/StartY` 应落在同帧该球员位置上。
实测中位误差 **0.0040 / 0.0043**（归一化单位 = **0.4m**）——对齐。
自检不过就 `exit(1)`，不产出错误特征（本探针里写死）。

> ⚠️ **复现前提**：`.scratch/tracking-data/` 是 gitignored 的，本 worktree 里没有——
> 重跑 `probe-real-shot-pass.mjs` 需要先从主仓库拷（或 symlink）那份 234MB 的
> Metrica sample-data。**本文引用的自检数字无法在本 worktree 单独复核**；
> 可复核的是产物 `out/real-shot-pass.jsonl`（1632 行）与其上跑的所有分析。

事件筛选：`SHOT` 且 `Subtype` 不含 `HEAD`；`PASS` 且 `Subtype` 为空
（排除 CROSS / GOAL KICK / CLEARANCE / DEEP BALL / HEAD —— 那些不是"持球者选射还是传"）。
产出：**1632 行 = 射门 31 + 传球 1601**；dGoal ≤ 30m 的射程内样本 **99 行（射门 29）**。

> ⚠️ **有 4 脚射门丢失**（`Player14 / 27 / 28 / 12` 不在帧的 idMap 里 = 未进 tracking 的替补）。
> 31 脚 vs CSV 的 35 脚非头球射门。如实记录，不作修正（他们被换下后无人顶上）。

### 1.3 ★ 标定表：引擎的假设**大部分**被数据反驳（但不是全部）

引擎的假设是「d1 小 → 不射」。真实数据在同一 `dGoal` 桶内**按 d1 切**：

| dGoal\d1 | 0–2m | 2–4m | 4–8m | >8m |
|---|---|---|---|---|
| 0–11m | **100%** (2/2) | **100%** (2/2) | 100% (2/2) | — |
| 11–16.5m | **60%** (3/5) | **60%** (3/5) | 100% (2/2) | — |
| 16.5–22m | 25% (1/4) | 17% (1/6) | 25% (1/4) | 100% (1/1) |
| 22–30m | **5%** (1/19) | 19% (5/27) | 17% (3/18) | 100% (2/2) |

**近门三行（≤22m）内部是平的**——16.5–22m 那行尤其干净：25% / 17% / 25%，与 d1 无关。
引擎在那里「d1≤8 → 永不射」的硬门**没有任何数据支持**。

> ⚠️ **但 22–30m 那行不支持这个读法**（审阅发现，早先版本漏了）：
> 该行 `0–2m` 格只有 **5%（1/19）**，是**该行最低**的一格，方向与引擎假设一致；
> 而且该行样本量四行里最大，不能当噪声一笔带过。诚实读法是：
> **"贴身也照射"在近门成立，在 22–30m 的远射区不成立**（合理——那里本来就极少射门：
> 该行 66 个事件里只有 11 脚，其中 `d1 ≤ 8m` 的 64 个事件里 9 脚）。
> 引擎的门问题主要在**近门区**。

（每格样本量很小，读**格局**不读百分点；全样本仅 99 个射程内事件。）

引擎侧同一张表（10 种子）**结构完全不同**：射门高度集中在中远距离的"无压"格
（22–30m 的 d1>8m 格 9%，中距离 d1 2–4m 格 0–2%），与真实正好相反。

### 1.4 多变量：压力维度**可整体删除**（这条稳），但"位置能解释多少"**依赖口径**（这条不稳）

L2 逻辑回归。**两个距离口径都跑、都报**——中位差 4.31m，结论对它敏感：

| 特征 | 欧氏口径系数 | 引擎口径（仅纵深）系数 |
|---|---|---|
| 到球门距离 | **−0.93** | **−0.57** |
| 射门角度 cos | +0.38 | +0.64 |
| 禁区内 | +0.28 | +0.55 |
| **第 1 近防守者** | **+0.39** | **+0.45** |
| 8m 内对手数 | −0.44 | −0.37 |
| 球门侧对手数 | −0.14 | −0.25 |
| 第 2 近防守者 | −0.12 | −0.16 |
| 10m 内队友数 | +0.08 | +0.13 |

**留一交叉验证 AUC**（全部真留一；警告：早先版本把"去掉 d1"打印成了"仅 d1"，已修）：

| 模型 | 欧氏口径 | 引擎口径 |
|---|---|---|
| 全特征 | **0.844** | **0.806** |
| 仅距离（真单变量） | **0.792** | **0.626** |
| 仅 d1（真单变量） | **0.516** | **0.516** |
| 去掉距离（其余全留） | 0.844 | 0.806 |
| **去掉 d1（其余全留）** | **0.844** | **0.806** |
| （样本内对照，全特征） | 0.892 | — |

> 「仅 d1」两列**必须相同**——单变量的设计矩阵与距离口径无关。上一版打出 0.410 / 0.627
> 是**实现 bug**：用"把其余 7 列置 0"来模拟单变量，那 7 列常量互相共线又与截距共线，
> 参数落在平坦脊上，梯度下降每次停在不同点。已改为**真的只拟合那一列**。

**三条读法（必须一起说，只报一条就是选择性报告）**：

1. **去掉 d1 一点不掉**（0.844 vs 0.844；0.806 vs 0.806）——**压力维度不承载独有信息，
   可以整体删除**。这是本节最稳的一条，也是 #89 原假设被证伪的**核心证据**。
2. **仅 d1 是弱判别器但≠抛硬币**（真单变量留一 **0.516**，两口径必然相同）。
   三处不同的数不要混用：全体本单变量留一 **0.516** / 贴身子集内单变量 AUC **0.499** / 
   偏效应系数（距离也在模型里时）**0.39–0.45**。
3. ⚠️ **"球门距离能解释多少"依赖口径**：欧氏口径下仅距离 0.792（接近全特征），
   引擎的仅纵进口径下只有 0.626——**只比 d1 的 0.516 高一点**。所以引擎的简化距离**不是**
   "位置主导"的现成替代品；要拿位置当判据，得先把距离量准（y 角向）。

**另一条独立的证据（不依赖口径选择）**：标定表（§1.3）在 16.5–22m 桶内
P(射门) 对 d1 平直（25%/17%/25%），那一格用的是**欧氏** dGoal——但桶内的比较
本身不涉及距离口径，所以"压力不承载信息"这条**不需要口径假设**。

### 1.5 这条结论对 #89 意味着什么

#89 的假设「区分贴身射门与贴身传球的是**压力之外的另一个几何维度**」——**方向对了**：
确实存在另一个维度（全特征留一 AUC 0.81–0.84）。
但**那个维度不是压力维度**，而是**位置维度**——而位置维度引擎手里**本来就有**
（`dist_to_goal_m` 已经进了 `compute_shot_score` 的 `distance_quality`）。所以：

> **"把单标量压力门换成多维（压力 × 位置）判断"不会拿到射门**——
> 因为被冻结的那个维度（压力）本来就不承载信息，
> 而真正有信息的那个维度（位置）**引擎早就在用了**（只是用在了 hazard 打分里，
> 而不是用在**门**上）。见 §4 的实测：二维门逐字等于一维门。

## 2. 引擎侧实现：三个变体 + 两个对照

`probes-main/exp89-variants.mjs`：

- `positionGate`（★ #89 的主假设）：射程内把门收到 `M`（贴身照射）、射程外保持 8.0，
  再叠 `d1 ≤ G 时不放行`（"护不住球"单向收紧）。
- `positionGateNoGuard`：同上无保护（隔离保护条的贡献）。
- `flatGate`：全局收门（= 已测过的 exp10 形态，隔离"位置条件"）。
- `engageShift`：★ **不在 #89 假设里**，是探针里长出来的第二个自由度（§3）。

> ⚠️ **★ 探针自身的坑（审阅发现，已修）**：带保护条时 `M` 会被**短路**——
> 判据是 `(nd ≤ M && nd > G) || (nd ≤ G && nd ≤ 8.0)`，第二项在 `G ≤ 8` 时恒真，
> 于是 `nd ≤ max(M, G)` 全部出球，**`M` 只有在 `M > G` 时才起作用**。
> 即 `M=0.5, G=1.5` 与 `M=1.5, G=0.5` **逐位等价**（实测确认：两者都是
> 纵深 40.279 / 射门 10.8 / 犯规 23.0 / 抢断 8.3——**完全相同**）。
> **所以报数时报的是有效门 `max(M, G)`，不是 `M`**（`exp89-variants.mjs` 的
> `effectiveCutoff` 把它写进源码注释，数字可审计）。
> 早先写"射程内把门收到 0.5m"**是错的**——那个配置的有效门是 **1.5m**。

### 2.1 ★ 先修正一条前人的因果结论

`notes/defense-layers.md` §5(a) 写：「出球门一收紧……**犯规 50.4**……传球是解压阀」。
**实测：这个因果链是混淆的。** 那条读数来自 `exp4b + 门 3.0`，而 **exp4b 自己**就把犯规
抬上去了：

| 配置 | 犯规/场（L1 200 场） |
|---|---|
| 干净 main | **23.53** |
| `flatGate3.0`（干净 main + 门 3.0） | **20.37** |
| `positionGate`（干净 main） | **22.48** |
| **exp4b 单独**（快车道 10 种子） | **55.3** |

→ **在干净 main 上收紧出球门，犯规反而略降。** 50.4 那次是 **exp4b 的队形压缩**造成的
（队形压紧 → 球员距离普遍变小 → `TACKLE_DISTANCE_THRESHOLD_METERS` 内的时间变多 → 抢断/犯规暴增），
与门无关。这条修正很重要，因为它推翻的正是 #89 立论的**唯一实测依据**。

## 3. ★ 真正的第二个自由度，与它打破的那次兑换

出球门管的是「**要不要离开持球档**」；`OPEN_PLAY_SHOT_ENGAGE_SHIFT` 管的是
「**离开时走哪条路**」（推进/起脚 vs 继续带球）。源码里是**两个独立的乘子**。
在干净 main 上只动后者：

| `OPEN_PLAY_SHOT_ENGAGE_SHIFT` | 普通射门/场 | 犯规/场（10 种子） |
|---|---|---|
| −4.3（源码值） | **7.2** | 20.2 |
| −3.5 | 17.6 | 22.4 |
| **−3.0** | **26.8** | **25.7** |
| −2.5 | 36.8 | 24.4 |
| −2.0 | 53.8 | 24.7 |
| −1.0 | 95.8 | 21.1 |

**射门从 7.2 一路扫到 95.8，犯规在 20–26 之间几乎不动。** 真实普通射门 16.51/场、
引擎 L1 门要求犯规 ∈ [16,30]。

**L1 门（200 场 release）确认**。
> ⚠️ **读数口径已修**（审阅发现）：早先只数 `l1_*` 五个测试并报"5 绿 0 红"，
> 而 `cargo test -- --ignored` 实际跑 **9 个**（含 `l3_shot_ratios`、
> `l3_home_away_goal_calibration`、`p13_side_effect_snapshot`、`p31_frequency_5min_directional`）。
> **读数范围必须与门的范围一致**——否则就是本 campaign 反复出的口径分叉。
> 下表是修好后重跑的（干净 main 因此从"5 绿"变成 **9 绿**）。

| 配置 | 射门/场（L1） | 犯规/场 | 黄 | 红 | 进球/场 | L1（9 门） |
|---|---|---|---|---|---|---|
| 干净 main | 7.75 | 23.53 | 3.00 | 0.08 | 0.89 | **9 绿 0 红** |

`−3.5` 红的：`l1_shot_result_distributions`、`l1_tackle_dilution_and_slot_mix`、
`l1_home_away_goal_asymmetry`。
`−3.0` 红的：`l1_shot_result_distributions`、`l1_pass_completion_rate`、
**`l1_tackle_dilution_and_slot_mix`**、`l1_home_away_goal_asymmetry`
（`shot/tackle` = 24.82/9.03 = **2.749 ∉ [0.5,1.5]**，`realism.rs:759`）。

> ⚠️ **这张表被返工过两次，原因值得记下**：`run-exp89.mjs` 早先按行匹配
> `test NAME ... ok/FAILED`。但 `--nocapture` 下测试自己的 stdout 会插在名字与
> `ok/FAILED` **之间**，`$` 锚定的正则**静默漏测试**——`−3.0` 被记成 8 个（5 绿 **3** 红），

> **自相矛盾告警**（两者不一致就吵）。9 门这个数字本身也是上一轮才修对的（早先只数 `l1_*`，5 个）。

> **在「射门接近真实量级」与「犯规落在 L1 带内」这两条上，本轮只有这两个配置同时满足**
> （**"十轮以来第一次"不可验证**——本仓没有前几轮的配置台账，审阅已要求去掉这个说法）。
> ⚠️ **还有两条限制**：
> (a) **"真实量级"要分开说**：`−3.5` 的 **15.71** 贴近真实 16.51，且落在引擎 L1 射门带
> [6,11] 之外不多；`−3.0` 的 **24.82** 是 1.5 倍真实值，**远超**引擎自己的带。
> 该带之所以是 [6,11] 而非真实值，是因为引擎**没有二次进攻链**（`criteria/README.md`）——
> 本配置并没有修那条链，只是把频率顶上去，所以**这个"量级"是被抬出来的，不是被修出来的**。
> (b) 判据组的**射门列本轮没有区分力**：`shotsReg` 是单边下界 5.5，**干净 main 本来就 7.2 ✅**
> （见 §5 的更正）——所以"射门 ✅"不是本配置挣来的。
> §0 说"假设部分成立"指的就是这个：**兑换确实存在，但换的是另一对量**。
> 门那一对（射门 ↔ 犯规）在干净 main 上**根本不是兑换**——它可以被单独推动；
> 真正互相拉扯的是**射门 ↔ 进球**（§3.1）。

**未披露的代价（审阅要求补上）**：`engageShift` 同时把**抢断**从 9.6 降到 8.1/场（−16%）。
这直接关系到 §2.1 那条论证——若"队形压缩 → 抢断阈值内时间变多 → 犯规暴增"成立，
那么反过来"抢断变少"也可能是犯规不涨的机械原因之一，而不全是"踢得更频繁所以更解压"。
本轮的产物不足以分离这两个解释。

### 3.1 但代价立刻出现，而且在别处

`engageShift −3.0`：进球 **0.89 → 3.18/场**（主 1.78 / 客 1.40，**3.6 倍**），
射门 7.75 → 24.82（**3.2 倍**）——**进球倍数 ≈ 射门倍数**。

机制直接：`shot_bucket` 的转化概率是**绝对常数**（禁区内 15/30、禁区弧 7/22、远射 4/11）。
射门涨 3.2 倍 → 进球涨 3.6 倍。**引擎的进球预算挂在射门频率上，而真实足球的
进球预算挂在射门**质量**上**（真实 16.5 脚进 ~2.7 球 ≈ 0.16/脚；引擎被校准到 7.75 脚进 0.89 球
≈ 0.115/脚，抬频率就直接爆）。

→ **这才是本题真正的「一维兑换」**：`射门频率 ↔ 进球`，通过**固定的转化率**耦合。
它不是门的问题，是**转化率没有随射门质量自适应**的问题。

## 7. 结论与给 #89 的判读

1. **#89 的原假设（把压力单标量换成压力 × 位置的多维判断）实测不成立。**
   真实数据里**压力维度不承载独有信息**——最稳的证据是**去一法**：
   去掉 d1 后留一 AUC 0.846（全特征 0.844），**几乎不掉**。单变量 d1 也是弱判别器
   （真单变量 **0.516**）。把门解冻成二维，射门与犯规**都不动**
   （配平对照 22.1 vs 21.8；且 `M` 参数被保护条短路，两个配置逐位等价）。
   **这条假设可以关闭了**——不是"没调好"，是**方向错**：被冻结的维度里没独有信息，
   而真正有信息的维度（位置）**引擎早就在 hazard 打分里用了**。

2. **但"出球门用错了维度"这个诊断是对的。** 正确的维度是**射门倾向本身**
   （`OPEN_PLAY_SHOT_ENGAGE_SHIFT`），不是压力。单独抬它：
   **射门 7.2 → 26.8/场、犯规 23.56 ∈ L1 [16,30] 绿**。
   ⚠️ 两条限制：**量级是抬出来的不是修出来的**（超引擎 L1 射门带 [6,11]，
   因为二次进攻链仍缺）；"十轮首次"无台账可验，只能说**本轮配置里唯一**。

3. **新的、真正的「一维兑换」被定位**：**射门频率 ↔ 进球**，通过 `shot_bucket` 的
   **固定绝对转化率**耦合。射门涨 3.2 倍 → 进球涨 3.6 倍（0.89 → 3.18/场）。
   要让射门频率向真实收敛，必须先让**转化率随射门质量自适应**（真实 0.16 球/脚，
   引擎 0.115 球/脚）。这是**下一个该动的自由度**，与队形、与压力都无关。

4. **横向仍是完全没碰的轴**，且本轮再次证明：**任何只动射门/纵深的改动，
   画面都是同一条水平铁轨**。判据组的 `latSd` 真实 10.5 vs 本轮 0.378–1.28
   （§6 那张图里的 0.32 是**渲染探针**口径，与判据组不可比，见 §6 注）。
   要出真画面，必须换 `formation_target` 的**表示方式**（P38 线 B 的结论未变）。

5. **给 #91 的一条（按审阅收紧）**：`shotsReg` 与 `hd` 的 +0.836 相关是在 16 个变体上测的；
   `engageShift` 提供了"几何近似不变而射门翻 3 倍"的**反例**，支持该判据非冗余。
   **但本轮没有任何配置是被这条判据挡住的**（干净 main 本来就 7.2 ✅），
   所以它是"有独立信息"的证据，**不是**"挡住了一个漏网配置"的证据。

6. **方法学：本轮四个探针缺陷会直接影响结论，全部已修**（经**两轮**独立审阅）：
   ① `run-exp89.mjs` 的 L1 读数**漏门两次**——先只数 `l1_*`（5/9），改成宽前缀后
      又因 `$` 锚定的行正则被 `--nocapture` 的交错输出打断，`−3.0` 被记成 8 个测试
      （5 绿 **3** 红），**漏掉的正是失败的 `l1_tackle_dilution_and_slot_mix`**。
      现改为解析 libtest 收尾行取计数 + panic 线程名取名单 + 自相矛盾告警；
   ② `cp` 的返回码被丢掉 → 构建/搬运失败会静默跑旧 wasm 却记一个像样的 sha；
   ③ `analyze-shot-pass.mjs` 的引擎常数漂移（`SHOT_SPACE_MIN/MAX_M` 写成 1.5/5.0，
      源码 **2.0/8.0**，lib.rs:540/542），且用欧氏距离喂引擎的 x-only `distance_quality`；
   ④ `probe-real-shot-pass.mjs` / `probe-shot-pass-compare.mjs` 把持球者自己算进
      "最近队友"（`mateDist ≡ 0`、`nMate10` 多 1）。
   另有两处**建模**错误：模型脚本把"去掉 d1"打印成"仅 d1"（单变量 vs 去一法），
   以及用"把其余列置 0"模拟单变量（7 列常量共线 → 落在平坦脊 → **同一设计矩阵给出随口径漂移的 AUC**）。
   修完**结论方向不变**，但**多个数字变了**：L1 绿/红计数（§3）、口径敏感性表（§1.4）、
   `mateDist`（§1.2）、22–30m 行的样本量（§1.3）。
