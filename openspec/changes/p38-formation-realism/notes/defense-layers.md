## 1. 先复现假设：真实是两层，引擎是一层

`probes-main/probe-defense-layers.mjs`（**可移植版**——原 `probe-shot-space.mjs` 硬编码到
`/home/happy/.claude/worktrees/` 的旧 worktree，是 P38"脚本指向旧 worktree"那个坑的现存实例）。

射门瞬间、球位到**对方非门将**球员的距离（米），按升序取前三档：

| 来源 | n | 第 1 近（中位） | 第 2 近 | 第 3 近 | 第 2 近 <8m |
|---|---|---|---|---|---|
| 真实 Metrica game1 | 24 脚 | **2.0m**（<4m 79%） | **5.8m** | 7.8m | **79%** |
| 真实 Metrica game2 | 24 脚 | **2.9m**（<4m 67%） | **5.0m** | 7.4m | **79%** |

**假设成立**：真实的防守在射门瞬间是「一人贴身 + 一人 5m 待命」的两层；引擎是「一层且都很远」。

> 顺带：本探针还暴露一个**引擎的足球问题**——真实的射手在 2–3m 压力下起脚，
> 引擎的射手面前**平均 7.9m 没人**。这不只是"防守方不会分层"，也是"进攻方射得太舒服"。

## 2. ⚠️ 但假设的**机制**是错的：exp4b 的防守者比真实还远

假设的因果链是：「exp4b 把整块压到球附近 → 防守者全贴到 1m → 射门空间因子归零 → 射门崩」。
直接量 exp4b：

| 配置 | 第 1 近 | 第 2 近 | 分层间距 | 纵深 hd | 普通射门/场 |
|---|---|---|---|---|---|
| 引擎干净 main | 8.29m | 12.42m | 5.16 | 40.32 | 7.2 |
| **exp4b** | **8.29m** | **12.42m** | **5.16** | **26.44** | **0.56** |

**exp4b 在射门瞬间的防守者距离与干净 main 一模一样（8.29 / 12.42）**——
因为射门是由**进攻方**发起的，而 exp4b 压缩的是**两队各自的块**，
进攻方射门时身边的防守者并没有被吸过来。所以"防守者太近"**不是**射门崩的原因。

**这条推翻了 findings-final §4 的机制解释**（"防守者 <8m 占比从 50.6% 升到 92%"）——
那个数字来自另一套口径（`probe-shot-space` 在 demo 世系上的读数），在干净 main 上不成立。

## 3. ✅ 真因：持球链的**出球门**（单变量实测）

既然不是防守者距离，就得直接问"射手为什么不射"。读 `evaluate_open_play_carrier_action`
（engine/src/lib.rs:1783）——持球者每 tick 依次过三道门，**第一道是硬门**：

```rust
// ① 出球档：被贴身逼抢（或门将持球）→ 普通传球
if gk_holding || nearest_defender_m <= OPEN_PLAY_PASS_PRESSURE_M || stalled_unpressed {
    return CarrierPlan { action: Some(CarrierAction::Pass { ... }), ... };
}
// ② 射门推进档：只有走到这里才可能射门
if open_play_shot_engage_hits(st, rng) { ... }
```

`OPEN_PLAY_PASS_PRESSURE_M = 8.0`（`FOUL_PRESS_DIST_M` 同尺度，P31 定）。
**实测（10 种子 × 5400s，n=270,010 持球帧）：最近防守者 ≤8m 的帧占 54%**
——即超过一半的持球时间，**射门档根本不会被评估**。

而真实球员在 **2.0–2.9m** 压力下起脚（§1）。**8m 这个门在真实尺度上宽了一倍以上。**

### 单变量验证（只改这一行常量）

`patches/exp10-pass-gate-3m.patch` = 把 `8.0` 改成 `3.0`，其余一字不动：

| 出球门 | 纵深 hd | 普通射门/场 | 引擎 L1 门 |
|---|---|---|---|
| 8.0（main） | 40.32 | 7.2 | **9/9 绿** |
| 5.0 | 40.4 | 7.6 | — |
| **3.0** | 40.38 | **11.4** | 4 红（射门 11.3 超上界 [6,11]、传球成功率 0.819、shot/tackle 1.65、主队进球 0.895） |

**射门对这条门高度敏感**（8.0→3.0 让射门 7.2→11.4，+58%）——**因果确立**。

## 5. ⚠️ 防守分层假设：**证伪**

按主 session 的建议实现了 `patches/exp11-defense-layers.patch`：
防守方按**纵深排名**（静态模板，避免排名随球跳动）分两层——
最靠前的 N 人压迫（贴球），其余保持在球后方 `holdM` 米、按排名铺开。

单独跑（无射门门修正）：

| 配置 | 纵深 hd | 横向 latSd | swarm | 普通射门/场 | 引擎 L1 门 |
|---|---|---|---|---|---|
| exp4b 基座 | 26.4 | 0.73 | −0.01 | 0.56 | — |
| exp11 分层（pressN=2, holdM=6） | **17.9** | 2.74 | 0.27 | **0** | — |

纵深**过压**（17.9，低于真实下界 23.4）、射门**归零**、且（在叠加射门门后）**10 种子崩 2 个**。

**判定：假设证伪。** 理由不是"没调好"，而是**机制上不该有用**：
§2 已证 exp4b 的防守者本来就比真实**远**（8.3 vs 2.0–2.9m），
**没有"太挤"需要靠分层来缓解**。分层解决的是"防守者全贴到 1m"这个**不存在的问题**。

> 这也解释了 §1 那个反差：真实是"贴身+待命"，引擎是"都很远"。
> 引擎缺的不是**防守方的分层**，而是**防守方整体太远** —— 那是另一个问题
> （防守方不去压迫），与射门崩**无关**（射门崩在持球链，§3）。

## 7. 结论与交给 #89 的东西

### 得到什么

1. **射门崩的真因改判**：不是"队形挤压防守者"，而是**持球链的出球门**
   （`OPEN_PLAY_PASS_PRESSURE_M = 8.0`）在真实尺度上宽了一倍以上。
   这是一条**新线索**，与前 9 次实验（全在队形里打转）**不同轴**。
2. **第一个"纵深达标 + 射门不崩"的实测点**：exp4b + 门 3–4m（纵深 26.9–27.4 / 射门 5.2–7.1）。
3. **防守分层假设证伪**，且给出了机制层面的理由（防守者本来就太远，没有"太挤"可解）。
4. 出球门通道**单独不可交付**（L1 门 4–5 红，犯规激增是硬约束）。

### 交给 #89 的判读

- **不要再在队形里找射门**。纵深与射门的耦合**不是通过防守者距离**发生的，
  而是通过**持球决策**：队形压缩改变的是**进攻方**的接球位置与推进路径，
  射门数随之变化。这条路需要单独设计（不是队形机制的副产品）。
- **出球门（8.0m）与犯规门（16–30/场）是同一根杠杆的两端**：
  收紧它 → 射门↑但犯规爆；放松它 → 犯规合规但射门被压。
  **这条一维兑换没有内部工作点**（与 lag 扫描同构）。要同时拿到，需要
  **另加一个自由度**（如：区分"背身/无支援"与"有出球选择"的受压，
  或让犯规成本随出球门收紧而上升）——属机制设计，不属本轮探索。
- 判据组（阶段 1）**正确地拒绝了所有这些点**：exp4b+门3 拿到 6/8（被 latSd、swarm 挡），
  main 拿到 2/8。**横向（latSd 10.5 vs 引擎 0.5–2.7）仍是完全没碰的轴**。
