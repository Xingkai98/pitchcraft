# 候选 03：两队队形解耦（相位滞后）

## 改了什么

**两个补丁，看你要哪个**：

| 文件 | 内容 |
|---|---|
| `cand03-decouple.patch` | 只在**基线**上加"非持球方的块锚滞后 0.10" |
| `combined-with-equal-spacing.patch` | **叠加 exp4b**（等间距块）+ 相位滞后 |

## 为什么——票据 #89 的核心假设，本轮首次实测

exp4b（等间距块）把纵深压到真实量级（27.1 vs 真实 25.9），但射门从 15.8/场崩到 **1.8/场**。
机制：**两队共用同一个块锚公式** `centre = 0.165 + 0.59 * ball` → 进攻方压上时防守方的块
**也在同一个位置** → 两块重叠 → 防守者全贴到 1m → 射门空间因子归零。

假设：**给非持球方的块锚加一个滞后**，两队就不再重叠。

## 实测结果（关键）

| 配置 | 纵深 | 重心间距 | **场均射门** |
|---|---|---|---|
| 真实 | 25.9 | 8.3 | **~13** |
| 基线 | 40.2 | 23.6 | 7.9 |
| exp4b 单独 | 27.1 | 7.8 | **1.8** ❌ |
| **exp4b + 候选03** | **27.1** | 16.8 | **3.8** |

**射门翻倍（1.8 → 3.8），且纵深保持在真实量级**——这是本轮**第一次**有方案
同时做到"队形压到真实量级 + 射门没崩"。

## 我的判断

⚠️ **假设成立了一半**：
- ✅ 解耦确实显著缓解了射门崩塌（×2.1）
- ✅ 纵深保持
- ❌ 但 3.8 离真实 13 还很远
- ❌ 而且**重心间距从 7.8 恶化到 16.8**（真实 8.3）——解耦把两队推开了

**这说明方向对、力度和方式都不够**。0.10 的滞后是个未经调优的初值。
可能的下一步（**我没做**，留给你判断）：
1. 扫描 `DECOUPLE_LAG` 看是否存在更优值
2. 滞后改成**非线性**（球越靠前，滞后越大）
3. 解耦只作用于**防线**（而不是全队），让中场保持对位

## 这个候选的价值

它是**唯一一个在"队形压到真实量级"的前提下没有让引擎崩掉的方案**——
虽然还不够好，但它证明了 **#89 的路是通的**（耦合可以被打破，只是需要更好的机制）。
