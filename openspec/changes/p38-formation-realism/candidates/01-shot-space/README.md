# 候选 01：射门空间尺度重标定

## 改了什么

`engine/src/lib.rs` 的四个常量（`exp8-shot-space.patch`）：

| 常量 | 原值 | 新值 | 含义 |
|---|---|---|---|
| `SHOT_SPACE_MIN_M` | 2.0 | 1.5 | 空间因子下限 |
| `SHOT_SPACE_MAX_M` | 8.0 | 5.0 | 空间因子上限 |
| `SHOT_PRESSURE_NEAR_M` | 8.0 | 3.0 | 最近防守者压迫尺度 |
| `SHOT_PRESSURE_SECOND_M` | 16.0 | 8.0 | 第二近防守者尺度 |

## 为什么——一个从没验证过的假设

引擎假定"**防守者在 8m 内就算被压迫**"。我实测了真实比赛射门瞬间的距离分布
（`probes-main/probe-shot-space.mjs`，Metrica 2 场 × 48 脚射门）：

| | 最近防守者 | 第二近防守者 |
|---|---|---|
| **真实** | 中位 **2.0–2.9m**，92% <8m | 中位 **5.0–5.8m**，79% <8m |
| 引擎 | 中位 8.3m，只有 45% <8m | 中位 9.8m，**只有 15%** <8m |

**真实球员就是在贴身逼抢下射门的。** 引擎的"8m 才算没压迫"与真实差了一个量级。

## 实测结果

| | 基线 | 本候选 |
|---|---|---|
| 场均射门（5 seed） | 7.9 | **9.6** |
| 引擎 L1/L3 门（9 道） | 全绿 | **全绿** ✅ |

**纵深/紧凑/重心距/宽度**：几乎不变（这个改动只碰射门模型，不碰队形）。

## 我的判断

✅ **单独看，这是一个正当的、可通过全部现有门的改进**——它修正了一个用真实数据
才能发现的错误假设，不是拟合。

⚠️ **但它救不了队形压缩造成的射门崩塌**：叠加 exp4b 后射门 1.8 → **1.0**（更差）。
所以它是独立的改进，**不是** #89 那个耦合的解药。

**建议**：可以作为**独立小改动**先合（它自己有据可依），但别指望它解决队形问题。
