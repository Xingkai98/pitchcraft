## Why

`#17A` 产出了一张**异常清单**（6/10 条规则触发：动作间隔 12.64 s、52.7% 同 tick 收束、
拦截/抢断夺回率 0.0% …），`#16`/`#124` 产出了**空间与意图观测**。但仓库里还没有一个东西
能回答**单个 possession 为什么长这样**：

- P17A 是**聚合**口径——它说「78.2% 的争抢集中在中带」，但**指不到**「seed 7 的第 42 段
  是在哪一拍、因为谁、丢在哪」；
- P16/P124 是**特征**口径——它们产出 AUC 与覆盖率，**不产出解释**；
- 三者都**没有**把「事件 + 空间 + 意图」按 possession **对齐**到一起看过。

后果是 `#19`（最小生成改造）目前只能**依据聚合数字**挑靶点，而 P17A 报告已经点名：
它的机制假设「需要球附近双方人数 / 最近防守距离」才能从假设升格为结论。**没有逐 episode
的诊断，改哪一条都只能靠猜。**

## What changes

- 新增一个**编译型 Rust 诊断器**（`engine/tests/p17b/` + `engine/tests/p17b_diagnosis_report.rs`），
  只读消费 `simulate_with_behavior_observations()` 的公开 `DiagnosticMatch`，
  **不新增生产 API、不改 `engine/src/`**（同 P17A）。
- **第一交付是「证据边界」**：把诊断要用到的每个量逐条标注
  **观测事实 / 机制假设**，并写明它落在哪个公开字段上。这是本 change 的**核心纪律**——
  本项目反复出现「doc 声称的机制，代码里不存在」，诊断器若声称能解释它看不见的东西，
  就是同一族缺陷的新实例。
- 产出**两级报告**：
  - **L1 逐 episode 诊断卡**：一段 possession 的完整展开（开始/结束原因、动作链、
    结束前若干拍的接应/压力/位置、**四类归因各自带证据出处**、可回放定位）；
  - **L2 聚合视图**：按结束原因 / 争抢成因 / 归因类别分组，供挑靶点。
- 四类归因**按证据能力分别定义口径**（见 design §4）：
  - **转换**：报**事件级转换**（`EpisodeStartReason` / `EpisodeEndReason` /
    `ContestStartReason`），**不报战术 phase**（`#16`/`#124` 已双负）；
  - **接应**：复用 `#16` 已固化的 `support_formation` 口径（含其阈值参数）；
  - **压力**：`pressure_state_ticks` + `DefensiveIntent`，措辞按 `#124` 的判别力结论收敛；
  - **动作**：`Mover.action` 串 + 事件（**含松散球期的 `chase`**——见 design §2）。
- 每条结论必须能落到**可回放定位**（seed / 时间 / episode / 事件下标），
  复现 `#17A` 已建立的形状。
- 产出机器可读 JSON 与人可读 Markdown，provenance 沿用 `#17A`/P16 形态。

## Non-goals

- **不实现 `#15B` 的 phase 标注器**；**不得**用区域/坐标冒充战术阶段，
  **不得**复用 `Phase` 词（`#113`/P16 的同类处置）。
- **不改比赛生成**：跑位/决策、RNG、正式事件流协议、golden 全不动；
  `simulate()` 与 opt-in 路径事件流仍**逐字节相同**。
- **不新增引擎观测**：本 change 的侦察（`.scratch/notes/17b-recon-2026-09-30.md`）
  实测现有 sidecar 已够；若实现中确证缺某量，**另开 change**（引擎改动须自己的 gate），
  不在本 change 里夹带。
- **不产生 pass/fail**：报告是**诊断**不是**判据**（同 P36 报告期纪律）；
  行为门留给 `#18`。
- 不做完整 22 人 tracking 分析（P15A 契约：团队级 + 球附近局部）。
- 不改 viewer / 不做可视化（那是 `#22`）。
