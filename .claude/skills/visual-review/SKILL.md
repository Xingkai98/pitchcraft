# visual-review：引擎画面「像不像足球」的独立审阅回路

**为什么有它**：本仓的统计带（L1：射门/抢断/犯规…）**测不出「画面像不像足球」**——
P143r 实测「射门/抢断调到真实值、过全部统计门」的版本，**画面在用户眼里毫无变化**。
而「球员 87% 时间静止」这种**过程缺陷**，统计带看不见。所以要一条**看画面**的独立回路。

**核心纪律（踩过坑，别省）**：
1. **★ 先看后量——改移动层第一步是「渲轨迹图 + Read 它 + 写下看到的」，不是跑指标**
   （2026-10-05 用户第二次强调后加，见下「飞轮为什么空转」）。
2. **单帧会骗人、稀疏采样会骗人**：必须在**短窗（12s）内密采 6 帧**，才看得出「动没动」。
3. **喂给视觉模型的图本身要自证**：曾因把引擎的球（数组 `[x,y]`）当对象 `ball.x`，
   球**从来没画出来**，裁判连续多轮「看不到球」，主 session 误判成「球点太小」。
   → `render.mjs` 已统一口径、球画成**亮黄大点**；测试 `visual-review.test.mjs` 守这个。
4. **打分的必须与改代码的分离**（用户 2026-10-03 要求）：**主 session 改引擎，打分另起一个
   零上下文 agent**（paseo agent）。主 session 只读它的记录，不改它的分。
5. **运动指标别挑窗**：曾报「静止率 3%」实为**单窗（高活跃窗）**挑出来的，全 match 是 56%。
   → `motion-metrics.mjs` 跨**全部窗**算、报中位与样本数。
6. **★ 飞轮必须 real-anchored，且盯着最大缺口**（2026-10-05）：
   见下「飞轮为什么空转」。

## ★ 飞轮为什么空转（2026-10-05 定位，三版都栽在这）

P143r 三版（v1 / v2g-g3 / FB4）都是「指标变好、用户看不出」。事后定位到**飞轮的结构缺陷**：

- **缺陷 A（无损失函数）**：motion-metrics 并排报引擎数与真实数，但**没有"离真实多远"的标量**。
  → loop 就去优化「方向一致性 dir」——而 **main 的 dir 本来就 0.63≈真实 0.70（没信号）**；
  v2 分支把它从 0.80 降到 0.68 是**分支自己制造的问题**，对 main 毫无改善。
  **优化了一个 main 已过关的量。**
- **缺陷 B（最大缺口不在视野里）**：`gap`（两队重心间距=「机械分边」）＝引擎 **23.2m vs 真实 5.2m
  （skillcorner 主锚，4.42×；metrica 锚 8.3m→2.8×）——全场最大缺口之一**，
  而 motion-metrics **根本不输出它**，L1 统计带也不覆盖它。
  ⇒ **用户最不满的点，没有任何数字承载。**
- **缺陷 C（阈值与眼睛脱钩）**：motion-metrics 的「静止=位移<0.5m」= 真实位移（13.46m）的 **1/27**。
  FB4 位移 ~3.6m（真实 13.46m 的 **27%**）在此阈值下算「0% 静止」——**数字说在跑，眼睛说没动**。
  P143r 的裁判反馈「机械的移动」+ 用户「没变化」= 这个盲区的正确诊断。

### ★ 缺陷 D：**开发时从不看图**——三版的元缺陷（用户 2026-10-05 点破）

**我（主 session）在三版里只跑 `motion-metrics` 的数字，从不渲「球员轨迹图」。** 一渲就露馅：
`trajectory.mjs` 的引擎轨迹是**水平短线**（球员在各自车道上左右滑、横向冻结「铁轨感」），
真实是**一团纠缠的弧线**（球员跑向球/绕行/回追、**红蓝混在一起集中在中路**）。
而当时我引的**全部指标都是这个结构的弱代理**——最刺眼的是 FB4 把**横向 sd 从 0.37 抬到 1.34**，
指标报「改善」，实际只是**加了横向抖动**，轨迹仍不是弧线、队形仍未聚拢（看图即知）。

⇒ **纪律升格为「先看后量」**：改移动层 → **第一步 `trajectory.mjs` 渲 + Read + 写下看到的**，
**然后**才引 `like-football` 数字。本仓 CLAUDE.md 早有此律（**图能发现，数值能守护**）——
我在 P143r 违反了它。**能被算出来的量写成数值断言进 CI；发现问题的永远是眼睛。**

**⇒ 修法**：`trajectory.mjs`（**先看**）+ `like-football.mjs`（**后量**）成为飞轮的头；
`contact-sheet.mjs` 看跨窗形态；`gap`/`disp` 进主视野；「静止」改成 real-anchored 的 `disp/真实位移`。

## 流程（**先看后量**——步 0/1 不许跳）

0. **渲轨迹 + 看（★第一步，不是可选项）**：`trajectory.mjs <wasm> /tmp/t.png` → **主 session 自己 Read**，
   **用一句话写下看到的**（例：「球员是水平短线、红蓝各占半场」vs 真实「一团弧线、混在中路」）。
   这一步能发现指标看不见的**结构缺陷**（铁轨感 / 不聚拢 / 不追球）。见「飞轮为什么空转」缺陷 D。
1. **损失表**：`like-football.mjs <wasm>` → **距离**（越小越像）+ **最大缺口是哪量**。
   **优化目标 = 让距离降、让最大缺口往上排改**。别再去优化 main 已过关的量（dir）。
2. **跨窗渲图**：`contact-sheet.mjs`（形态是否每窗都在）+ `render.mjs`（短窗细看）。
3. **独立裁判**（paseo agent，零上下文）：给它 wasm + 口径，让它渲图 + `ask-vision.mjs` 判读 +
   按**固定 6 维**打分（见下），追加进 `RECORD.md`，**带全口径**（图路径/seed/t0/wasm sha8/原文）。
4. **决策**：**轨迹图（先看）+ 距离（后量）+ 像不像分（裁判）+ （另跑）L1 统计门**，一起看——
   **统计全绿 ≠ 画面像**，**方向一致性高 ≠ 画面像**，**横向 sd 变大 ≠ 动得像**（都见「飞轮为什么空转」）。

## 固定 6 维（每次必须全答，跨版可比）

1. 引擎相邻帧球员位置变化（几乎不变 / 有些 / 很大）
2. 真实相邻帧变化（对照）
3. 引擎球员分布（均匀铺满 / 聚在局部 / 机械分边）
4. 引擎红蓝是否交错（交错 / 半边各一 / 混合）
5. 引擎有无局部聚集（争抢/盯人/接应）（有 / 少 / 无）
6. **像不像真实足球（1–5）** + **最不像的一点**

## 已知盲区（如实带过，别掩盖）

- **传球/球权类改动，视觉回路测不到**：12s 窗平均仅 ~0.8 次传球，装不下「球在球员间流动」。
  P5（弹球 60%→10%）画面分纹丝不动。→ 这类改用**事件流探针**（弹球率/接球熵）。
- `motion-metrics` 的**方向一致性**区分度有限（本仓校准：main 0.63 / 真实 0.70，
  不如裁判自定义口径分得开）——**趋势可用，别当绝对门**。**它不该是优化目标**（main 已过关）。
- 视觉模型判读有噪声：同一张图重复判读可能跨 1 分；**不确定就重复判读 + 报一致性**。
- **`like-football` 的距离是「幅度量」的对数比均值，对「结构形态」敏感、对「事件内容」不敏感**
  （它用的都是队形/位移量，不含传球/射门）。事件层改动仍走事件流探针。

## 当前最大缺口（2026-10-05，main 实测——飞轮的优化靶）

**先看（轨迹图，一句话）**：引擎球员是**水平短线、红蓝各占半场、横向几乎冻结**；真实是
**一团纠缠的弧线、红蓝混在中路**。⇒ **核心结构缺陷 = 球员沿「车道」滑动、不跑向球、不聚拢。**

**后量（`like-football` 距离 0.85，main，锚=基线 skillcorner 20 场）**。逐量（引擎/真实）：
- **位移/窗 0.13×**（1.77m vs 13.46m）——**动没动**，最大缺口。**根在移动层结构**。
- **分边 gap 4.42×**（23.16m vs 5.24m）——**机械分边**。红队钉左/蓝队钉右。**用户一号抱怨。**
- 纵深 hd/ad 2.19×（40.1m vs 18.3m）——**队形太散**（也被 gap 带动）。
- 球距 1.46×、紧凑度 1.47×、宽度 1.14×——次一级。
⇒ **要「更像足球」，攻的是 disp（位移）+ gap（分边）+ hd/ad（纵深）**，不是 dir。

**轨迹图实测数字（`render-trajectories.mjs`，90s）**：引擎非门将**横向位移 sd 0.37m**，
真实 **5.36m**（**14×**）——「铁轨感」的量化。

**基准事实（防倒退）**：FB4 把距离 0.85→0.81（−5%），横向 sd 0.37→1.34（+260%），
**但轨迹图看：只是加了横向抖动，仍不是弧线、队形仍未聚拢**；且分边反而恶化（4.42→4.84×）。
⇒ **「sd 变大」骗过了指标，「看图」一眼拆穿**——正是「先看后量」的意义。
