# adversarial-explore：带对抗的探索回路

**为什么有它**：本仓反复栽的三类错，**都是「单视角验证」抓不到的**：

- **结论对但机制错**（`conclusion-right-mechanism-wrong`）——机制描述与代码不符，审阅只看结论就放过。
- **数字全绿、画面没变**（飞轮空转三版，见 `visual-review` skill 的「飞轮为什么空转」）。
- **必要性主张没试最简解**（`necessity-claims-need-the-simplest-competitor`）。

单线「实现 → 跑数字 → 下结论」必然漏网。所以要**多镜头 + 对抗**：候选由**独立 agent** 产出，数字与画面由**不同镜头的零上下文 agent** 独立复核与**试证伪**。

**实跑记录（2026-10-13）**：三条轴 `TRACK_X`(C1) / `MIX_X`(C3) / `SPREAD_X`(C4) + **4 个对抗镜**。

- **C1**：对抗层改了 4 处——算术实错（把「目标量」与「站位表量」相减）/ 低估「非系统性」/ 漏免责（判据基线自己就 5 窗反 2 次）/ 发现**距离标量有退化方向**（纯块配置距离 0.365 全场最低，画面却是两队叠在球上）。
- **C4**：判据镜**逐格复现、三条主张一条没证伪**；但指出「角球 4.83→14.48 炸了」这条**方向反了**——角球带 `[1,7]` 是 **guard band**，真实 ≈ **10.27/场**，基线 4.83 **低于**真实、14.48 反而更接近。
- **C3**：表全对、结论成立；但 ★「两根轴 = 同一根 `gain` 旋钮」**被证伪**——按公式挑**等 gain 的另一对** `(T=0.61, M=0.80)` 后，swarm 指标（dir/lat）统计同一、**结构量（分边差 5.5σ）与事件层（L1 破的带只共享 2 条）却对不上** ⇒ `gain` 是两轴的**共同分量、不是充分统计量**。**幸存的真主张**：缺口长在**站位表**（`default_lineup` 的 **29.82 m** 静态队间间距，与球无关）——该主张的证伪尝试**失败**。
- 证据：`.scratch/notes/p-form-{track,mix,spread}-x-2026-10-13/`。

**实跑记录（2026-10-14）**：两条轴 `FORM_CENTER_*`(C2) / **站位表压缩**(C5) + **4 个对抗镜**（每轴各一画面盲测 + 一判据镜）。

- **C2**：判据镜逐格复算**全对**、主结论（反向轴、两端无可用点）**成立**；但**证伪了子结论**「硬底 14.9 m / 可达区间 [9.4, 22.8]」——h=0 实测 **7.94 m**，κ 只在被扫的 `h∈[0.30,0.50]` 上 ≈0.849，**扩域后单调滑到 0.716**（「5 点拟合的常数」被外推）。另查出一条口径事实：**「真实分边 5.24 m」是继承值、本轴未验证**——同管线 Metrica = **8.32**（与入库基线逐位相同）⇒ 真实是**带**不是点。
- **C5（站位表压缩，第五条轴）**：候选报「无可行区间、不推荐落地」，判据镜**逐位复现它的每一个进入结论的读数**后判**成立**，并升级为**结构性必然**：基线整场同队最小间距 **2.137 m** 已低于引擎自己的扫掠地板 2.14 m，距 spacing 门只剩 **0.137 m（6.9%）** ⇒ 该门在此轴上是**开关不是尺子**。**画面盲测镜反过来推翻了候选自己的画面结论**：候选说「压缩后画面单调变差」，盲裁（不知道哪张是基线）把**基线排在最后**。
- 证据：`.scratch/notes/p-form-center{,-adversary}-2026-10-13/`、`.scratch/notes/p-table-compress-2026-10-14/`（含 `SYNTHESIS.md`）。

## 流程（四步；②③ 用 subagent，paseo 托管）

### ① 主 session「先看」+ 列候选

- `node tools/visual-review/trajectory.mjs <wasm> <out.png> [seed] [t0] [win]` 渲「引擎 vs 真实」**多窗**（多 `t0`，或 `contact-sheet`），**Read 完写下一句话**（不许跳）。
  ⚠️ **单窗图是高方差判据**（C3 判据镜实测：同一配置**跨窗直度波动 20×**）⇒ 图上排序常不可靠；判形态**必须多窗 + 配同窗客观量**。
- 读码定位机制——**算出结构性关系**（例：「两队共用同一常数 ⇒ 块心间距恒 = f(常数)，与球无关」），别只描述。
- 产出**候选杠杆清单**，**优先最简解**（改常数 > 改机制）。
- 用**该 worktree 现建的 wasm**（别拿旧实验产物；见 `stale-local-engine-wasm-false-red`）。

### ② 候选层（每候选一条轴 = 一个 agent，各自 worktree/分支隔离）

- 每轴扫 **≥3 个点**（基线 + 两侧），每点**从本 worktree 源码重建 wasm**。
- 每点跑**同一套面板**：`like-football` **距离 + 目标两根杆**、**L1 逐带实测值**（不是只报 9/9）、`spacing-sweep`、**轨迹 png**。
- 落盘：读数表（**口径齐全**：wasm sha + seed + 时长 + 源码状态）+ png + **它自己声称的因果机制**（供人打）+ **预注册**（先写下预测，再测）。

### ③ 对抗层（每候选 ≥2 个不同镜头，零上下文，并行）

- **画面盲测镜**：把候选的 png **改中性名**（A/B/C），**不告诉它哪张是哪档**，判「两队是否混在中路 / 更像真实 1–5」+ 排序。**只准看图、别猜参数**。
- **判据镜**：**自己重建 wasm、自己复算**全部读数（标出任何对不上的）+ **试证伪**候选的因果机制 + 查 **L1 带余量** / `spacing-sweep` / blast radius。**未能证伪的部分也要写**。

### ④ 主 session 综合

- 四条全过才进短名单：**距离↓ / 目标两根杆↓ / L1 不破 / 盲测说更像**。
- 对抗层修正过的条目**逐条记账**（原结论哪里被改）。

## 硬纪律

1. **先看后量**——第一步是渲图 + 看，不是跑指标。
2. **盲测**——画面裁判不许知道「哪张是哪档」。
3. **距离不是优化目标**——标量有**退化方向**（纯块配置距离最低、画面却是两队叠在球上）。必须配盲测图 + 结构量。
4. **口径齐全**——wasm sha + seed + 时长 + 源码状态。**同 wasm 哈希 ≠ 同一次实验**。
5. **换样本不换判据**；**改门是红线**（`DUR`/`STEP`/默认 seed 集/detector 阈值/统计带一律不动）。
6. **先预注册**再测（预测要能被实测打脸）。
7. **对抗镜自己重建、自己复算**（别信候选的数）。
8. **worktree 隔离**：一候选一 worktree。**别在主仓库那棵树跑引擎实验**——它可能不在 main、有未提交改动 ⇒ 读数不可比。
9. **环境**：用 **paseo agent**（不要用 Claude 自带 `Agent`/`Workflow`——paseo 会话里会被中断）。探针用完即删。
10. **guard band 的中心不是真实值**——仓里有些带（如角球 `[1,7]`）是「不塌缩 / 不爆炸」的**护栏**，不是拟合带。**越带 ≠ 变差**（真实角球 ≈10.27/场，基线 4.83 反而低于真实）。**引带判优劣前先查它是不是 guard。**
11. **「代数恒等式」≠「充分统计量」**——一个公式对**某个分量**精确成立，不代表它解释全部（`gain` 公式管得住 dir/lat，管不住结构量与事件层）。**越漂亮的统一，越要拿「等值但换轴」的反例去证伪**（按公式挑等值参数、换一根轴，看读数是否真一致）。
12. **盲测能推翻候选自己的画面结论**——候选读了图也可能判反（C5：候选说「画面单调变差」，盲裁把基线排最后）。常见病因是拿「覆盖范围 / 整齐度像不像」当唯一尺子。**判序：组织错误（两队各占半场、接触率 3% vs 真实 39%）> 尺度错误（团大团小）**。
13. **headline 要逐 seed + 逐锚查**——C5 的「三条同时进带」5-seed 均值距带上沿只差 **0.8%**：逐 seed **3/5**、15 seed **7/15**。**均值压线 = 掷硬币**，不能当成功证据。
14. **带宽定义能制造假成功**——同一读数，真实带取「两数据集 [min,max]」时成立，换**任一单锚**立刻消失。**报告必须写清用的是哪个带定义**，并给单锚下的判定。
15. **开轴前先量目标门的基线余量**——C5：spacing 门基线只剩 **0.137 m** ⇒ 该门在此轴上无区分度、任何有效改动必红（**开关不是尺子**）。先量余量，能省一整轮。
16. **候选自标为「未验证」的地方 = 对抗镜的头号目标**——C5 候选自己写了「这一步我没读调用条件去逐条核」，**那处恰好是它唯一被证伪的机制主张**。
17. **自写探针按 `p.id` 取人，不按下标**——`Game.players` 会**过滤已罚下者** ⇒ **下标 ≠ id**（`match-metrics.js` 自身按 `p.id` 取、安全；`f.players[i]` 写法会失真）。

## 已知盲区（如实带过，别掩盖）

- 盲测用的是**轨迹累积图**，「帧间位移」只能反推；**单窗图跨窗波动可达 20×**（实测）⇒ A/B 排序常不可靠——**分不太开时必须报不确定**，结论只用**聚合指标 + 多窗**。
- 判据镜与候选**同工具同方法**，不是完全独立：它抓**口径 / 夸大 / 算术**，抓不到「整套方法都错」。
- 对抗层**不能替代最终人眼验收**：用户看的是 viewer（5min/seed42），不是 90s 探针窗（见 `viewer-scale-vs-probe-scale`）。
- **盲测用的图自带裁切/采样偏置**（C5 盲测镜自报）：contact sheet **只采每窗头 ~12 s**；渲染视窗只覆盖中圈附近 **100×65 m**（**底线/边线内容被裁掉**）；部分档位缺 contact sheet。⇒ 盲测结论只对「视窗内 + 该时段」成立，别推广成整场。
- 成本：每候选 = 1 候选 agent + ≥2 对抗 agent。**先拿一条轴把流程跑通**，再加轴。
