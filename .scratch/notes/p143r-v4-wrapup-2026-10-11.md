## 1. ★ 两条真不变量：修 + 根因订正

### 1.1 `p53_same_team_spacing_holds_between_anchors`

**落地报告 §D4 的原解释（「P34 carrier 拍内扫掠豁免」）被探针证伪。** 实测（`rescan`/`p53_probe`）：

- 违规 = **seed 8 t=719s，pair id2/id4，d=1.765m，`sk_raw=−0.191` → `kind=START`**——
  最近点在**线段起点**，不是拍内中点；
- 拍内扫掠（`sweep_pair_lateral`）遇到「起点已 <阈值」本就**早返回**（「起点不可动」），
  **与 carrier 是否豁免无关**。

**真机制**（事件 dump 实证）：t=717 一次传球（`subject 10 → 4`，落点 `(0.2761,0.4906)`）；
飞行期（t=717→718）**无球 mover id2 跑进了该落点 1.765m 内**；t=719 结算 `PassCaught` 时
`finalize_highlight` 把 id4 直接放到落点 → **下一拍 carrier 的起点**（=`st.pos[4]`）距 id2 仅
1.765m，而**起点不可动** ⇒ 整拍残留。即：**`finalize_highlight` 的参与者位置写回绕过了同队分离**。

**修**（`lib.rs` `PassCaught` 结算处）：
```rust
let (rx, ry) = separate_target_point(st, receiver, catch_pos);
st.pos[receiver] = (rx, ry); st.last_ball/carrier_from = ...
```
即用**既有**单点分离把接球者从**当前**队友位置推开（队友冻结、只推接球者）。

**验证**：`p53` 绿（seed 8 最坏 1.765m → **2.133m**）；**L1 仍 4/5**（未破射门几何）。
**不是缩守卫**——修的是真实的写路径缺口；非 carrier 对的守卫原样保留。

### 1.2 `realism::l2_cross_event_invariants`（射门落点）

**落地报告 §7 说「`y2` 越界」——错。** 探针（`shot_probe` + 定向变异）定位：违例是
**`x2` 越门线**（应 0.02，实 0.0192/0.0194），**不是 `y2`**。
```
seed=1  t=4552.000 subj=14 result=off_target x2=0.0192 y2=0.4400 detail=header       → X2_BAD
seed=42 t=...      subj=..   result=saved      x2=0.0194 y2=...    detail=undefined    → X2_BAD
```
⚠️ **不是「唯一违例=header」**（收尾订正过窄）：违例**两条射门路径都会出**——
seed 1 是 **header**（`emit_header_shot`），seed 42 是 **open-play saved 射门**（`detail=undefined`，
走 `emit_shot_highlight`）。根因：`separate_target_point` 为求 2.2m 分离余量把射门终点沿 x
推离门线——但对已 >2.0m detector 阈值的 pair 是多余的。

**修**：**两条**射门路径（`emit_shot_highlight` / `emit_header_shot`）分离后都把 `x2` 夹回
门线（只保留 y 方向分离）——正因为两条路径**都**能违例，才必须两处都夹。
**验证**：`rescan shot 1..=120` **零违例**；定向变异（只撤一条路径的夹回）→ 对应 seed **当场红**
（撤 header → seed 1；撤非 header → seed 42），证明两条夹回都是必要条件。

## 6. 已知记录（审阅 P2-6 / P2-7）

- **P2-6（`p28` 断言语义弱化，已注释、非静默——给用户知情）**：`p28_action_deadline_formula` 的
  两条**方向断言**由严 `<` 放宽到 `<=`（`DANGER_URGENCY` / `PRESSURE_URGENCY`）。因
  `BASE_ACTION_DEADLINE_TICKS == MIN == 2` 后 `deadline` 被地板吃掉（escape=0 时恒 2），严 `<`
  **不可达**——放宽是「地板吃掉压缩」的**必然后果**，代码里已注释。代价：这两条方向断言的
  **判别力下降**（不再是严格不等式）。**给用户知情**（用户级？否——纯测试断言，不改引擎行为）。
- **P2-7（三条 C 类带余量薄，建议后续收紧）**：`p16::state_snapshot_frozen`（实测 **28.5%** vs 界 33%）、
  `p124::defensive_intents_are_sparse`（**20.5%** vs 界 25%）、`p124::window_features_are_mechanically_tied_to_shots`
