## 0. 本轮最重要的教训：**读代码连错两次，都是探针纠正的**

| 读码得出的推断 | 实测结果 |
|---|---|
| 「松散球走 `advance_loose` 早退分支，**没有 mover**」 | ❌ **错**。`advance_loose` 末尾显式 push `action: "chase"` 的 mover |
| 「`chase` 只在门球预判/角球 battle 路径上」 | ❌ **错**。普通松散球**也**产 `chase` |
| 「Q3『丢球后谁做了什么』答不了」 | ❌ **错**。**可答**——但**只在 46.7% 的丢球上**（见 §3） |

根因：我按「主目标循环（`targets`/`actions`/`beat_movers`）」判断有无动作，

这是本仓 `[[spec-verify-by-probe]]` 的又一实例——**读代码会错**。

⚠️ **第三轮又添两例（grill 抓到、本人独立复现）**：修完上两条后写出的 §3，

**「实跑得到数字」还不够，还得核对这个数字代表什么**；

## 3. Q3：追球者**可见，但只在产 loose beat 的那一半丢球上**

> ⚠️ **本节初版的口径是错的，已按 grill 的发现 + 本人独立复现（30 seed）重写。**
> 初版结论（「43% 两队都追」「27% 无追球者」）**建立在两个混淆上**，见 §3.3。

### 3.1 修正后的权威数字（30 seed，探针 v4）

**按争抢成因切开**（`contest_started` → 之后到 `contest_ended` 之间有无 loose beat）：

```text
成因                  争抢数   有loose beat   时长0(无loose beat)
  interception_loose     729          **0**           729     ← 36%，**一次都不产**
  delivery_loose         645          307            338
  tackle_loose           434          434              0
  pass_lost              212          198             14
  shot_rebound             7            7              0
  ------------------------------------------------------------
  合计                  2027          946           1081   （46.7% 产 loose beat）
```

**松散球段**（连续 loose beat 串）**按重开准备期拆开**：

```text
                段数   两队都追   只一队   none    平均时长(beat)
  开球期        946     541       405      0      3.02      ← none 恒 0
  准备期        379       0         0    379      6.28      ← 全是「无追球者」
```

`chase` mover 共 **3091 个，全部落在开球期**；准备期 **0 个**。

### 3.2 结论（修正后）

- **`interception_loose`（36% 的丢球，且是 P17A 的 A2 主因）完全不产 loose beat**——
  184/184（8 seed）、**729/729（30 seed）**。
  ⇒ 诊断器**在这类丢球上看不到任何 mover**。
- **在产 loose beat 的开球期丢球里**：两队都追 **57.2%**、只一队追 **42.8%**、无追球者 **0%**。

⇒ **Q3 的能力必须降级为**：「在**产 loose beat 的 46.7%** 丢球上可答；其余 53.3%
（以 `interception_loose` 为主）**只看得到拾取者与归属，看不到追逐过程**」。

### 3.3 初版错在哪（**如实记录**）

| 初版说法 | 实情 |
|---|---|
| 「43% 两队都追」 | ❌ **混合口径的产物**：开球期 57.2% 与准备期 0% 混合成 149/343=43%。**43% 不存在于任何单一情形里** |
| 「27% 无追球者」 | ❌ **全部是重开准备期**（角球/界外球发球前的走位等待，球钉在发球点）——**不是「丢球后没人追」**，也**不是缺陷** |
| 「343 段是**下界**」 | ⚠️ 方向对但**只对了一半**：同拍拾取确实不产 loose beat（→ 低估），但**准备期段又被算了进来**（→ 高估）。**净效果让比例失真**，不能只说「下界」 |

**根因**：判据 `beat.ball.loose == true` 的语义不是「松散球」，而是
「**球不在任何球员脚下**」——它**同时覆盖重开准备期**（`advance_restart_prep` 也产 `loose:true`）。
这是**判据的口径错误**，不是笔误。

### 3.4 ⇒ 对判据的修正（供设计定死）

松散球判据应为 **`beat.ball.loose && !in_restart_window`**，
其中 `in_restart_window` 取 `restart_sequences` 的 `[start_t, taken_t)`。

⚠️ **两个 946 的口径不同**（「产 loose beat 的争抢数」与「开球期段数」），
数值相等**属巧合**，**不得混用**（本仓 `[[probe-records-must-carry-their-caliber]]`）。

## 4. Q2：射门有意图相，传球没有

| 信号 | 有没有 | 出处 |
|---|---|---|
| `shot_setup` 全相（`in_window`/`window_ticks`/`drive_ticks_left`/`committed`/`entry_pressure_bucket`） | ✅ | P124 `intent_snapshots`（逐 tick） |
| `DefensiveIntent`（防守动作类型 + 防守者 id） | ✅ | P124（**稀疏**，每次机会一条） |
| `pressure_state_ticks` | ✅ | P124 |
| **传球当时的候选/选择集** | ❌ | 引擎私有打分，sidecar 无出口 |
| **射门时门将位置** | ✅ | `Event::keeper_x/keeper_y`（射门 :3815 / 头球射门 :5041 都设）+ `StateSnapshot.pos[0]/[21]` |
| **射门者的起脚位置** | ✅ | `Event::{x,y}`（shot 的 subject 位置） |
| 射门当时的 **hazard 值本身** | ❌ | 引擎私有打分；**但其输入部分可得**（`entry_pressure_bucket` / `pressure_state_ticks` / 双方位置） |

⇒ 报告须**分列**：射门可以说「起脚窗口已开 N 拍 / 是否 committed / 入窗压力档 /
**门将当时在哪**」；传球**只能说结果**，不得写成「因为…所以传了」。

> ⚠️ **本表初版把「门将位置」错列为不可得（2026-09-30 grill 抓到，已更正）**。
> 见 design §2 的同一处更正与教训。

⚠️ **P124 的教训复用**：`pressure_*` 对 phase 无判别力（AUC 0.372）——
用它做归因时**不得**声称能区分阶段。

## 5. Q4：四类归因的证据盘点

| 归因类别 | 证据 | 现状 |
|---|---|---|
| **阶段转换** | `EpisodeStartReason` / `EpisodeEndReason` / `ContestStartReason`（6 员） | ⚠️ 能报**事件级转换**，**不能报 phase**（三档判不了） |

| **动作选择** | `Mover.action` 串（闭集恰为 `{chase, close_down, run, keeper_return}`） | ⚠️ 有，但 `close_down` **不恒追球**——见下 |

## 6. 对 #17B 设计的直接影响

1. **必须显式声明证据边界**：逐条标注结论落在哪个 sidecar 字段，
   并区分「**观测到的事实**」与「**机制假设**」（本仓反「假覆盖」纪律）。
2. **Q3 的能力降级**（§3.2）：只在 **46.7%** 的丢球上可答；`interception_loose`（36%）
   **不产 loose beat**，须在证据表里写明。**松散球判据须排除重开准备期**（§3.4）。
3. **Q4 的「阶段转换」改口径**：报**事件级转换**，**不得**复用 `Phase` 词。
4. **Q2 分列射门/传球**；射门侧**门将位置可得**（§4 表）。
5. 每条结论都要能落到**可回放定位**（seed / 时间 / episode / 事件下标）——复用 P17A 形状。
6. ⚠️ **`close_down` 不恒为「追球」**：其靶点按 `TransitionSource` 分流
   （`Tackle` → 球位；`SaveCaught` → 新进攻方前插球员）。实测 **188/513（8 seed）**
   的 `close_down` 终点距球 > 5.25 m ⇒ 它们在**追人**。报告**不得**把
   `chase` 与 `close_down` 并称「追球者」——须分类或分开报。
6. **接应结构**须先定口径（或明确降级为 `unknown`），**不得**拿重心当代理冒充。
