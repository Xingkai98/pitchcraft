## 0. 本轮最重要的教训：**读代码连错两次，都是探针纠正的**

| 读码得出的推断 | 实测结果 |
|---|---|
| 「松散球走 `advance_loose` 早退分支，**没有 mover**」 | ❌ **错**。`advance_loose` 末尾显式 push `action: "chase"` 的 mover。8 seed 实测 **844 个 `chase`** |
| 「`chase` 只在门球预判/角球 battle 路径上」 | ❌ **错**。普通松散球**也**产 `chase` |
| 「Q3『丢球后谁做了什么』答不了」 | ❌ **错**。**可答**——见 §3 |

根因：我按「主目标循环（`targets`/`actions`/`beat_movers`）」判断有无动作，
而 `advance_loose` **自己**构造 mover 并推入 beat，**绕开了主循环**。
这是本仓 `[[spec-verify-by-probe]]` 的又一实例——**读代码会错**。

## 3. Q3：追球者**可见**（实测数据）

探针 v2/v3（8 seed，逐 beat / 逐松散球 episode）：

```text
beat 总数 / 含 movers             = 42910 / 18644
松散球 beat（beat.ball.loose）     = 1447
  其中 mover action = chase       = 844
  其中 mover action = close_down  = 513
  追球者到球距离(norm) P50=0.0119  P90=0.1051   （样本 1357）

松散球 episode（连续 loose beat 段）  = 343
  两队都追过                          = 149  (43%)
  只有一队追                          = 102  (30%)
  无追球者 mover                      =  92  (27%)
  平均时长                            = 4.20 beat（TICK_SECONDS=1s ⇒ 秒）
  时长分布(beat: 段数)                 = {1:1, 3:287, 4:16, 5:1, 6:1, 7:3, 10:1, 13:7, 14:10, 15:16}
争抢成因(contest_started.detail)      = {interception_loose:184, delivery_loose:177,
                                        tackle_loose:116, pass_lost:52, shot_rebound:2}
```

⇒ **#17B 可以如实报告**：这次丢球后，**哪几号球员**以 `chase`/`close_down` 向球移动、
**是否两队都有人追**（43% 是）、持续了几拍、最后由谁拾取。

⚠️ **探针的已知局限（如实记录）**：
- 用 `beat.ball.loose == true` 识别松散球 ⇒ **同拍拾取**（A2 的「52.7% 同 tick 收束」）
  可能**不产生 loose beat**，故本表的 343 段是**下界**；
- 「27% 无追球者」的成因**未查**（可能是 hold 相、或同拍拾取的边界）——
  设计若依赖该比例，须先补探针。

## 4. Q2：射门有意图相，传球没有

| 信号 | 有没有 | 出处 |
|---|---|---|
| `shot_setup` 全相（`in_window`/`window_ticks`/`drive_ticks_left`/`committed`/`entry_pressure_bucket`） | ✅ | P124 `intent_snapshots`（逐 tick） |
| `DefensiveIntent`（防守动作类型 + 防守者 id） | ✅ | P124（**稀疏**，每次机会一条） |
| `pressure_state_ticks` | ✅ | P124 |
| **传球当时的候选/选择集** | ❌ | 引擎私有打分，sidecar 无出口 |
| 射门当时的 hazard / 门将位置 | ❌ | 同上 |

⇒ 报告须**分列**：射门可以说「起脚窗口已开 N 拍 / 是否 committed / 入窗压力档」；
传球**只能说结果**，不得写成「因为…所以传了」。

⚠️ **P124 的教训复用**：`pressure_*` 对 phase 无判别力（AUC 0.372）——
用它做归因时**不得**声称能区分阶段。

## 5. Q4：四类归因的证据盘点

| 归因类别 | 证据 | 现状 |
|---|---|---|
| **阶段转换** | `EpisodeStartReason` / `EpisodeEndReason` / `ContestStartReason`（6 员） | ⚠️ 能报**事件级转换**，**不能报 phase**（三档判不了） |
| **接应结构** | `state_snapshots.pos`（22 人逐 tick） | ⚠️ 位置全有，但**「可接应队友」无固化口径**（待核） |
| **压力判断** | `pressure_state_ticks` + `DefensiveIntent` | ✅ 有；判别力弱（P124），措辞须收敛 |
| **动作选择** | `Mover.action` 串 | ✅ 有（含松散球 `chase`，见 §3） |

## 6. 对 #17B 设计的直接影响

1. **必须显式声明证据边界**：逐条标注结论落在哪个 sidecar 字段，
   并区分「**观测到的事实**」与「**机制假设**」（本仓反「假覆盖」纪律）。
2. **Q3 可正面回答**（§3），但须写明上表的**两个已知局限**。
3. **Q4 的「阶段转换」改口径**：报**事件级转换**，**不得**复用 `Phase` 词。
4. **Q2 分列射门/传球**。
5. 每条结论都要能落到**可回放定位**（seed / 时间 / episode / 事件下标）——复用 P17A 形状。
6. **接应结构**须先定口径（或明确降级为 `unknown`），**不得**拿重心当代理冒充。
