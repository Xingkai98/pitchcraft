### 3.2 主张 2：spacing 预算 —— **确认，并查明「坪」的机制**

我独立写的探针（`probe/myspacing.mjs`，按 `p.id` 取人，0.5 s 步长，整场 5400 s）：

```
base  : 整场同队最小间距 = 2.1372 m  pair=(18,15) t=2191.5s
        最小 8 对: 18,15=2.1372  19,18=2.1380  19,17=2.1394  15,12=2.1401

```

**我扫了全部五个点，候选的每一个数、每一个 pair、每一个时刻都逐位复现** ✅：

| 点 | 整场最小同队间距 | 最紧 pair @ 时刻 | 相对 base |
|---|---|---|---|
| base `S_Y=1.3` | **2.1372 m** | (18,15) @ 2191.5 s | — |
| `S_Y=1.1` | 2.1383 m | (2,4) @ 931.5 s | +0.0011 |
| `S_Y=0.85` | **2.1365 m** | (15,12) @ 2060.5 s | **−0.0007** |

| `S_Y=0.6` | **2.0616 m** | (14,13) @ 1685.5 s | −0.0756（仍 **> detector 阈值 2.0**）|

- **「坪」确认**：base 最小的 8 对落在 `2.1372–2.1421`（跨度 0.005 m），**不是一对**。
  且**「最紧对」的身份在每个点都换人**（18,15 → 2,4 → 15,12 → 1,4 → 14,13）——这本身就是「坪」的直接证据，
  也是为什么「候选对某个特定 pair 做的恒等论证」不可能是通用机制（见下）。
- **我补的机制**：`engine/src/lib.rs:741` `pub const SAME_TEAM_MIN_DIST_M: f64 = 2.2;` + `separate_pair_m()`
  把同队间距推到**恰为 2.2 m**（`if d >= min_dist_m { return }`，只有 d<2.2 才推开）。
  实测地板 2.137 m = **目标分离 2.2 m 在实现位置上的过冲**。⇒ 地板由**分离机械**决定，**与队形宽度正交**，
  这正是「压 y 不吃 budget」的原因，也是候选那句「不是通用否决项」的**真机制**（候选给了现象与一个 `base.y` 恒等论证，但没点出 `SAME_TEAM_MIN_DIST_M`）。
- **边界订正**：候选说「本轴对 (2,4) 恒等（两者 `base.y` 都是 0.5）」——但 base 的最紧对是 **(18,15)**，`base.y` = 0.7 / 0.4（**不相等**），
  它们在**动态遭遇**中贴到 2.1372（名义间距 32 m）。所以「紧对是 `base.y` 相等的对」这个论证**只对 1.1 点成立**（那时最紧对恰好是 (2,4)），
  不是一般机制。**结论对、理由是特例。**（这解释了为什么 `S_Y` 一变「最紧对」就换名字——因为它本来就是个坪。）
