**这条轴不是「分边」的杠杆，它是反向的**——把两队块心**对称收拢**会让分边**单调变大**

## 3. ★ 与预注册的偏差（**必须明确** —— 任务书要求）

### 3.1 我的预注册预测错了，错在哪一行

`PREDICTION.md` 写于跑任何读数**之前**。核心预测 P1/P1b：

> 分边随收拢**下降**（19.20 → ~16.2 → ~12.8），且在中心重合处（0.50/0.50）有 floor ≈ 10 m。

**实测**：收拢方向上分边**上升**（19.20 → 20.17 → 21.56 → 22.49），中心重合处是**峰值** 22.49 而非谷值。

**错误定位（可核到行）**：预注册 §1 里我写

> 旧式那半：`Δtx_旧 = center_home − center_away = −2e`

**这一行是错的**。`tx_旧 = base.x + 球侧平移 + 压上` —— **它里面根本没有 `center0`**，
所以主客相减得的是**站位表本身**的间距 `mean(base_away) − mean(base_home) = 0.642 − 0.358 = 0.284`，
**与 `FORM_CENTER_*` 无关、是个常数**。我把它误当成了随收拢而变小的量。
修好这一项后模型立刻反向（§3.2），且**与实测吻合到 1–2%**。

### 3.2 修正后的解析律（本报告的核心产出）

用 `default_lineup` 的外场 `base.x` 均值（主 **0.358**、客 **0.642**），令 `h = FORM_CENTER_HOME`
（客 = `1 − h`），展开 `tx2 = 0.5·tx_旧 + 0.5·block_tx` 对**全队取均值**：

```
mean(tx2)_home = 0.3222 + 0.25·ball − 0.15·h
mean(tx2)_away = 0.4278 + 0.25·ball + 0.15·h        （球项相同 ⇒ 相减抵消）

⇒ 目标点 x 间距 = 0.1056 + 0.3·h     （归一化）
⇒ 分边 ≈ 105 × (0.1056 + 0.3·h) × κ ,  κ ≈ 0.85（目标点口径 vs 实测重心口径的系统差）
```

**核对（κ 由实测/解析之比得到，理论上应≈常数）**：

| `h` | 解析分边（m） | 实测 5-seed（m） | κ |
|---|---|---|---|
| 0.30 | 20.54 | 17.29 | 0.842 |
| **0.358** | **22.37** | **19.20** | **0.858** |
| 0.40 | 23.69 | 20.17 | 0.852 |
| 0.45 | 25.26 | 21.56 | 0.853 |
| 0.50 | 26.84 | 22.49 | 0.838 |

**κ = 0.849 ± 0.007（5 点，跨 ±0.20 的配置范围）** —— 一个五点、跨全部扫描区的线性律，
**且基线的 κ 是被预注册的天真模型错判的那一点**。这条律的三个直接推论：

1. **∂分边/∂`FORM_CENTER_HOME` = +0.85 × 105 × 0.3 ≈ +27 m/单位**（即每 +0.10 → **+2.7 m**）。
   收拢（`h` ↑）**必然让分边变大**。
2. **要压小分边只能把 `h` 往下推**（0.30/0.70 → 17.29，−9.9%）。代价见 §2.2（2 条红）。
3. **整条轴的可达范围够不着真实**：`h ∈ [0, 0.5]`（主队名义块心在自己半场，最"疯狂"的
   `h=0` = 块心压到自家门线）⇒ 分边 ∈ **[9.4, 22.8] m（实测口径）**，真实 **5.24** 在范围之外；
   而**像样的足球范围 `h ∈ [0.25, 0.45]` 只覆盖 ~5 m**（16–21 m），要够到真实需要 ~11 m。

### 3.3 为什么 §3.2 的律可信（不是事后拟合）

- **κ 在 5 个点上稳定到 ±0.8%**，而这 5 点跨越了 5-seed 聚合 + 两套补充配置。
- **逐帧探针（3 个互不相干的窗）**独立确认排序（§2.1 下表），且 `Δy`（横向分量）恒 ≈ 0.1–0.4 m
  ⇒ 「分边」**几乎 100% 是沿进攻轴的块间距**（与 C1 §1.3 的结论同）。
- 机制可指认：`mean(block_tx) = 0.2·center0 + 0.8·mean(base.x)` —— **块均值的 80% 由站位表定**，
  把 `center0` 往中间挪，块心只挪 20% 的距离；同时**块内铺开的锚点 `(base.x − center0)` 反向放大**
  （系数 −0.8），净效果是**位移方向反了**（`0.5 − 0.8 = −0.3`）。
  换句话说：`FORM_CENTER_*` 在公式里**不是"球队站哪里"**，它是**随球牵引的锚点**，
  同时兼任**铺开基准**；这两个角色在收拢时**互相抵消并反超**。

## 5. 推荐 + 下一步

### 推荐：**`FORM_CENTER_HOME = 0.358` / `FORM_CENTER_AWAY = 0.642` 保持不动。**

理由（按重要性）：

1. **符号反了**：要它帮分边，就得**把两队块心拉开**（0.30/0.70 → −9.9%）；按任务书的**收拢**
   方向走，分边**单调变差**（+5% / +12% / +17%），且画面更 rail（§3.5）。
2. **收益天花板太低**：整条轴（`h ∈ [0, 0.5]`）的分边范围只有 **[9.4, 22.8] m**，
   真实 5.24 在范围外；**像样的足球范围只覆盖 ~5 m**，要够到真实需要 ~11 m。
   ⇒ 与 `FORM_TRACK_X`（C1，封顶 11.39 m）**同一个天花板**、同一个原因：
   `FORM_MIX_X = 0.5` 把**一半权重**压在**与球无关**的站位表间距上
   （`0.5 × 0.284 × 105 = 14.9 m`），**`FORM_CENTER_*` 碰不到这半**。
3. **代价在两端都付不起**：0.30/0.70 破 2 条（含**主客进球方向反转**）；0.40/0.60 破 1 条；
   0.45/0.55 破 2 条（含禁区内进球占比 0.6853 vs 下界 0.72）；0.50/0.50 破 4 条 + spacing 门。
4. **距离标量再一次骗人**：0.30/0.70 的距离 **0.504 是全场最低**，而它有 2 条 L1 红 + 主客反转。
   不要把 0.504 当"更接近真实"。

### 给主 session 的轴级判断（**本轴已被证否，与 C1/C3/C4 合起来的第四根**）

C1 / C3 / C4 / C2 四根轴现在各自独立地撞在**同一堵墙**上：

> `tx2 = 0.5·tx_旧 + 0.5·block_tx`，而 `tx_旧` 完全由 `default_lineup()` 的 **`base.x` 站位表**决定
> ⇒ 分边有一条 **~14.9 m 的硬底**（`0.5 × 0.284 × 105`），**任何不动 `base.x` 或 `FORM_MIX_X` 的轴都碰不到它**。

⇒ 若还要在「分边」上继续，**唯一的入口是站位表本身（`default_lineup` 的 `base.x`）或 `FORM_MIX_X`**；
C3 已经证过「这套轴系里没有『低 gain + 小分边』」——那正好把选择收敛到**站位表**。
⚠️ 但按 `like-football` 头注释与 skill 的记录，分边**有退化方向**（两队叠到球上 ⇒ 距离最低、画面最差），
**动站位表时必须配盲测图 + 结构量（`mix`/`ballDist`/`spacing`），不能只看这个标量。**

### 若有人仍要试这根轴

唯一有点意思的方向是**拉开**（`h < 0.358`），但：① 收益 −9.9% 换 2 条 L1 红 + 主客方向反转；
② 它"有效"的机制是 `(base.x − center0)` 锚点解耦的**算术副作用**，不是足球语义
（把主队名义块心往自家半场挪，反而让主队球员**整体前压**）。**不建议。**
