## 1. 我对 BRIEF §3 解析模型的独立复核

**结论：核心公式对；变体 A 那一行算错；两处该写没写的非线性（防线 clamp）会实质改变结论落点。**

### 1.1 同意的部分（我逐项重推，代数一致）

`间距_target = (1−M)·Δb + M·[Δc·(1−T) + S·(Δb − Δc)]`，M=0.5 / T=0.5 / S=0.8。

抵消项我逐条核过，**都对**：
- `shift = (ball−0.5)·0.06` 两队同式 ⇒ 差里消掉；
- `press`：一次进攻一次防守时，`attack_dir·press` 对两队**同号**（主 +P / 客 (−1)(−P)=+P）⇒ 消掉；
- `FORM_CENTER_OFFSET`：同理同号（主攻时两队都得 +OFF）⇒ 消掉。
⇒ **差里确实不含球**，BRIEF 这条成立。

- **变体 C 复核为真**：Δb = Δc = −0.284c ⇒ `0.5·(−0.284c) + 0.5·[0.5·(−0.284c) + 0.8·0] = −0.213c`
  ⇒ ×105 = **22.37c**，与 BRIEF 逐位相同。✔
- 交叉验算：我另写 `zz_target_model.mjs` 把 `formation_target` 的 x 分支**逐字重实现**（含 `base`/`shift`/`press`/`is_defender` 的 clamp），
  在 c=1 且**关掉防线 clamp** 时给出 22.37 m —— 与 §3 公式吻合，说明我对 §3 的理解没跑偏。

### 1.2 不同意的部分

**(1) 变体 A 那一行的算式是错的（BRIEF 自己也标了「自己复核符号」）。**

BRIEF 写 `间距 = 4.47 + 26.84·(1−c)`。它在 c=1 给出 **4.47**，但 c=1 时 A ≡ C，
真值必须是 **22.37**。正确式（我推 + 数值模型都同）：

```
间距_A = 0.0426 − 0.2556c      ⇒ ×105 = |4.47 − 26.84c| m
```

即 **A 的间距在 c ≈ 0.167 处穿零、符号翻转**（压缩过头后两队块心在 x 上互换了相对位置）。
c=0 时它给 4.47 m 但**方向是反的**，不是「压到 4.47」。

**(2) §3 漏掉了 `is_defender` 的 clamp —— 而它正是「实测/预测 = 0.858」的主要来源。**

`lib.rs:3461-3465`：防线球员的 `tx` **不是** `base.0 + shift + attack_dir·press`，而是

```rust
tx = if home { tx_full.min(ball.0).max(base.0) } else { tx_full.max(ball.0).min(base.0) }
```

（home 的 `tx_full = base.0 + shift + push + press`，`push = |ball.x − ownGoal|·0.12`。）
把这段加进模型后：

| | §3（无 clamp） | 我的模型（含 clamp） | 实测（like-football 5 seed） |
|---|---|---|---|
| c=1 目标间距 | 22.37 m | **19.83 m** | **19.20 m** |

⇒ BRIEF 说的「基线实测/目标 = 19.20/22.37 = 0.858」**不是**「动力学折损」，
而是 **0.885 = 防线 clamp（22.37→19.83）** + **0.968 = 动力学/抖动残差（19.83→19.20）**。
这条分解很重要，因为 **clamp 的强度随 c 变**（见下），而动力学残差基本不变 ⇒ **不能用常数 0.858 外推**。
BRIEF 自己在 hd 上标了 `fitted-ratio-constant-only-holds-in-scan-region` 的警告，gap 上没标，我把它补上。

**clamp 为什么会随 c 变**：home 防线的下限是 `base.0`、上限是 `ball.x`。
表压缩把 `base.0` 从 0.14–0.20 抬到 0.35–0.41（c=0.45）⇒
① 下限抬高（防线被钉得更靠前，**压缩 home 的队均 x 幅度**）；
② 上限 `ball.x` 开始频繁成为绑定约束（`tx_full > ball.x` 当 `ball < (base.0−0.05)/0.82`，
阈值从 c=1 的 ~0.134 抬到 c=0.45 的 ~0.362）——**球在 0.14–0.36 区间时，home 防线被 clamp 到「正好站在球的 x 上」**，
这是一个**基线不存在的新行为**，且 `home line.x ≤ ball.x` 这条注释承诺的不变量在 `base.0 > ball.x` 时**被破坏**（`max(base.0)` 在最后）。

**(3) hd 的「静态跨距」不是 hd 的预测子。** BRIEF 用 `39.10/46.6 = 0.839`。
但 46.6 m 是**表本身的 q10–q90**，而目标层还要过 `S·(base−center0)` + 混合，
我的模型在 c=1 给 `hd_target = 38.76`，**实测 39.10 ⇒ 比值 1.009 ≈ 1**。
⇒ hd 应当**直接用目标跨距预测，不是乘 0.839**。BRIEF 在这点上也给了警告（很好），但选错了基线量。

### 1.3 我修正后的预测子（写进 §2）

- **gap_实测 ≈ 0.968 × gap_目标(含 clamp)**（0.968 由 c=1 标定：19.20/19.83）
- **hd_实测 ≈ 1.01 × hd_目标**（由 c=1 标定：39.10/38.76）
- **width 与 c 无关**（模型给常数 49.4 vs 实测 49.73，差 0.7%）——与 BRIEF 的「内置对照」一致，**我同意**
- **spread**：模型的 c=1 值是 19.8，实测 20.83（比 1.05）。spread 含**不随 c 变的 y 分量** ⇒ 只能降到 ~14 附近就到底（实测真实锚 12.76）

### 2.2 带穿越（判「能不能落进真实带」的那句话）

真实锚 = 两个数据集的 **[min, max]**：gap 带 **[5.24, 8.32]**、hd 带 **[18.31, 25.94]**。

| 变体 | gap ∈ 带 的 c 区间 | hd ∈ 带 的 c 区间 | 交集 |
|---|---|---|---|
| **C**（主口径） | **[0.345, 0.490]** | [0.505, 0.689] | **空**（缝宽 0.015） |
| **A**（对照） | **[0.454, 0.579]** | [0.505, 0.689] | **[0.505, 0.579]** ← **非空** |

⇒ **预注册的两条 headline**：

1. **变体 C：BRIEF 的「两根带不能同时满足」结论成立**，但**落点不同**：
   我预测 c* ≈ **0.49**（BRIEF 说 0.45），且原因是「gap 被防线 clamp 压得更快」而非「线性比 0.858」。
   最接近的双擦点：**c = 0.50 ⇒ gap ≈ 8.4（超出上沿 8.32 约 1%）、hd ≈ 18.4（贴着下沿 18.31）**。
2. **变体 A：我预测「两根杆能同时落进带内」，c ≈ 0.51–0.58，推荐点 c = 0.55**
   （预测 gap 7.7 ∈ [5.24,8.32] ✔ / hd 20.3 ∈ [18.31,25.94] ✔）。
   **BRIEF 明写「若你实测出现两根杆同时稳落带内 ⇒ 我的线性模型错了，照实报」——我把这条押上去。**
   机制（可核）：A 固定 `center0`，使 `Δc = −0.284` 不再随 c 缩小，
   于是 `S·(Δb − Δc)` 项变成 **+0.8·0.284(1−c) > 0**，与 `Δc(1−T)` 反向抵消 ⇒ **A 的 gap 比同 c 的 C 更小**
   ⇒ A 要**更大的 c** 才落进 gap 带，正好挪进 hd 带所在的 c 区间。
   **同时** A 的 hd 与 C 的 hd **逐位相同**（hd 是队内跨距；A 相对 C 只是在 `block_tx` 上加了一个**全队同向常数**
   `S·(mean_base − center0)`，跨距不变）——我的数值模型确认两者每一个 c 上都相等。
   ⇒ **A 相对 C 的净效应是「只挪 gap 不挪 hd」**，这正是把两根杆对齐的动作。
   ⚠️ 这也是「常数副本」设计债的量化：A 是**错**的语义（`center0` 不再是队均），
   但**在结构量上它反而更优**——这条如果成立，是本轮最有价值的发现。

### 2.3 L1（9 带）——我预测会红，且**方向是「事件量膨胀」**

从 C1 学到：两队块心靠近 ⇒ 事件量整体膨胀（射门/抢断/角球/犯规同向↑），最终主客进球方向反转。
本轴也把两队拉近 ⇒ 我预测同族效应，但**多一层**：本轴还同时压**队内**纵深（`spread` ↓），
所以「同一片区域里人更多」的效应更强，而「各自摊开」的效应更弱。

| c | 我预测的红带数 | 最可能的红 |
|---|---|---|
| 0.70 | 0–2 | `l3_shot_ratios`（射正率上界 0.39，基线 0.3757） |
| 0.55 | 1–3 | 同上 + `l1_shot_result_distributions`（禁区内进球占比，基线 0.7211 vs 下界 0.72，**余量 0.0011**） |
| 0.45 | **≥2** | `l3_shot_ratios` / `l1_pass_completion_rate`（下界 0.82，基线 0.8424）/ `shot/tackle`（下界 0.5，基线 0.5322） |
| 0.30 | **≥4** | 以上 + `l1_tackle_dilution_and_slot_mix`（角球 max ≤15） |

**方向性预测（可打脸）**：`width`（y）在 like-football 里**移动 < 3%**；

### 2.5 机制（★ 本轴最容易被「数字对、机制错」的地方）

**(b) 停车式 vs (a) 随球式**：本轴按构造做的是 **(b) 静态中线停车**。我预测量化判据：

- **队均 x 对 ball.x 的斜率在目标层恒为 0.304，与 c 无关**（我的模型逐点算：0.304 / 0.304 / 0.304 / 0.304 / 0.304）。
  BRIEF 手算 0.28（不含防线 push）；两者都指向「**不变**」。
- **真实帧的同一斜率我预测显著更高（0.45–0.75）**。
  ⇒ 预注册：**本轴能把「结构量」送进带，但斜率这条机制量纹丝不动**。
  若实测引擎斜率随 c 明显变化 ⇒ 我的模型错（球项没有像我说得那样抵消）。
- **`mix`（混队度）**：BRIEF 的观察②（引擎摊满全场 vs 真实挤成团）若真由静态表造成，
  压缩应让 `mix` 上升。**我预测 mix 基本不动（0.80 → 0.80±0.02）**——
  因为 `mix` 是**窗内位移**的混队度，由移动层决定，而本轴只改目标位置、不改移动机制。
  ⇒ 这又是一条「结构量动、机制量不动」的可打脸预测。

### 2.6 画面（我押注的方向）

我预测 **c 越小，轨迹图越像「两队挤在中路两条平行带」**，
两色在 x 上确实互相插入（分边小了），但**每队内部仍是一块板**（纵深同步收缩），
**不会**出现 BRIEF 观察②里真实那种「20 人挤在球周围一小团」——
因为块心仍**不跟随球**（斜率不变）。⇒ 我的先验判读：**「数字变好、画面部分变好但机制没变」**。

**我预期 c=0.45–0.55 的图比 c=1.0 更接近真实**（至少两队不再各占半场），
**但 c=0.30 会退化成「两队叠在中线上」**（两块板重合，去掉了足球里最基本的「攻守分半场」结构）。

## 3. 反证条件（我承诺照实报，一条也不藏）

1. **gap 在 c=0.45 处 > 10 m** ⇒ 我的 clamp 模型错（BRIEF 的线性模型反而更近）。
2. **gap 随 c 非单调 / 在某个 c 反弹** ⇒ 有我没建模的机制（`[0.04,0.9]` 末端 clamp、位置滞后、分离推挤）。
3. **`width` 相对 49.73 移动 > 3%** ⇒ 改动溢出到 y 轴，实现有 bug（本轴不碰 y）。
4. **变体 A 在 c=0.55 没能同时落进 gap 与 hd 带** ⇒ 我 §1/§2.2 的「A 只挪 gap 不挪 hd」机制主张被证伪，
   写「结论对但机制错」的旗帜。
5. **`mix` 或斜率随 c 显著变化** ⇒ 说明本轴**不只**动了静态摊开，还动了随球机制，我的 (b) 判断错。
6. **c=0.30 的 `p53`/`spacing-sweep` 没红** ⇒ 我「lineup 不过 repulsion」的机制主张错。
7. **盲测图判「比基线更不像足球」** ⇒ 数字变好画面变差（本仓飞轮三版的老坑），照实报代价。
8. **L1 红带数超出 §2.3 区间（上界）** ⇒ 我的「对称 / 温和」判断错。
9. **`cargo test` 出现与被改表无关的红**（如 p16/p17a/p17b/realism 非 golden 项）⇒ 我漏了某个 `base` 读取点，报为 bug 不报为代价。
