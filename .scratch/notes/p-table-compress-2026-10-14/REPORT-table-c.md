## 3. 带穿越：能不能落进真实带？

真实带 = 两数据集的 **[min, max]**：`gap ∈ [5.24, 8.32]`、`hd ∈ [18.31, 25.94]`、`ad ∈ [18.45, 26.79]`。

| 情形 | gap ∈ 带 | hd ∈ 带 | ad ∈ 带 |
|---|---|---|---|
| 变体 C | c ∈ **[0.379, 0.527]** | c ∈ **[0.475, 0.701]** | c ∈ **[0.581, 0.701]** |
| 变体 A | c ∈ **[0.454, 0.577]** | 同 C（逐位近似） | 同 C |

- **变体 C：`gap` 与 `hd` 的交集 = [0.475, 0.527]，非空**（实测 c=0.50：gap 7.79 ✔ / hd 19.28 ✔）。
  **BRIEF §4「两根真实带不可能同时满足」被证伪**——它的空交集来自线性外推 `gap≈19.2c`（预测 0.45 处 8.6，
  实测 6.71，偏低 1.9 m）。
- **变体 C：三条同时 ∈ 带 ⇒ 空**（`ad` 的下界 18.45 要求 c ≥ 0.581，而 gap 上界要求 c ≤ 0.527，缝宽 0.054）。
  最近点 **c ≈ 0.55**：gap 8.79（超上沿 5.6%）、hd 20.86 ✔、ad 17.24（差 6.6%）。
- **变体 A：三条同时 ∈ 带 ⇒ 非空**（c=0.60 实测 **gap 8.26 ✔ / hd 22.99 ✔ / ad 19.56 ✔**）。
  这是**本轮最锋利的一条**：BRIEF 明写「若你实测出现两根杆同时稳落带内 ⇒ 我的线性模型错了，照实报」——
  **照实报：实测成立，且是变体 A 而非 C**。
  > ⚠️ 但 gap 8.26 距上沿 8.32 只有 **0.7% 余量**（本仓「引擎贴着带沿站」的老坑），
  > 且 `ad` 在 A 与 C 上同值 ⇒ **A 的这点优势纯粹来自它把 gap 压小**，不是它更「像足球」。

**为什么 A 能、C 不能**（解析，可核）：A 固定 `center0` ⇒ `Δc = −0.284` 不随 c 缩小
⇒ `S·(Δb−Δc) = 0.8·0.284(1−c) > 0`，与 `Δc(1−T)` 反向抵消 ⇒ **A 的 gap 比同 c 的 C 小**，
于是 A 要**更大的 c** 才进 gap 带，正好挪进 hd/ad 带所在的 c 区间。
而 **hd/ad 是队内跨距**：A 相对 C 只是在 `block_tx` 上加了一个**全队同向常数** `S·(mean_base − center0)`，
跨距不变 ⇒ **A 的净效应是「只挪 gap 不挪纵深」**。我的数值模型预测两者 hd 逐点相等，实测差 ≤1.1% ✔。

## 4. 我声称的因果机制（**「因为/原因是」也请对抗镜核**）

### 4.1 gap 为什么降——**不是 BRIEF §3 的线性律，是「线性律 − 防线 clamp」**

BRIEF §3 的公式（我把代数重推过，**成立**）：
`间距_target = (1−M)Δb + M[Δc(1−T) + S(Δb−Δc)]`，M=T=0.5、S=0.8 ⇒ 变体 C `= −0.213c` ⇒ **22.37c m**（c=1 时与 BRIEF 逐位相同）。

**它漏了 `is_defender` 的 clamp**（`lib.rs:3461-3465`：防线 `tx = tx_full.min(ball.x).max(base.0)`）。
把这段加进模型后我得到 c=1 的**目标**间距 **19.83 m**，而实测 **19.20 m**：

| | §3（无 clamp） | 含 clamp 的模型 | 实测 |
|---|---|---|---|
| c=1 目标间距 | 22.37 | **19.83** | **19.20** |

⇒ BRIEF 说的「实测/预测 = 0.858」**不是动力学折损**，而是 **0.885 = 防线 clamp** × **0.968 = 动力学/抖动残差**。
这条分解是有后果的，因为 **clamp 的强度随 c 变**：表压缩把 home 防线的 `base.0` 从 0.14–0.20 抬到
0.35–0.41（c=0.45），于是 `min(tx_full, ball.x)` 的**上界开始频繁成为绑定约束**——
球在 `0.14 < ball.x < 0.36` 区间时，home 后四人被 clamp 到**正好站在球的 x 上**（基线不存在的状态）。

**实测判据（谁对）**：

| c | 我（含 clamp + 0.968×） | BRIEF（19.2c） | 实测 | 我的误差 / BRIEF 的误差 |
|---|---|---|---|---|
| 0.70 | 12.8 | 13.4 | **12.69** | −0.11 / +0.71 |
| 0.55 | 9.6 | 10.6 | **8.79** | −0.81 / +1.81 |
| 0.45 | 7.6 | 8.6 | **6.71** | −0.89 / +1.89 |
| 0.30 | 4.4 | 5.8 | **3.76** | −0.64 / +2.04 |

**我的 clamp 模型在 gap 上系统性胜过线性律**（误差 0.1–0.9 vs 0.7–2.0，且 BRIEF 的偏差随 c 单调放大）。
**但我的模型也不是对的**：残差 `模型−实测` ≈ 0.63/0.50/1.14/1.14/0.76（c=1.0/0.70/0.55/0.45/0.30），
**大致是常数 ~0.8 m（加性），不是乘性** ⇒ 0.968 这个比值**不能常数外推**
（我预注册里用了它，所以在 c≤0.55 处**系统性高估 ~0.8–0.9 m**——如实记录，这是我自己的预测偏差）。
加性残差与「`ix` 个体抖动（`block_tx` 里 `sin(...)·0.08`，权重 M=0.5 ⇒ 队均残差非零、且**与 c 无关**）」的
量级一致——但**我没有直接测 ix 的队均残差**，这一步是**推断**，不是测量。

### 4.2 纵深为什么随 c 线性降：**直接几何**（这一条我有把握）

`block_tx = block_cx + (base.0−center0)·S`，变体 C 下 `(base.0−center0) = c·(base0_原 − 0.358)`
**逐字随 c 缩放**；旧式 `tx = base.0 + …` 的跨距同样随 c 缩放。两项同缩放 ⇒ 队内跨距 ≈ 线性于 c。
我的目标层模型给 `hd_target` 38.76/26.28/20.12/16.13/9.85（c=1/0.7/0.55/0.45/0.30），
实测 39.10/25.91/20.86/17.44/12.02 ⇒ **比 1.01/0.99/1.04/1.08/1.22**。
⇒ **线性在 c ≥ 0.55 成立，c ≤ 0.45 起实测高于线性**（深度掉不下去）。
机制（推断）：防线 clamp 的 `max(base.0)` 下限**随 c 抬高**，把后四人的 x 钉住 ⇒ 跨距有下限。
c=0.30 处 hd 仍 12.02 m 而线性说 11.7 m——差异不大，**这条推断的证据不强，标注为推断**。

### 4.3 **本轴做的是「静态停车」还是「随球紧凑」？——两个都不是**

BRIEF §5 的框架：(a) 球相对紧凑（真实） / (b) 静态中线停车（退化）。我用**同一段代码**（`zz_table_probe.mjs`）
在引擎各 c 与真实帧上算了「队均 x 对 ball.x 的斜率」与「按 ball.x 分箱」：

| 配置 | 主队斜率 | 客队斜率 | r(主) | 分箱跨度（球 0-21m → 84-105m） |
|---|---|---|---|---|
| **真实 game1** | **0.524** | **0.537** | 0.811 | home 28.5 → 72.8 m（**44.3 m**），gap 恒 ≈6.5 m |
| **真实 game2** | **0.633** | **0.633** | 0.828 | home 24.2 → 71.9 m（**47.7 m**） |
| C 1.00 | 0.388 | 0.377 | 0.908 | home 31.2 → 61.2 m（30.0 m），gap 15–18 m |
| C 0.70 | 0.403 | 0.403 | 0.849 | home 28.2 → 70.3 m |
| C 0.55 | 0.395 | 0.425 | 0.830 | home 28.9 → 67.5 m |
| C 0.45 | 0.441 | 0.440 | 0.841 | home 30.1 → 72.6 m（**42.5 m**），gap 1.7–1.8 m |
| C 0.30 | 0.468 | 0.482 | 0.891 | home 31.0 → 70.0 m，**两队块心在极端球位互换（gap −0.5 m）** |
| A 0.55 | 0.436 | 0.434 | 0.856 | — |

**⇒ 我预注册的「斜率不变（0.304）」被证伪，而且证伪得有价值**：
- **水平就不对**：预测 0.304，实测 **0.388**（c=1.0，5 seed 合并 13.5 万帧）。
- **不是常数**：斜率**随 c 单调上升** 0.388 → 0.403 → 0.406 → 0.395 → 0.403 → 0.441 → 0.468（c=1.0→0.30），
  即**压缩确实略微增加了「随球走」的程度**，但**到不了真实（0.52–0.63）**。
- **`r` 反向**：引擎的相关系数（0.83–0.93）**高于**真实（0.81–0.83）——引擎的队均 x 与球位**同步得更紧**，
  只是**幅度小**。
- **为什么斜率会升**（推断，未直接测）：`is_defender` 的 clamp 上界 `ball.x` 在压缩后频繁绑定
  ⇒ 后四人被钉在球的 x 上，等于给队均加了一条强随球项。**这一条我没有单独测「防线 vs 非防线」的斜率去证伪，
  是本报告最大的未验证机制主张。**

**所以 (b)「静态停车」这个说法也不准确**：引擎的队**确实跟着球走**（r 0.83–0.93），
只是**幅度不够 + 两队块心离得远**。压缩把块心拉近的同时把队内跨距也压掉了，
于是 c=0.30 出现**两队块心在极端球位互换**（红蓝谁在左取决于球在哪）的退化态。

**我预注册「c=0.45 过 spacing、c=0.30 破」被证伪**（0.45 就 17 条）。
理由是我把判据算成了「静态对 (2,4) 间距 = 6.3c m ≥ 2.0」——**静态对确实过（2.835 m），
但破的是动态**。

> **读数口径提醒**：sweep 的 `finding 数` 是「滑窗命中数」，**不是独立事件数**——
> 窗宽 10 s、步长 2.5 s（4× 重叠）⇒ **同一个瞬态会被数 4 次**。
> c=0.70 的 4 条 finding 经 `zz_spacing_detail.mjs` 核实是 **同一个事件**（t=4049.5 s，pair 2/4，
> `breach_samples=1`）在 4 个重叠窗里各报一次。c=0.30 的 79 条 = 8 seed × 多个事件的滑窗计数。
> ⇒ 「4 条」听起来像「4 处」；**实际是 1 处 × 4 窗**。这两点读法都必须给出，别只给一个数。

**机制（已实测核到事件级，`zz_spacing_detail.mjs` + `zz_ballx_check.mjs`）**：
- 破点唯一是 **pair (2,4)**（home）——表里**唯一一对 y 完全相同（同为 0.5）、x 只差 0.06** 的队友，
  压缩后名义间距 `6.3c` m。
- c=0.70 seed 42：`t=4049.5 s` 两人相距 **0.525 m**，且此刻 **id4 的位置 = 球的 position 逐位相同**
  `(0.3750, 0.5073)` ⇒ id4 是**追球者**（`targets[id] = st.ball_pos`），id2 恰好在球旁。
  1.5 s 前 id2/id4 还相距 7.9 m。
- ⇒ **引擎的 2.2 m 分离约束作用在「目标」上，不作用在「已实现位置」上**
  （`separate_pair_m` 在 `compute_movers` 第二遍改 `targets`，不动 `st.pos`）。
  所以「追球者跑到球上、队友恰好在球旁」这种瞬态**结构性地不受分离保护**。
  压缩把 (2,4) 的余量吃光后，这个瞬态就跌破阈值。**基线的同一 pair 也会靠近（2.149 m），只是余量 0.149 m。**
- ⚠️ 这是我**第一次把这条机制写清楚**，但**「追球者豁免」这一步我没有读 `separate_pair_m` 的调用条件去逐条核**
  （我只核到「破点时刻 = 追球者与队友同位」这个事实）。**对抗镜应优先打这一条。**

## 7. 推荐

**不推荐落地本轴。** 理由按重要性：

1. **代价付不起，且来得比预想早**：c=0.70（`gap` 才降到 12.69，离真实带还很远）就已经
   **破 4 条 L1 带断言（3 个 test）+ 破 spacing 门（8 seed 里 1 个出 4 条 finding）**。
   而 `gap` 要进带必须 c ≤ 0.53。
   ⇒ **「进带所需的最小压缩」比「门能承受的最大压缩」还小**，本轴**没有可行区间**。
2. **它治的是「分边」这一根杆**：`width`（49.7 vs 真实 35.96，\|ln\| 0.32）**一动不动**，
   在 c=0.55 处已与 `gap` 并列成为最大缺口。用户抱怨的形态里，这条轴只覆盖了一半。
3. **运动量反着走**：`disp` 6.00 → 4.14（真实 13.46）、`lat` 0.38→0.32（真实 0.43）、
   `mix` 0.80→0.70（真实 0.80）——**距离函数里唯一被改善的是结构量那几行**。
4. **纯数字诱人**：A 0.55 的 `like-football` 距离 0.280（基线 0.520，降 46%），
   且 A 0.60 三条结构带同时落带——**这正是本仓飞轮四次空转的形态**（数字变好、用户看不出）。
   若只看距离，本轴会被误判为「成功」。

**给主 session 的三条可复用结论**：

- **C-1（正面）**：`default_lineup` 的 `base.x` **确实是** `gap`/`hd`/`ad` 的**真杠杆**，
  单调、可解析（含防线 clamp 的模型在 4 个点上误差 0.1–0.9 m）、且**能真的落进真实带**。
  作为**诊断工具**它很有价值：它证明「三个结构缺口确实由静态表钉住」。
- **C-2（负面）**：但**落带所需的压缩量本身就会摧毁比赛**——因为 `base.x` 同时承载
  「两队块心位置」和「一队的纵深」，**两者共用一根杆**。要同时改对**必须拆杆**
  （例如只改「队均值差」而不改「队内跨距」，或把纵深交给另一路信号）。
- **C-3（设计债的量化）**：`FORM_CENTER_HOME/AWAY` 作为「`default_lineup` 队均的硬编码副本」
  这个债**不是零成本的**：同 c 下 **A 的 gap 比 C 小 1.6–1.8 m**（c=0.55：6.97 vs 8.79；c=0.60：8.26 vs 9.85），
  而 hd/ad 只差 ≤1.1%——**这个差额正好落在"进带 / 不进带"的分界上**（C 0.60 的 gap 9.85 出带，A 0.60 的 8.26 进带）。
  且 A 的语义是**错的**（`(base.0−center0)` 不再是「离块心的偏差」，而是一个全队同向推力）
  —— 但在结构量上 **A 反而更优**。⇒ 落地任何压缩类改动时，
  `FORM_CENTER_*` **必须与表同步**，否则你得到的是一个语义错误但数字更漂亮的配置。
