## 1. `phase_offset`（块心相对球的纵向差，米）

**符号约定**：**攻方进攻方向为正**（攻方 + = 在球前；守方列出的值在同一坐标系里，
**正 = 比球更靠攻方进攻方向** = 守方在球与自家球门之间）。

| 量 | n | 均值 | 中位数 | sd |
|---|---:|---:|---:|---:|
| 攻方块心 − 球（沿攻向） | 34307 | **+2.444** | +1.673 | 13.21 |
| 守方块心 − 球（沿攻向） | 34307 | **+9.246** | +8.598 | 12.98 |

逐场 / 分组（稳健性）：

| 切法 | 桶 | 攻方 | 守方 |
|---|---|---:|---:|
| 逐场 | g1 | +3.120 | +9.621 |
| 逐场 | g2 | +1.728 | +8.848 |
| 控球方 | home 作攻方 | +1.898 | +8.596 |
| 控球方 | away 作攻方 | +3.013 | +9.923 |
| 球位场区（攻方视角） | 攻方本场三区 | **+12.932** | **+19.640** |
| 球位场区 | 中区 | **+1.318** | **+8.165** |
| 球位场区 | 攻方进攻三区 | **−10.363** | **−3.463** |

**冻结值**（沿**本队自己的进攻方向**，进源码常量）：

```
PHASE_ATT = +2.444 m     # 攻方块心在球前 2.444 m
PHASE_DEF = -9.246 m     # 守方块心在球后 9.246 m（沿守方自己的进攻方向 = 负）
```

> 即：某队自己的攻向为 `d`（home +1 / away −1），则 `block_x = ball.x + (my_attack ? PHASE_ATT : PHASE_DEF) · d`。

⚠️ **这是一条被实测削弱的假设（如实记，进 PREDICTION 的未知）**：`phase_offset` **不是常数**——
它随球在攻方轴上的场区从 **+12.9 m 变到 −10.4 m**（攻方），跨度 ≈ 23 m，sd 13.2 m。
真实里的「块心相对球」主要由**球在场上的位置**决定（球在本方三区时全队压上、块心远在球前；
球在对方三区时全队回撤、块心落在球后），**不是**一个固定的前/后错开。
本轮按设计只冻结**全场均值**，等于用「平均而言攻方在球前 2.4 m / 守方在球后 9.2 m」近似整条曲线。
**后果**：机制只能复现真实关系的**均值**，复现不了它的**场区依赖**——A3 的分箱图会直接显示这一点。

**横向（y）**：攻方块心 y − 球 y 均值 **−0.764 m**，守方 **−0.648 m**（两场、两控球方一致）。
量级 < 1 m → **冻结 `block_y = ball.y`（横向相位 = 0）**，并把这条 <1 m 的偏差如实记在此处。

## 3. `BLOCK_SCALE` 反解（**只按纵深**——任务书原文：「映射到真实纵深需要的 scale」）

真实纵深**带**（两数据集；committed 基线 `benchmark-baseline.json` 的 `datasets.*.perMetric`）：

| 锚 | hd | ad | 几何中点 |
|---|---:|---:|---:|
| skillcorner（like-football 的 **primary**） | 18.307 | 18.449 | — |
| metrica（本轮实测同量级：25.81 / 25.61） | 25.939 | 26.793 | — |
| **带的中点（几何）** | **21.791** | **22.233** | **22.012** |

```
BLOCK_SCALE = 22.012 / 46.620 = 0.4722   →  冻结 BLOCK_SCALE = 0.472
```

**为什么取带的几何中点、而不是某一个锚**：两端点各让引擎**贴着带沿站**（本仓已有
`engine-sits-at-band-edges` 的教训：带沿余量 1–6%，任何有效改动必越界）。中点对两个锚的
`|ln|` 相等（各 0.174），是余量最大的选择。两个端点各自的取值也一并记下，供后来者重取：
`BLOCK_SCALE_skillcorner = 0.3942`、`BLOCK_SCALE_metrica = 0.5656`。

### 3.1 ⚠️ 实测到的**结构性冲突**（本节最重要的发现）

base 站位表与外场真实块**长宽比不一样**，所以**一个统一标量不可能同时进两条带**：

| 轴 / 估计量 | 需要 `BLOCK_SCALE` |
|---|---:|
| x 纵深（q10–q90，**带的中点**） | **0.472** |
| y 跨度（max−min，真实 39.679 / base 40.800） | 0.973 |
| y 纵深（q10–q90，真实 30.248 / base 28.560） | 1.059 |

- 用 `0.472`（按纵深冻结）：纵深 ≈ **22.0 m**（进带 ✓），但 y 跨度塌到 **19.3 m**——
  真实 39.7 m，**只有 0.49×**，**跌破真实带下沿**（判据 G：不许靠压扁换密度 ⇒ 直接违反）。
- 用 `0.973`（按宽度）：y 跨度 39.7 ✓，但纵深 = 45.4 m，**远在带外**（真实带顶 25.94）。
- 真实块「**宽而扁**」（y 跨 39.7 > x 纵深 25.8），base 表「**深而窄**」（46.6 > 40.8 span、
  46.6 ≫ 28.6 q10–q90）。**两者不是同一个形状，差一个各向异性缩放。**

⇒ **结论（待本轮实测检验）**：DESIGN §2 的单标量 `target = block + rel·BLOCK_SCALE` 在
「同时满足判据 B（纵深进带）与判据 G（宽度不塌）」上**结构性不可能**；要两者兼得必须
**分轴缩放**（x≈0.472、y≈1.06）。

### 3.2 本轮怎么处理这个冲突

- **主面板 `U`**：按任务书字面执行——**单标量 `BLOCK_SCALE = 0.472`**，均匀作用在 `rel` 的
  x、y 上。跑满 5 点。**预注册**：它的 y 跨度会塌到 ~19 m，判据 G 必红，画面会呈「一根窄柱」。
- **对照面板 `A`（aspect-corrected）**：`BLOCK_SCALE_X = 0.472`、`BLOCK_SCALE_Y = 1.059`
  （y 用**同口径**的 q10–q90 反解，不是 max−min——两个估计量不对称是 `#160` 已裁过的坑）。
  ⇒ 块形状**与真实同形**，于是 `ANCHOR` 成为**唯一变量**，可把「球锚」与「压扁」两个效应**分开归因**。
  这是本仓强制的**最简竞争解对照**（`necessity-claims-need-simplest-competitor`）：
  若不跑它，A1/A2 的任何改善都无法区分是「锚在球上」还是「整队被压小」。
  `A` 只跑 ANCHOR = 0.5 / 1.0 两点（归因用，不铺满）。
- `A@ANCHOR=0 ≡ U@ANCHOR=0 ≡ 基线`（ANCHOR=0 走原表达式的显式分支）——三点同一份代码。

## 4. 个体差异化梯度（**任务书强制项**：`p38-swarm-comes-from-common-signal`）

全队共用一路信号必然同步 ⇒ 每名球员的 commit 系数必须不同。**不从「角色」拍脑袋，
从真实量**：把客队镜像（`x' = 1−x`）后，按球员到球的**米制距离**分箱，箱内 OLS
`x_player ~ ball_x` 的斜率 β = **「球每移动 1 m，该距离档的球员平均跟着移动几 m」**。

原始探针输出（`logs/commit-gradient.json`，0.2 s 抽样、原始球帧、剔门将、两场合并）：

| 离球距离 (m) | 0–5 | 5–10 | 10–15 | 15–20 | 20–25 | 25–30 | 30–40 | 40–60 | 60–200 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| β | **0.955** | 0.882 | 0.803 | 0.702 | 0.586 | 0.496 | 0.383 | **0.326** | 0.769 |
| n | 31545 | 47349 | 65880 | 72043 | 74881 | 74923 | 120271 | 131560 | 67688 |

**单调递减、跨度 0.96 → 0.33**（0–60 m 段）。**冻结形式**（分段线性插值 + 两端平延）：

```
w(d):  d<=2.5 -> 0.955
       2.5..55  -> 在下面这些实测节点间线性插值（节点=各箱中点与实测 β）
                 (2.5,0.955) (7.5,0.882) (12.5,0.803) (17.5,0.702)
                 (22.5,0.586) (27.5,0.496) (35,0.383) (50,0.326)
       d>=50 -> 0.326
commit_i = ANCHOR · w(d_i) / w(0)    # 归一化：近球者 1.0、远球者 0.345
```

- **用实测节点插值、不用拟合式**：拟合式（如 `β ≈ 0.945 − 0.0140·d`）在两端各有 ~0.08 的
  系统偏差；既然有实测值就直接用实测值（「口径齐全」优先于形式简洁）。
- **归一化到 w(0)=0.955**：让 `ANCHOR` 单独承载**全局强度**、`w(d)` 单独承载**个体差异形状**。
  这样扫描 `ANCHOR` 时不会同时改变个体差异的幅度（否则两个效应又混在一起）。
- ⚠️ **`60–200 m` 箱的 β 回升到 0.769，判为伪影、不采用**：60 m 以外离球的是**对面半场**的球员，
  他们的 x 与 ball.x 高相关来自**整块随球平移**（全场重心移动），不是「跟球」。
  用 0–60 m 段的单调递减形状；这条判断如实记在此处（未做独立验证）。

**滞后（lag）**：`formation_target` 是**无状态纯函数**，拿不到球的历史 ⇒ **不实现真正的时间滞后**。
以**每 id 相位的确定性正弦**（沿用现有 `FORM_PHASE_PERIOD_S` / `FORM_PHASE_ID_STEP`）近似去同步：

```
wobble_i = 1 + FORM_COMMIT_WOBBLE · sin(phase_i)      # phase_i 已含 id 偏移
commit_i = clamp( ANCHOR · (w(d_i)/w(0)) · wobble_i , 0, 1 )
```

**限制如实记**：这是**相位去同步**，不是时间滞后；真滞后需要引擎存球轨迹（改 `MatchState`），
本轮不做（避免动状态层污染 ANCHOR=0 的等价性）。

## 5. 限制（本轮**没**覆盖的）

1. **只有 Metrica 两场**。SkillCorner 原始帧要 1.8 GB 下载（本轮明确排除）⇒
   ① 纵深带的**下沿**（18.31/18.45）只有 committed 基线一个来源，本轮**没有独立复算**；
   ② 逐场球场尺寸（104/106）**本轮完全不涉及**——两场 Metrica 都是 105×68（帧上无 `pitchMeters`），
   所以「逐场尺寸」这条口径本轮**未被检验**。**真实带是 [skillcorner, metrica] 的两点区间，
   本轮只在 metrica 一侧加了独立证据。**
2. **`phase_offset` 的场区依赖被均值抹平**（§1）。
3. **真滞后未实现**（§4）。
4. 真实侧帧是 25 Hz 全量、非 0.2 s 抽样，且是**整场**而非 300 s 窗——与 `benchmark-baseline.json`
   的窗口径（300 s / 900 s 步长）**不同**；故此处的 hd/ad 25.81/25.61 与基线的 25.94/26.79
   有 ~1–4% 的口径差（方向一致）。**冻结用的是基线的 25.94/26.79**（判据也是挂基线的），
   本节的 25.81/25.61 作为**独立复现的旁证**。
