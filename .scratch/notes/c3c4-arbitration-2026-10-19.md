# 两条确认 bug 的修复与验证

本文件只记录 **C3/C4 两个机制错误**的修复前后读数。验收回路本身见
`c1c5-flags-gates-2026-10-19.md`。**本 change 不调任何概率/几何常数，不以 L1 进带为目标。**

## 改了什么

### A. C3：换人惩罚按进攻者身份（commit-less worktree）

- `MatchState.mark_prev`（`Vec<Option<usize>>`，`att_ids` 下标）删除；
- 改为 `mark_prev_attacker: [Option<usize>; 22]`（防守者 id → 上一次匹配到的**进攻者 id**），
  换防守方时清空，未匹配时保留；
- `apply_marking` 每次用“上一拍进攻者 id → 当前 `att_ids` 下标”构造 `prev`，找不到则 `None`；
  `marking::assign` 的 `same_as_prev` 现在真正表示“还是同一个进攻者”。

### B. C4：先选压迫者，再做盯人

- `apply_pressure` 拆成 `pick_presser`（只选人/算压迫点、累计门控）与
  `apply_pressure_target`（设压迫目标 + 弱侧压缩）；
- 调用顺序：`pick_presser` → 选中者 `action="close_down"` → `apply_marking`（自动排除）→
  `apply_pressure_target` → repulsion；
- 被 press 选中的人不再参与 mark（#172 契约）。

## 机制探针（3 场，seeds 401–403，C1–C4 全开）

| 量 | 修复前 | A（只修 C3） | B1（A+C4 仲裁） | B2（B1 + excluded 修复） |
|---|---:|---:|---:|---:|
| 换人对象 / 调用 | 1.269 | **0.778** | 0.819 | 0.633 |
| 换人惩罚下标错位 | 10,787（7.4%） | **0** | **0** | **0** |
| 未匹配防守者 / 调用 | 0.41 | 0.43 | 0.39 | 0.32 |
| press 门控通过 | 8,927 | 8,625 | 8,510 | 6,426 |
| 门控通过后有压迫者的调用 | **3.5%** | 3.7% | **100%** | **100%** |
| 平均压迫人数/调用 | 0.019 | 0.020 | 0.531 | 0.400 |

**B2 的复审 P1**：B1 的 `pick_presser` 没排除 `excluded`（本拍不产 mover 的高亮参与者/
冻结者），可能选中一个不会移动的“压迫者”，让“已派出”读数虚高。B2 在候选里过滤
`excluded` 并加单测；压迫率仍是门控通过后的 100%，但门控通过次数/平均人数因轨迹反馈
下降（8,510→6,426 / 0.531→0.400）。

**机制结论**：

- A 把“惩罚目标错位”归零，换人率从 1.27 降到 0.78——证明下标错位确实在制造/漏掉惩罚，
  但换人率仍高，剩下的不是这一个 bug 能解决的；
- B 让 C4 真正生效（门控通过后 100% 有人压迫），不再被 C3 占满。

## L1 四条体量带（60 场，seed 401..460；同口径）

|---|---:|---:|---:|---:|

| B1（C3+C4） | 9.667 | 124.967 | 36.050 | 0.8394 |

200 场仍 **1/4** 通过：只有传球成功率在带内（0.8401）；射门/抢断/犯规三条仍红。

**结论：两条修复都没有把射门/抢断/犯规带回来。** C4 生效 + excluded 修复后射门从
8.2 升到 9.6（200 场），但离下限 14 仍远；抢断/犯规从 126/36 降到 121/35，仍在带外。
→ “这两个 bug 是 L1 出带主因”的假设**不成立**。
下一步应查机制探针（可起脚窗口/12m 内防守者/抢断选择率），不要调常数硬顶带。

## 视觉（先看图）

- 轨迹 seed42/1800–1890s：B1/B2 后**仍是满场水平长条**（C2 的队形主因未动）；
  B 之后球员更向球侧聚集，但“铁轨/横条”形态未消。
- 轨迹 seed7 同一窗：B 后蓝队仍拉出大横向带；红队集中在左侧。
- 结论：两条修复没有把画面变“像”；C2/C3 的站位/目标生成仍是下一层问题。

## 判别性守卫（变异实测变红）

- `c3_mark_prev_identity_changes_assignment`：上一次盯稍远的 12 时惩罚应继续选 12；
  无历史时选更近的 11。“把 prev 改成全 None”变异会红。
- `c3_probe_switch_counts_by_attacker_id_not_index`：进攻者 id vs 下标、跨防守回合重置；
  “存下标”和“去掉重置”两个变异都会红。
- `c3_probe_switch_survives_unmatched_defender`：`out[k]=None` 不得清空上次目标；
  “None 分支清空”变异会红。
- `c4_pick_presser_precedes_marking`：presser 不进入 mark、目标在应用阶段写入；
  `excluded` 中的球员不得被选为压迫者。
- `c4_compute_movers_does_not_starve_press`：完整 `compute_mover_candidates` 下
  `pressers_total == 1`；“改回 mark-first”变异会红。

## 判定

- **A、B 是真实 bug，修复有机制证据**（错位 7.4%→0、门控通过后压迫率 3.5%→100%），应保留。
- **但它们不是 L1/画面问题的主因**：200 场仍 1/4（射门 9.585、抢断 120.995、犯规 35.425、
  传球成功率 0.8401）。不要在此基础上继续调 `SWITCH_PENALTY_S` 或停距去凑带。
- C4 修好后产生了实际代价（B1 gap 出带；B2 gap 仍 10.196），C4 是否保留/怎么改要回到
  design 评估。
